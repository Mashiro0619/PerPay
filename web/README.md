# PerPay 管理前端

最近一次本地与浏览器验收结果见 [管理端验收记录](ACCEPTANCE.md)。本地通过不等于容器或远端发布验收通过。

## 技术选择

- React + TypeScript：管理界面组件和类型检查；不引入第二个服务端框架或 SSR 层。
- Vite：开发热更新、按页面分包、带内容哈希的静态资源。
- React Router Data Router：`/admin` 下可直接访问和刷新的路由，以及未保存修改的导航保护。
- TanStack Query：服务端状态、请求取消、缓存失效及查询重试；写操作不自动重试。
- 原生 CSS、原生表单、Popover 和 `<dialog>`：响应式、三态主题、焦点与键盘支持。Lucide 仅用于图标，没有 UI/CSS 组件库或图表库。
- Hey API：从根目录 `openapi.yaml` 生成 TypeScript 类型与 fetch SDK，支持项目当前的 TypeScript 6。
- jsQR：仅在选择经营码图片后加载的本地二维码解码器，不增加图片上传接口或外部识别服务。

前端依赖都属于构建期依赖。生产环境仍只有 Node.js + Hono 服务，公开收银台不加载 React。管理端没有模拟数据、浏览器持久化业务缓存或离线财务操作队列。

下拉选择保留原生 `<select>`，焦点轮廓与控件边框重合显示，避免双层边框。支持 `appearance: base-select` 的浏览器通过 CSS 统一弹出菜单、选中标记和明暗主题；样式置于 `@supports` 内，不支持的浏览器继续使用系统原生菜单，键盘选择、标签关联和表单提交不依赖自定义 JavaScript。

## 主题、导航与统计

桌面不再使用重复的顶部导航栏；首页直接展示收款统计、趋势与待处理事项，完整运行状态和实例版本统一留在运行状态页，仅未完成配置时显示首次配置引导。侧栏底部只保留并排的主题与退出图标按钮，提供悬停提示、无障碍名称和 44px 点击区域，不重复展示实例信息。窄屏的导航入口位于页面标题旁，抽屉支持 Escape、返回焦点与背景滚动锁定。

主题支持浅色、深色和跟随系统，默认跟随系统。只有 `perpay:theme` 偏好写入 localStorage；订单、密码、密钥和草稿均不持久化到浏览器。`public/theme.js` 在应用加载前设置主题，订阅系统与跨标签页变化，并在存储被禁用时保留内存内的选择。它以同源外部脚本加载，使用 ETag 重新校验，不需要放宽 CSP。

概览中的两幅原生 SVG 面积图共享日期选择：上方显示付款确认金额，下方显示新建订单数。单位不同，不做数值堆积，也不新增统计字段。支持悬停、轻点、方向键、Home/End 及前后日期按钮，并提供完整数据表。业务时间与日统计统一使用北京时间（Asia/Shanghai，UTC+8），7／30／90 天包含今天并以北京时间零点切日；数据库时间戳和 API 的绝对时间仍保留 UTC 表达，不依赖服务器或浏览器的本地时区。

## 界面文案

普通页面只保留标题、数据、状态和操作，不重复解释页面用途、排序方式、数据来源、轮询策略或内部配置版本。设置页不显示“基于配置版本”或更新时间脚注；只有实际修改时才显示未保存状态，版本冲突校验与草稿保护保持不变。

字段格式、金额口径、错误和加载状态仍在需要的位置显示。退款登记、密钥轮换、真实测试收款等风险集中保留在对应操作处，不依赖列表底部的常驻说明。可访问名称、输入标签和图表键盘指引不因文案精简而移除。

## 动效与可访问性

全局页脚的品牌标语与金额／时区说明已移除，仅精简显示，不改变人民币金额和北京时间的统计口径。页面仍保留必要的业务说明与移动端底部安全距离。

动效使用原生 CSS、SVG、Web Animations API 和浏览器 View Transitions，不增加依赖、内联样式或 CSP 例外。统一样式位于 `src/styles/motion.css`，交互动画由 `src/lib/motion.ts` 处理取消与生命周期：

- 普通页面采用新旧内容衔接，而不是整页反复横移：旧内容约 150ms 离开、新内容约 300ms 到位，侧栏始终保持稳定。路由模块由 Data Router 按需加载，准备好后再切换。不支持 View Transitions 时回退为短淡入，不重挂载表单，也不为查询参数变化重播整页动画。
- 侧栏、设置分类、统计周期和列表标签使用一个连续移动的选中背景或下划线。`SelectionIndicator` 在快速连点时从当前可见位置继续，尺寸变化时重新定位，不累积动画队列，也不依赖内联样式。
- 图表切换周期不再重新挂载和重画整条曲线；保留已展开的数据表、仍在范围内的选中日期和图表焦点。十字线与选中点短距离跟随，更新周期只做轻淡入；金额和订单数始终直接呈现真实值。加载期间保留旧数据并明确标注其所属周期，迟到响应不覆盖当前选择。
- 数据表与技术字段利用原生 `details` 平滑展开／收起；支持相关 CSS 的浏览器增强动画，不支持时保留原生行为。按钮按压、复制完成、主题菜单和移动抽屉使用统一节奏；减少重复的列表错峰和数字入场，避免多组动画互相抢注意力。
- 设置、测试收款和鉴权页面不参与页面快照；登录界面出现或对话框打开时立即隐藏过渡快照。弹窗关闭、敏感信息清除和会话失效不等待退场动画。`prefers-reduced-motion` 停止空间运动并保留短颜色反馈，运行中切换偏好会立即停止；页面隐藏或卸载会停止相关脚本动画，没有非必要循环特效。

## 开发与部署

使用项目要求的 Node.js 24。首先安装依赖：

```sh
npm ci --ignore-scripts
npm run build
```

`npm run build` 同时生成服务端 `dist/` 和控制台 `web-dist/admin/`，由现有 Hono 服务在 `/admin` 提供。正式部署仍遵循根目录 README：仅支持 Linux Docker，Windows 使用 WSL2 的 Linux Docker。Dockerfile 会完成同样的打包流程，无需单独部署 Nginx、开启 CORS 或放宽 CSP。

热更新开发使用两个进程：一个独立的开发后端实例（推荐本地 Linux Docker 容器），以及：

```sh
npm run dev:admin
```

浏览器打开 `http://127.0.0.1:6191/admin/`。Vite 默认将 `/api`、`/checkout` 和收银台资源代理到 `http://localhost:6190`。如需修改，设置 `PERPAY_DEV_API_URL`；它的 Origin 应等于开发后端的 `PERPAY_PUBLIC_URL`。开发代理仅对自身两个回环 Origin 重写来源头，不改变生产服务的来源校验。

请使用隔离、回环 HTTP 的开发实例，不要把 Vite 连接到线上收款服务；本地 HTTP 开发页也不应依赖线上 HTTPS 的 Secure Cookie。Vite 只监听 `127.0.0.1`，端口固定且冲突时退出。

若只构建服务端而没有前端产物，管理页面返回带构建说明的 503，管理 API 和公开收银台仍可使用。

## API 与安全边界

```sh
npm run api:types
npm run api:check
```

生成文件位于 `src/api/generated/`，应随接口修改一起提交，不要手改。生成时保留全部数据模型，只生成管理端 SDK；浏览器负责发送 `Origin`，因此仅在客户端类型中将该头改为可选，服务端依然严格校验。`api:check` 在临时目录重新生成并比较，CI 不会静默更新已提交的文件。

`src/api/client.ts` 统一限制同源请求，设置 `credentials: same-origin`、`cache: no-store`，为写请求读取当前 CSRF Cookie。管理员会话令牌由 HttpOnly Cookie 保管，不进入 localStorage/sessionStorage。401 会清除业务查询缓存并回到登录；403、429、409 和服务不可用均显示明确错误及请求编号。

配置表单保留读取时的 revision，409 时保留草稿，不会自动拿新版本覆盖旧修改。存在修改时，设置分类切换、侧栏跳转、浏览器返回、主动退出和重新读取均需确认；刷新或关闭标签页使用浏览器原生离开警告。保存成功或恢复原值解除保护，会话失效则立即清除敏感状态，不会被草稿拦截。财务处理先查询真实订单和流水，再确认方向、金额、理由及操作；相同负载的重试复用操作 UUID。

密钥仅通过显式操作读取，不进入 Query 缓存或浏览器存储；明文对话框 60 秒后或标签页隐藏时关闭。不要在日志、截图或测试数据中使用真实密钥。依赖覆盖 `js-yaml@4.3.1` 用于修复 API 生成器间接依赖的已知解析拒绝服务漏洞，不影响后端协议。

## 经营码图片识别

在“实例设置 → 经营码与订单”点击“上传二维码图片”，支持 PNG、JPG、WebP，单张不超过 10 MB。识别结果原样填入“支付宝经营码内容”，仍可手动输入或修改；核对收款码后点击“保存配置”才会生效。识别只提取二维码内容，不验证收款方身份，也不会访问其中的链接。

图片仅在浏览器内读取，不发送到服务端或第三方；jsQR 按需加载，沿用现有 CSP，不使用 Blob URL、外部脚本或内联样式。源图片限制为不超过 2400 万像素且任一边不超过 8192px，识别画布最长边为 2048px；透明背景按白色处理，并尝试识别反色码。图片读取、格式或识别失败时保留当前内容，可重新选择同一文件。

识别期间禁止保存旧内容；手动修改内容、切换设置分类或离开页面会取消当前识别，迟到结果不覆盖新的输入。成功填入后沿用未保存提示、离开确认、revision 冲突保护与现有配置保存接口，不自动保存或持久化原始图片。

## 验证

```sh
npm run typecheck
npm run test:admin
npm test
npm run check
```

`npm test` 会先构建管理前端，再运行 Node 和前端测试；`npm run check` 还检查版本一致性、API 类型漂移并构建服务端。前端测试覆盖金额与密码校验、CSRF、错误处理、初始化、配置冲突、密钥清除、弹窗焦点恢复及标题层级。浏览器验证应同时覆盖桌面、窄屏、深色模式，以及首配和已有数据两种场景。

新增回归覆盖主题启动与存储回退、跨标签页、设置草稿与退出失败、双图不同量纲、零数据、小额金额、7/30/90 天、指针与键盘联动。`test/admin-smoke.test.mjs` 在真实 Hono 和临时 SQLite 上执行与容器相同的初始化、认证、资源、CSP、配置冲突与重启持久化检查；对账、通知及财务处理继续由现有 HTTP 集成测试覆盖。

### 容器发布门槛

Container validation 与 Release 工作流复用 `scripts/admin-smoke.mjs`。脚本从宿主机通过 stdin 交给容器内 Node 执行，不复制到正式镜像；镜像不得包含 `test/`、`web/` 源码、`src/`、`scripts/` 或演示密码。

该脚本只能用于全新、隔离的回环 HTTP 实例，需要显式设置 `PERPAY_SMOKE_ISOLATED=1` 和至少 24 字符的随机 `PERPAY_SMOKE_PASSWORD`。`initialize` 创建测试管理员并修改备份策略，拒绝已经初始化的实例；`verify` 在重启/恢复后检查同一账户与配置并退出登录。两种模式均检查深链接、所有打包资源、缓存、CSP 和匿名访问限制，不配置支付宝、不创建支付、不发送通知。

在仅用于验收的 Compose 项目中，可按工作流的方式执行：

```sh
export PERPAY_SMOKE_ISOLATED=1
export PERPAY_SMOKE_PASSWORD="$(openssl rand -hex 32)"
docker compose -p perpay-admin-acceptance -f YOUR_ISOLATED_COMPOSE_FILE exec -T \
  -e PERPAY_SMOKE_ISOLATED -e PERPAY_SMOKE_PASSWORD app \
  node --input-type=module - initialize < scripts/admin-smoke.mjs
```

重启后使用相同临时密码将 `initialize` 改为 `verify`。不要对已有收款实例运行；验收应使用当前源码构建的本地镜像和独立临时卷，不能用远端 `latest` 代替当前改动。通过本地检查不代表远端 CI、镜像发布或真实支付已验收；这些结果必须分别记录。

### 隔离浏览器验收

在项目根目录运行：

```sh
npm run build:admin
node --experimental-strip-types test/admin-browser-fixture.ts
```

`http://127.0.0.1:6194/admin` 提供带合成订单、账务异常和通知记录的实例，管理员密码为 `test/http-fixture.ts` 中的 `HTTP_TEST_ADMIN_PASSWORD`；`http://127.0.0.1:6195/admin` 提供尚未初始化的实例。两个实例均使用系统临时目录，不读取生产数据库，不启动支付宝或通知网络传输。按 Ctrl+C 退出并清理临时数据库；端口被占用时应先检查占用者，不要连接实际收款实例代替验收。

Hono 在启动时读取前端静态资源。修改后需重新构建并重启此隔离进程，单纯刷新浏览器不会替换服务内已缓存的资源；重启会清空本轮演示数据。这里只验收界面和管理 API，不代表真实支付已完成联调。

不能从“退款登记”推断渠道退款能力，也不能从候选记录推断订单已付款。确认金额是现有统计接口的事件口径，不能作为扣除退款后的净收入或账本结算金额。
