# 前端开发

后台和公开收银台统一使用 **shadcn/ui · Base UI · Nova · Neutral**。保留 React、Vite 和 React Router；无需单独部署前端，部署方式见[项目说明](../README.md)。

## 目录

以下路径相对仓库根目录：

| 路径 | 内容 |
| --- | --- |
| `components.json` | 官方 CLI 的 shadcn 配置；MCP 是否可用需另行核实 |
| `web/src/components/ui/` | 官方组件源码，不维护另一套基础控件 |
| `web/src/components/app-sidebar.tsx` 等 | 基于官方 `dashboard-01` 的导航、指标卡、面积图 |
| `web/src/components/login-form.tsx` | 基于官方 `login-01` 的登录与初始化表单 |
| `web/src/pages/` | 后台页面与业务交互 |
| `web/src/api/generated/` | OpenAPI 生成的管理 API 客户端；不要手改 |
| `web/src/checkout/` | 独立收银台视图、SSR / hydration 入口、轮询和下载控制 |
| `src/shared/checkout-view.ts` | SSR 与客户端共用的公开投影和状态解释 |
| `src/http/web/checkout*.ts` | Hono HTML 输出与构建清单加载 |
| `web/src/styles.css` | Tailwind v4、官方 Neutral 变量、CSP / 触控适配 |
| `web/public/theme.js` | 首次绘制前的明暗偏好 |
| `web/test/` | 前端业务与组件测试 |

旧的 Panel / Button / Dialog / 菜单封装、样式覆盖目录和静态收银台脚本已移除。添加控件使用根目录的官方工具，不另写外观相似的替代品：

```sh
npx shadcn@latest add <component>
```

组件使用默认变体；页面只组合业务数据、中文内容及响应式布局。官方源码的修改仅限中文可访问名称等必要适配；更新组件前先查看 CLI diff。官方源许可见仓库 `NOTICE`。

## 开发与构建

需要 Node.js 24.15+（24.x）。在仓库根目录执行：

```sh
npm ci --ignore-scripts
npm run build:admin
npm run build:checkout
npm run dev:admin
```

先另行启动隔离开发后端。后台开发入口是 [http://127.0.0.1:6191/admin/](http://127.0.0.1:6191/admin/)，默认代理到 `http://localhost:6190`。更换后端时设置 `PERPAY_DEV_API_URL` 并核对该实例的 `PERPAY_PUBLIC_URL` / Origin 配置。**不要连接生产收款实例。**

Vite 在开发态从该后端的 `/admin/` HTML 读取初始化标记，再注入热更新页面；启动开发后端前需至少构建一次管理台。每次加载页面都重新读取，不把首次状态缓存为永久状态。后端未启动、尚未加载管理台构建或没有明确标记时，认证页提供重试，不把未知状态当作首次部署。生产构建仍由 Hono 直接注入状态，不经过开发态桥接。

收银台由 Hono 提供 SSR 页面。修改收银台后执行 `npm run build:checkout` 并重启隔离后端；Vite 的 `/checkout` 和 `/assets/checkout` 代理不代替生产构建。

| 命令 | 用途 |
| --- | --- |
| `npm run build` | 构建全部客户端资源、私有收银台 SSR 和服务端 |
| `npm run build:admin` | 构建管理后台 |
| `npm run build:checkout` | 构建独立收银台客户端与 SSR |
| `npm run api:types` | 修改 OpenAPI 后生成类型与客户端 |
| `npm run test:admin` | 前端测试 |
| `npm test` | 先构建两个前端，再运行全部测试 |
| `npm run check` | 版本、接口、类型、测试与服务端构建检查 |

客户端产物分别位于 `web-dist/admin/` 和 `web-dist/checkout/`。`web-dist/checkout-ssr/renderer.cjs` 是**私有**产物，已打包 SSR 所需前端依赖；Docker 在裁剪开发依赖后仍保留它。只按构建清单提供公开资源，不发布 SSR、源码、source map 或清单文件。

## 安全与交互约束

- 管理员初始化只由服务端明确的 `initialized=false` 开启，并作为主页面呈现；正常实例不显示初始化链接，访问 `/setup` 也回到登录。创建成功后单独登录；遇到另一个客户端已完成初始化的明确冲突时，清空新建密码并回到现有管理员登录。配置向导属于登录后的收款设置，不等于重复创建管理员。
- 不放宽服务端 CSP。入口使用 Base UI 的 `CSPProvider disableStyleElements`；必要规则在外部 CSS。图表配置只提供标签，不让 Chart 在页面里注入无 nonce 的样式元素。SSR HTML 不含可执行内联脚本或 style 属性。
- 收银台不加载后台路由、管理 API 客户端和设置组件。启动数据仅包含公开订单投影、初始错误、服务端时间和同源资源地址；不包含管理员退款标记、备注或密钥。关闭 JavaScript 后仍能读取订单与有效二维码或终态说明。
- 收银台保留轮询、失败退避、Retry-After、离线 / 隐藏暂停、取消请求和旧响应丢弃。计算付款期限时计入脚本加载和 BFCache 停留时间；到期关闭二维码并取消尚未完成的 PNG 下载。
- `perpay:theme` 只保存 light / dark / system，跨标签页同步；不再读取 `perpay:palette`。明暗切换不能重新挂载表单、读取密钥或发送业务写请求。
- 后台写操作继续使用现有 CSRF、幂等 UUID、并发版本和服务端校验。相同请求重试保持 UUID，冲突不静默覆盖。密钥轮换结果不确定时当前弹窗不能再次提交。
- 人工关联收款遇到资金状态冲突后先重新核对证据，不直接重复确认旧事实；重读失败不能回退到旧预览。同一请求结果不确定时仍保留原请求编号重试。关联成功后，上下文入口会禁用或移除，焦点返回主内容；取消则回到原入口。
- 固定证据确认弹窗收到 HTTP 409 后不再提交旧命令，关闭时刷新业务数据；普通校验错误和暂时性失败不被误判成状态冲突。嵌入详情的撤销操作完成后，焦点返回稳定的主内容，独立关联详情仍回原操作入口。
- 密钥仅在点击查看后读取，不进入查询缓存；关闭、隐藏标签页和 60 秒超时清除明文，并取消未完成的读取。
- 表单无修改时禁止普通保存，首次向导可以保存继续。高级字段折叠时使用 `keepMounted` 保留表单值；原生或服务端校验失败时展开并定位。离开脏表单只确认一次。

## 数据与状态语义

- 列表使用服务端游标，不对当前页伪装全量搜索或排序。订单号为精确查询，返回详情来源时保留筛选和分页。
- 详情复用订单已经携带的流水、候选及通知尝试；缺少的关联资源按 ID 复用缓存，不递归加载完整关系链。操作在本页完成并刷新相关缓存。
- 图表基于真实每日数据，金额与数量切换显示，不叠到同一尺度。区间请求未完成时显示加载占位，不能将旧区间标为新区间；保留键盘访问和每日数据表。
- 忽略提醒不等于处理异常，也不停止通知重试。运行统计仍包含已忽略事项；其链接须明确对应全部记录还是未忽略提醒。
- 退款是独立的管理员标记，使用官方红色状态标签，不改变付款、金额或历史退款语义。未付款且无标记历史时隐藏退款操作；完整说明在确认弹窗内。

验收除 `npm run check` 外，还需在**实际生产 CSP**下检查后台和无脚本 / hydration 收银台，覆盖浅色、深色、2560 / 1440 / 1024 / 390 / 320px、长文本、键盘及危险操作取消。所有写操作验证只使用隔离数据库。演示图表数据只能放在工作区外的预览夹具中，不能进入应用默认数据或生产统计。

### 界面显示设置

实例设置 → 界面显示，可切换收银台商品名称显示和首页图表样式（面积 / 柱状 / 折线）。设置保存到实例数据库，跨浏览器与重启保持；使用原配置版本校验、CSRF 与审计，不改变付款版本或订单 / 通知 API 内容。隐藏商品名称仅控制页面展示，不作为数据保密功能。

首次配置的常规采集默认为 60 秒、活跃 8 秒、采集有效时限 120 秒，已有采集配置保持不变。显示设置新增数据库迁移 24，应用版本仍为 0.2.2；旧版程序不可直接读取升级后的库。

### 官方组件组合与布局验收

- 页面中的交互控件使用 `web/src/components/ui/` 的官方组件；业务组件只组合数据、状态与操作，不另写按钮、菜单、表单控件或弹窗。提交用的隐藏 input 不属于视觉控件。
- 保留官方默认变体，优先用已有 size、variant 与子组件处理密度；响应式 className 只用于必要的布局，不另建覆盖主题。
- 订单表格按**容器可用宽度**切换列，避免侧栏展开时错误套用桌面布局。窄屏把付款状态、退款标记放进订单摘要，不隐藏关键信息。
- 设置分类窄屏使用官方 NativeSelect，宽屏使用带图标的 line Tabs。经营码与订单规则、收银台与图表显示分别放在官方 Card 中，相关保存操作使用 CardFooter；不再将完整表单限宽后靠左。切换分类须继续遵守脏表单确认，不能重置草稿或隐式保存。
- 主导航、辅助导航使用 SidebarMenuButton 的默认 32px 行高和 SidebarMenu 的默认间距，不使用 `lg` 导航按钮制造留白；触屏仍保留必要点击面积。
- 图表使用官方 ChartTooltipContent 的 formatter 扩展点，标签与金额至少相隔一个明确 gap，金额右对齐、不折行；提示只包含实际绘制的数据系列，不补造未绘制系列。数量与金额切换使用 ToggleGroup，坐标轴明确单位。
- 订单工作区使用金额卡、订单信息、收款依据、通知与 Item 动态列表；中屏两列、宽屏三列，不保留旧版 max-w-6xl 靠左空栏。金额与订单卡保持自然高度，不按同一行最高卡片拉伸；内容不足一屏时允许自然留白，禁止用无意义组件或虚构数据填充。
- 密钥状态与用途放在同一摘要列并按可用宽度自然换行，每行只渲染一份状态；查看与生成操作不能挤碎密钥名称。密码表单的提交按钮位于 CardFooter，但与输入框属于同一个原生 form，保留回车提交与校验焦点。
- 设计参考为官方 `dashboard-01`、`preview-02` 的金额卡 / 设置卡与 `examples/base`；示例只提供组合与视觉基准，不能复制营销占位数据、无作用按钮或不适用的金融口径。
- 验收包含弹窗内部、表格内部和当前导航项的可见性；“整页无横向溢出”不是通过标准。长内容的资金操作弹窗使用可滚动正文，标题、风险说明和取消 / 确认按钮保留在正文外；字段错误需通过 aria-describedby 正确关联。
