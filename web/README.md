# 前端开发

仅供修改源码。部署请看[项目说明](../README.md)，无需单独部署前端。

## 目录

以下路径相对仓库根目录：

| 路径 | 内容 |
| --- | --- |
| `web/src/pages/` | 后台页面 |
| `web/src/components/` | 共用组件与配置表单 |
| `web/src/api/` | API 客户端；`generated/` 由接口文档生成，不要手改 |
| `web/src/styles/` | 样式 |
| `web/public/` | 静态资源 |
| `web/test/` | 前端测试 |

公开收银台不在 `web/`：模板位于 `src/http/web/checkout.ts`，样式和脚本位于 `static/app/checkout.*`。

## 本地开发

需要 Node.js 24.15+（24.x）。以下命令均在仓库根目录执行。

先启动独立开发后端，再运行：

```sh
npm ci --ignore-scripts
npm run dev:admin
```

打开 [http://127.0.0.1:6191/admin/](http://127.0.0.1:6191/admin/)。Vite 默认代理到 `http://localhost:6190`；换后端时设置 `PERPAY_DEV_API_URL`，与该后端的 `PERPAY_PUBLIC_URL` 一致。不要连接生产收款实例。

## 构建与测试

| 命令 | 用途 |
| --- | --- |
| `npm run build` | 构建前后端，产物为 `dist/` 和 `web-dist/admin/` |
| `npm run build:admin` | 只构建管理前端 |
| `npm run api:types` | 修改 `openapi.yaml` 后重新生成 API 类型与客户端 |
| `npm run test:admin` | 运行前端测试 |
| `npm run check` | 完整检查：版本、API 类型、类型检查、全部测试和服务端构建 |

## 详情工作页面

- 订单详情集中展示收款、异常及通知，桌面使用主次双栏，手机按业务优先级单栏展示。后台控件使用统一间距和触控目标；详情保留独立的紧凑布局。
- 订单、关联、候选、异常、流水和冲突共用详情组件。使用订单自带的流水、候选和通知页自带的尝试记录，不逐条重复查询。隐藏的异常历史在展开后加载缺失上下文，关联查询按资源 ID 复用缓存，不递归加载整条关系链。
- 金额推断摘要只解释已知结构中的有效字段；未知结构保留原始证据，不猜测。操作人的理由来自只读操作记录，提醒状态与资金状态独立。通知的最新标识由服务端跨分页计算，写操作仍由服务端重新校验资格。
- 低频操作放在记录的“更多”中；仅有技术信息时直接展开，不再多套一层菜单。详情内操作复用原有幂等和单次确认对话框，不导航离开当前订单；已知对象自动带入，但实际关联前重新读取证据。刷新同时覆盖当前展示的关联数据。
- 详情交互、摘要准确性与只读上下文均有独立回归测试。

## 提醒与退款界面边界

- 待处理的查询键和游标必须同时包含分类与 `visibility`。批量请求使用确认时捕获的分类与操作 UUID，重试不能生成新 UUID；成功后刷新首页及全部分类并回到第一页。
- “已忽略”不是底层事项状态，已结束记录不可恢复提醒；不要用它过滤运行状态中的真实冲突和通知统计。账本与对账的默认待处理异常／冲突由管理接口在数据库分页前排除已忽略项；全部冲突及历史详情不受影响，通过“查看已忽略”进入同分类的提醒历史。忽略与恢复后都要刷新账本列表缓存。
- 管理员退款标记使用独立版本，不复用业务订单版本。对话框打开后保持版本快照，冲突时要求重新读取，不自动覆盖。标记不选择支出流水，也不调用旧退款写接口。
- 相关交互测试在 `web/test/work-item-actions.test.tsx` 和 `web/test/refund-mark.test.tsx`；后端与迁移测试只使用隔离数据库。

## 外观与统一交互

- `web/public/theme.js` 在首次绘制前设置 `data-theme` 和 `data-palette`；分别使用 `perpay:theme`（light/dark/system）与 `perpay:palette`（blue/bamboo/sand/violet/graphite）。非法值独立回退，存储不可用时仍可在内存切换。
- 配色定义在 `themes.css`，不能把成功、警告和错误色替换成配色强调色。切换时同步前景和背景，避免低对比度渐变；不重新挂载业务页面、不预取密钥、不提交配置。
- `MoreActions` 处理键盘、焦点和点击外部关闭；`RecordTools` 复用菜单与原始信息展开；`SuccessMessage` / `useFeedback` 提供约 4 秒的局部成功反馈。错误排障编号折叠展示。
- 设置表单保留草稿保护。普通已配置表单未修改时禁止保存，首次向导不受此限制。隐藏的高级字段仍保留表单值，错误定位前先展开所在区域。
- 密钥明文仅在明确查看后读取，不进入查询缓存；保持请求取消、60 秒与标签页隐藏清理。轮换不是幂等写操作，结果不确定后当前弹窗禁止再次提交。
- 手机通知与对账表格转为分块记录；长编号和原始证据不得导致页面级横向溢出。运行统计包含已忽略记录，不能把真实总数链接到未忽略提醒列表。
- 交互回归见 `web/test/usability.test.tsx`、`theme.test.tsx`、`theme-contrast.test.ts`；视觉验收使用独立临时数据库，覆盖五种配色的明暗模式及 1440/390/320px 视口。
