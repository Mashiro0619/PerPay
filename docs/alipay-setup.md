# 支付宝配置图文教程

先准备收款码或经营码并核对下方条件，再[部署](../README.md#部署)并登录 PerPay，打开 **系统设置 → 配置向导**。配置路线是：创建账号 → 配置支付宝应用和密钥 → 检查连接 → 上传收款码或经营码 → 分配给业务网站。

## 准备条件自检

| 要准备什么 | 去哪里确认 | 完成标志 |
| --- | --- | --- |
| 支付宝收款账号和收款码 | 保存该账号的收款码图片；使用经营码时，按下方步骤申请并保存 | 收款账号与开放平台应用对应，二维码能正常识别 |
| 开放平台应用 | 登录[支付宝应用管理](https://open.alipay.com/develop/manage)，打开已有应用或创建网页应用 | 记下 App ID，应用状态为“已上线” |
| 账务明细查询权限 | 在该应用的产品／接口权限中核对[账务明细查询接口](https://opendocs.alipay.com/open/02awe0) `alipay.data.bill.accountlog.query` | 该应用可查询对应收款账号的账务明细 |

新建应用后，在支付宝应用控制台完成资料、产品开通和上线流程；缺少查询接口时，按控制台提供的申请入口处理。若当前账号无法开通该接口，先解决权限问题，再配置 PerPay。PerPay 的连接检查会实际查询账单并验证响应签名，可用于确认最终配置是否可用。

“开发中”的应用不能用于这里的正式查账。收款码、App ID 和密钥应属于同一收款账号；多个收款账号分别配置。

### 申请并保存经营码

1. 在支付宝登录实际收款的账号，搜索 **“经营码”**，进入支付宝提供的申请入口。
2. 按申请页面要求填写资料并完成申请。已有经营码可直接打开经营码页面。
3. 申请成功后，保存该账号的经营码二维码图片，供下方 **第 5 步** 上传。

接下来为同一个收款账号配置开放平台应用和密钥，并核对应用的上线状态与账务明细查询权限。普通收款码与经营码都在 PerPay 的 **收款码** 页面上传。

## 1. 创建 PerPay 支付宝账号

在配置向导的 **配置支付宝账号** 中点击 **添加支付宝账号**，填写账号名称，点击 **创建账号并继续**。页面转到“应用信息”，顶端列出尚缺的配置。

账号的“接收新订单”开关表示配置完成后的接单意愿。应用、密钥和收款码补齐并通过查账后，该账号才参与收款。

## 2. 打开或创建支付宝应用

已有应用可直接打开并记下 **App ID**；新建应用从[应用管理](https://open.alipay.com/develop/manage)的 **网页／移动应用** 进入创建流程，选择 **网页应用**，按平台要求填写应用信息和关联账号。

![打开应用创建入口](assets/alipay-setup/01-create-application.png)

![应用类型选择网页应用](assets/alipay-setup/01b-select-web-application.png)

创建后完成平台要求的上线与接口开通步骤。把同一应用的 **App ID** 填入 PerPay 的“应用信息”，可以先 **保存配置**。

## 3. 生成并上传应用公钥

在 PerPay 点击 **生成应用密钥**，复制生成的 **应用公钥**。应用私钥由 PerPay 加密保存，用来签名查账请求。

首次接入已有密钥时，也可以展开 **导入已有应用私钥（可选）**，导入后保存，再复制显示的应用公钥。应用私钥与支付宝公钥是不同的字段。

**① 在支付宝应用打开 开发设置 → 接口加签方式 → 设置。**

![打开接口加签设置](assets/alipay-setup/02-open-signing-settings.png)

**② 选择“密钥（普通适用）”，点击“下一步”。**

![选择密钥方式](assets/alipay-setup/03-select-key-mode.png)

**③ PerPay 已生成密钥，直接进入上传步骤。**

![跳过密钥工具](assets/alipay-setup/04-skip-key-tool.png)

**④ 粘贴 PerPay 的应用公钥，点击“确认上传”。**

![上传应用公钥](assets/alipay-setup/05-upload-application-public-key.png)

平台侧说明见官方[设置密钥加签方式](https://opendocs.alipay.com/common/02kdnc)。

## 4. 填回支付宝公钥并检查连接

上传完成后，复制同一应用页面提供的 **支付宝公钥**，填回 PerPay 的“支付宝公钥”。

![复制支付宝公钥](assets/alipay-setup/06-copy-alipay-public-key.png)

核对应用已上线及查询权限，然后点击 **保存并检查**。结果分别显示配置保存和连接检查状态：

- **连接检查通过**：App ID、签名和账单查询可以使用。若尚缺收款码，页面会直接列出“待补充：收款码”。
- **连接检查未通过**：根据显示的原因，核对 App ID、应用公钥、支付宝公钥、查询权限或网络。配置已保存，修正后再次保存并检查。

查账节奏在独立的“查账设置”中调整，初次配置可使用默认值，详见[查账节奏](../USAGE.md#查账节奏)。

## 5. 上传收款码或经营码并创建网站

1. 在当前支付宝账号切换到 **收款码**，上传或拖入此前保存的收款码或经营码图片，核对识别结果后保存。
2. 在 **运行状态** 查看首次查账结果。配置完整且收款就绪时，账号可用于新订单。
3. 点击 **创建业务网站**，填写网站名称并选择收款账号；多个账号可随机或按权重分配。
4. 创建完成进入 **接入与通知**，按业务系统选择协议。

| 接入方式 | 下一步 |
| --- | --- |
| 已有易支付插件 | 选择插件使用的易支付 V1/V2，复制对应网关、商户 PID 和凭据，见[易支付接入](epay-integration.md) |
| 自己开发原生 API | 生成该站 API 密钥；需要回调时再生成通知签名密钥，见[原生接入](integration-quickstart.md) |
| 先验证收款 | 在配置向导进入“试收款”，选择网站创建小额测试订单并按收银台金额付款 |

通知域名填写完整回调地址的来源部分。例如回调地址为 `https://shop.example.com/payment/notify`，通知域名填写 `https://shop.example.com`。保存接收端配置后，在网站开启通知并保存；未开启通知的业务系统可主动查单。

收款确认后，再核对业务网站是否收到通知。通知失败的原因与后续投递结果可在对应订单的通知记录中查看。备份属于系统设置，恢复配置时还需要主密钥，见[维护说明](maintenance.md)。

## 更换应用密钥

打开 **系统设置 → 支付宝账号 → 对应账号 → 应用信息**，点击 **更换应用密钥**。

尚未完成支付宝接入配置时，此操作直接替换原密钥对；已经复制或上传过原公钥的，需要重新上传新公钥。

已完成接入的账号按以下步骤切换：

1. 确认生成新密钥，新密钥会保存为 **待启用**，当前仍使用原密钥。
2. 复制 **待启用应用公钥**，上传到同一支付宝应用。
3. 从支付宝重新复制本次提供的公钥，填入 **新的支付宝公钥**。
4. 点击 **验证并启用**。只读账单查询和响应验签通过后，PerPay 才切换到新密钥。

验证失败时，修正后重试。待启用密钥保存在账号中，离开或刷新页面后可继续。若决定放弃且已向支付宝上传新公钥，先在支付宝恢复当前应用公钥，同步恢复后获得的支付宝公钥，再点击 PerPay 的 **放弃新密钥**。

换钥只处理当前账号，保留 App ID 和查账参数。支付宝侧的生效过程见官方[更新密钥／证书](https://opendocs.alipay.com/common/05wt1i)。

## 配置冲突与旧账号

账号被其他会话修改时，点击 **重新读取账号**，核对双方修改后保存。服务器已有待启用密钥时，先采用服务器的应用配置，再启用或放弃该密钥。

升级留下的旧沙箱账号保留历史记录。需要继续收款时，新增使用已上线应用的正式账号。

## 通知签名密钥维护

在 **业务网站 → 网站设置 → 接入与通知** 选择原生 API，生成或轮换 **通知签名密钥**。生成密钥后配置接收端、填写通知域名，开启通知并保存。

轮换后，新发送和重试的通知使用新密钥，正在发送的请求可能仍使用旧签名；及时更新业务系统的验签配置。轮换不自动重发已完成的通知。

网站密钥通过独立弹窗查看和复制，关闭即清除显示内容。首次生成或轮换的结果不明确时，关闭提示后点击“重新读取密钥状态”，再查看当前密钥。重读会保留未保存的配置；遇到配置冲突时，先应用核对结果，再继续密钥操作。
