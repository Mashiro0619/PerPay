# 后台详情、编辑弹层与设置摘要

本轮调整管理后台的列表、详情和配置入口。以下说明对应未发布源码；数据库版本与业务接口沿用当前 RC，不引入新的管理员角色或网站权限。

## 页面与操作入口

- 订单、通知、流水、对账证据、审计记录和网站概况从列表打开详情弹层。列表保留筛选、排序、当前游标和已读取内容；进入详情本身只读取数据。
- 管理网站使用紧凑表格，显示名称、接单状态、所选周期实收、待处理数量和操作。名称打开网站概况；“进入后台”进入网站工作区，“网站设置”进入该网站的设置摘要。
- 支付宝账号使用紧凑表格。配置弹层分为基本信息、应用信息、收款码、应用密钥和使用情况；切换分组保留同一份配置草稿。
- 实例设置显示当前值和编辑入口。网站设置保留基本信息、收款账号、订单设置、接入与通知、收银台展示五个普通摘要页，编辑时在一个弹层内切换分组。默认模板独立编辑，只影响以后创建的网站。
- 安全设置展示白名单与密码摘要、密钥入口和登录会话。密码、白名单、会话详情分别打开弹层；会话列表保留单个撤销、退出其他会话和注销全部会话。
- 首次配置向导继续使用嵌入式表单和原步骤，不要求先进入日常设置摘要。公开收银台继续使用独立页面。

## 地址与历史记录

地址栏保留父页地址，`overlay` 参数保存前台对象的内部路径。参数值需要 URL 编码，不包含 `/admin` 前缀。例如：

```text
/admin/orders?payment=UNPAID&overlay=%2Forders%2Fexample-order
/admin/settings/display?overlay=%2Fsettings%2Fdisplay%2Fedit
/admin/sites?range=30&overlay=%2Fsites%2Fexample-site%2Fsummary%3Frange%3D30
```

以上编号仅为格式示例，访问时仍须使用当前实例存在的对象。

| 入口 | 行为 |
| --- | --- |
| 从列表打开详情 | 保留父页条件，关闭后回到原列表；触发元素仍存在时恢复焦点 |
| 详情中的关联对象 | 在同一个详情容器切换；前进、后退遵守已知的前台历史 |
| 旧订单、通知、流水、审计等详情路径 | 转换到合法父页与 `overlay` 参数，仍可刷新、复制和在新标签页打开 |
| 旧订单、通知、流水详情中的 `section` 参数或 hash 锚点 | 定位同一正文中的分区或记录；优先按 hash 锚点定位，无 hash 或无法识别时回退合法 `section`，保留父页状态与详情参数 |
| `/admin/sites/:clientId/settings/:section` | 保留为网站设置摘要；编辑入口为 `/sites/:clientId/edit?section=...` |
| 直接访问或重新加载详情地址 | 读取父页和目标对象；关闭时安全返回父页，不根据不存在的页面历史退到外部网站 |
| 无效或未注册的前台路径 | 在弹层内显示错误，不把任意外部地址当成后台详情 |

URL 能保存筛选与当前游标。已经访问的游标链、原触发元素和滚动位置属于当前浏览器运行会话；重新加载后不能恢复已经销毁的 DOM 或未知历史。此时关闭采用父页地址，焦点回到主内容。

首次未登录时打开共享详情地址，登录后继续进入该详情。已经登录的会话失效时，前台请求、草稿和受保护缓存被清理；重新登录停留在父页，不恢复旧会话的未完成操作。

## 桌面与手机

详情共用一个容器，标题和操作区保留在容器内，正文独立滚动。普通长表单或选取流程作为内部步骤展示，短确认继续使用确认框；进入内部步骤后不会同时展示两套可操作的正文。

订单的概况、收款关联、通知、动态与记录，通知详情的概况与投递记录，以及流水的交易、收款关联、采集记录和已有冲突，按业务顺序连续展示在同一正文中。各分区同时挂载，通过正文滚动阅读；滚动不修改详情地址，也不创建一条前台历史。

记录详情的字段按内容自然宽度排列，标签与值优先同行，空间不足时自然换行。字段、标签和值均限制在当前容器宽度内；备注、长商品名、地址和时间范围等指定长字段独占一行并保留完整文字。商户订单号与流水详情中的核对凭据随内容宽度排列，长编号自然换行并可完整复制。分区间距为 1rem，分组内部间距与字段换行间距为 0.5rem，同行字段间距为 1.5rem。此规则只作用于记录详情，编辑表单与确认步骤保持原有布局。

订单的下单金额和加价金额并入订单信息；未关联提示与人工关联入口同排，按钮保持自然宽度。订单动态的事件、时间与说明紧凑排列，较早动态、异常历史和通知历史继续使用原有折叠与分页。

流水与对账详情的环境标记紧随“支付宝交易”标题，支付宝流水号、订单号与商户单号按实际长度排列。只有一份查账记录时直接展示状态、内部流水编号与保存时间，省去重复的可见来源标题和外框；“查账记录 1”仍作为屏幕阅读器可读标题保留。多份来源保留各自的可见标题和边界；来源编号、当前关联、撤销历史、操作资格及原有锚点不变。

订单主记录成功读取后首次加载该订单的通知列表；通知详情先读取投递主记录，成功后首次加载投递尝试。主记录读取失败时不发起投递尝试查询，失败状态仍可明确重试。滚动、调整窗口或改变内容宽度本身不重复发起读取；刷新、重试和分页继续按原流程请求数据。

桌面在视口允许时，常规详情最大宽度为 40rem；订单、通知、流水与对账等业务详情统一使用 56rem，默认字号下分别约为 640、896px。流水的当前入口与旧 `/ledger/:ledgerEntryId` 地址使用相同宽度。小于 768px 时使用全屏布局。后台列表仍根据可用宽度切换表格与手机摘要；这不改变查询范围或记录数量。

固定按钮区通过 `OverlayActions` 保留表单上下文。移入按钮区的提交按钮显式关联原表单；滚动、调整窗口和切换内容宽度不会创建第二份草稿。账号弹层常驻“保存并检查”，草稿保存和重新检查从“更多账号操作”打开，避免放大文字时操作区挤空正文；菜单提交的必填校验仍会切换并聚焦错误字段。

设置与列表视图保留横向分类，用方向键移动焦点，按 Enter 或空格才打开对应分类。焦点与选中项在横向容器内显示，调整窗口时保留可见位置，不带动页面纵向滚动；订单、通知和流水详情使用上述连续正文。

## 技术信息与核对凭据

所属记录的“技术信息”入口打开独立的只读弹窗，展示完整标识符、原始数据与复制入口。业务核对需要的金额、编号、来源、时间和处理记录继续直接展示在主详情中。技术信息不再在原正文内展开，也不作为替换主正文的编辑步骤。

打开或关闭技术弹窗时，父详情保留同一份 DOM、窗口尺寸和正文滚动位置，不改变详情地址或历史。技术弹窗的标题、顶部关闭按钮与底部关闭区固定在非滚动区域，只有正文纵向滚动；长编号和原始数据在正文中换行，不建立第二层滚动盒。打开时焦点进入标题，点击窗口外部或按 Escape 只关闭技术弹窗并恢复到原“技术信息”入口，父详情保持打开。技术窗口拥有自己的遮罩，外部点击不会穿透到主详情的按钮；从窗口内开始、在外部结束的拖动不作为关闭操作。

小于 768px 时，技术信息使用全屏阅读窗口；长内容、200% 字号和短视口下仍保持标题、关闭入口与正文单滚动区。读取、滚动与复制只使用已读取的记录，不提交业务操作。

## 草稿、提交与权限

- 同一个对象内切换分组、页内查询或查看信息时保留草稿。关闭、切换对象、离开父页和浏览器后退统一交给现有的导航保护处理；取消离开后保留字段与焦点。
- 存在关闭保护的进行中操作会取消本次离开；需要确认离开的已提交或结果未确认操作继续使用原确认与重试流程。关闭界面不等于取消已发送的请求，恢复网络也不会自动重放保存或财务操作。
- 设置弹层的刷新先处理未保存修改。确认并成功读取最新配置后才重新建立表单基线；读取失败保留草稿。修订冲突不自动覆盖服务器值，网站跨分组的修改一并参与合并核对。
- 已提交的保存可能在离开后完成。重新进入编辑时先完成首次配置读取，再建立表单；读取失败可重试，避免把旧值当作保存后的结果。
- 账号、网站创建或删除由服务器确认完成后再切换界面。删除同时清理对应详情缓存，避免重新打开一个看似仍可编辑的已删除对象。
- 查询、打开详情、切换分组和复制地址不提交配置。财务操作、密钥操作、密码修改、会话撤销继续使用原 API、管理员会话、CSRF、IP 白名单和服务端业务校验。
- 详情 API 的网站范围来自目标对象的 `/sites/:clientId` 路径。父页 API 范围与侧栏选择不被详情改写；`selected_site` 仅用于导航记忆，不能作为写入身份或新增权限。
- 密钥仍按原规则隐藏与清除；离开、隐藏或会话失效后不恢复晚到明文。查看或隐藏密钥不代表取消已经执行的轮换。

网站实收按选择的周期读取，切换周期时不会把旧周期金额显示为新周期结果。读取失败使用不可用状态，未知金额不显示为零。会话详情展示完整来源 IP、设备信息和有效期；已撤销会话显示已结束。

## 审计列表与详情

审计页默认查看操作审计，提供操作审计、接口访问、后台任务、维护活动和全部记录五个视图。视图是界面选择；既有 `source`、`category` 筛选地址继续有效。桌面默认展示时间、事件、执行者、网站、IP、客户端、结果和详情，方法、路由、HTTP 状态及日志 ID 可按需显示。

搜索、日期和结果保留为常用筛选，其余放在高级筛选中。“显示”菜单集中密度和桌面列选择；桌面隐藏列不改写手机的固定摘要。采集状态、保留期、快照时间和 CSV 规则从页头进入，异常及已检测到的来源缺口继续显著显示。

详情默认展示事件和中文字段变化，UUID、请求 ID、原始设备信息等放在技术信息中。秘密字段继续脱敏；分钟汇总的次数、首次与末次时间、累计与平均耗时保留原口径，关联多条日志不等于执行多次业务操作。

## 本地预览

在仓库根目录完成构建后，可启动可编辑的临时预览：

```sh
npm run demo:preview -- --interactive --port 6192
```

访问 `http://127.0.0.1:6192/admin/`，初始演示密码为 `123456`。交互模式允许现有管理员 API 修改本次生成的临时数据库，可验证保存、校验错误、版本冲突和 CSV；会话、来源、CSRF、修订及幂等校验仍由实际应用执行。退出进程后清理临时数据，重新启动重新生成样本。

省略 `--interactive` 时继续使用默认只读演示，只允许原有登录、退出和受保护导出。两种模式都绑定回环地址，使用合成网站、订单和非付款二维码；健康与查账状态为模拟数据，不启动支付宝客户端、自动查账或通知发送。公开收银台继续保留演示限制。

官方更新查询默认关闭并显示预期的不可用结果。需要读取真实的官方版本元数据时，可额外传入 `--official-updates`；这个选项只影响更新查询，不启用付款或通知传输。

## 维护入口与回归

新增详情类型时同时登记 `overlayRouteDefinitions`、合法父页和资源范围，再接入统一容器。页面标题、页头操作与底部操作使用现有上下文；不要在业务页面另建一套全屏路由或跳过导航保护。

需要同时验证旧详情地址、列表打开、刷新、新标签页、关闭、前进后退、跨网站对象、失败重试和会话失效。表单还要检查固定按钮关联、隐藏字段错误聚焦、跨分组草稿、版本冲突、进行中请求和完成后的跳转。

主要自动化入口：

- `web/test/overlay-navigation.test.ts`、`overlay-host.test.tsx`、`overlay-session.test.tsx`、`secondary-dialogs.test.tsx`：地址、历史、作用域、独立技术弹窗、焦点和认证恢复。
- `web/test/detail-sections.test.tsx`、`order-detail.test.tsx`、`notification-readable.test.tsx`、`ledger.test.tsx`、`ledger-dense.test.tsx`：连续分区、旧链接定位、首次读取、失败恢复、来源身份与完整核对凭据。
- `web/test/settings-overlays.test.tsx`：设置摘要、固定提交区、跨分组冲突、周期统计、创建／删除完成和会话详情。
- 网站配置、应用密钥、会话、向导、导航及操作恢复原有组件测试继续保留业务断言。
- `ui-tests/settings.spec.ts`、`session-management.spec.ts`、`security-card-flow.spec.ts`、`mobile-settings-reflow.spec.ts`：真实浏览器中的摘要、弹层、横向分类键盘可达性、焦点和放大文本。
- `ui-tests/alipay-accounts.spec.ts`、`site-required-fields.spec.ts`、`site-timeout.spec.ts`、`site-delete-navigation.spec.ts`：独立本地数据库中的保存、必填反馈、修订冲突与删除结果。
- `ui-tests/detail-record-layout.spec.ts`、`detail-reading.spec.ts`、`order-card-flow.spec.ts`、`unified-reconciliation.spec.ts`、`copy-sources.spec.ts`、`mobile-dialog-flow.spec.ts`、`technical-dialog-dismissal.spec.ts`：连续详情、完整字段与复制来源、旧锚点、独立技术弹窗及其父详情的尺寸／滚动／DOM 保持、鼠标与触摸外部关闭及防止点击穿透、单滚动区域及滚动和缩放时的请求次数。
