# 1.0.0 用户流程修复浏览器验收

日期：2026-10-08（北京时间）。对应[原始审查及修复记录](../user-flow-review-1.0.0.md)。使用真实 Chromium 154.0.8037.98 和项目正式构建，桌面及 390 × 844 窄屏；合成数据库位于系统临时目录，没有真实付款、支付宝采集或外部通知投递。

## 重现环境

在仓库根目录运行：

```powershell
npm run build
node --experimental-strip-types test/admin-browser-fixture.ts
```

访问 `http://127.0.0.1:6194/admin/`，使用隔离 fixture 的测试密码 `a-secure-local-password` 登录。6195 为另一份全新实例。测试数据与凭据只用于此隔离 fixture；退出运行进程结束验收。源码或构建改变后应重启 fixture，因为静态资源在应用创建时加载。

以下表格给出浏览器操作及断言。需要模拟网络返回的场景使用 Playwright 路由拦截；完整业务边界由仓库保留的 React、HTTP、SQLite 回归共同验证。

## 场景与实际结果

| 场景 | 操作与断言 | 结果 |
| --- | --- | --- |
| 跨组连续保存 | 新建网站 A；基本信息改名 → 订单有效期改为 420 秒 → 返回基本信息再次改名；全程在同一后台会话中操作 | 三次保存成功，无 409，无错误提示 |
| 冲突合并 | 本地修改网站名称；用实际 API 模拟另一会话将名称改为不同值、有效期改为 480 秒；本地保存收到 409，点击读取并核对 | 选择前“应用核对结果”禁用；选择保留本地名称后显式保存，GET 验证名称为本地值、有效期仍为服务器的 480 秒 |
| 窄屏与键盘 | 在 390px 下对冲突选择聚焦并按空格，随后应用、保存；检查页面宽度 | 可完成选择和保存，documentWidth 不超过视口宽度，无横向溢出 |
| 离线放弃 | 实例采集设置将常规间隔从 10 改为 20；真实 browser context 离线 → 保存 → 切换界面显示 → 确认放弃 → 恢复网络 → 返回采集设置 | 写请求计数始终为 0，恢复后值仍为 10；提示说明在途保存可能继续，未承诺撤销已发送请求 |
| 人工关联 | 共享账本打开人工关联；候选显示网站身份；选订单，再从全部可关联收入流水中选择，进入最终确认 | 候选与最终确认均显示“原业务网站 · default”；确认按钮可用，金额不同仍有提示；验收结束取消操作，未执行关联 |
| 测试收款跨站恢复 | A 创建测试订单：请求送到实际 API 后故意丢弃响应；暂时关闭、切到 B、打开测试收款并重试原请求；仅将结果 GET 合成为已确认 | 两次 POST 均属于 A；B 页面内的“查看订单”指向 A，实际点击后进入 A 的订单详情 |
| 关闭后观察 | 打开 fixture 既有关闭订单收银台；手动查询一次；第二次 GET 合成为迟到确认 | 两次请求均为 GET，间隔 30009ms，页面自动显示“收款已确认” |
| 过期后观察 | 打开 fixture 已过期订单，390px 下使用 Enter 触发查询；第二次 GET 合成为迟到确认 | 两次 GET 间隔 30018ms，自动查询后显示确认，无核实 POST，窄屏无横向溢出 |
| 新网站通知配置 | 新建网站显式生成 API 和通知密钥，隐藏明文；配置来源 `https://shop.example.com`，再开启通知并保存 | 保存成功；GET 返回通知已启用及正确来源，没有 `site_secret_missing` |
| 轮换说明 | 查看通知轮换确认并取消，检查在途旧签名、新尝试新密钥及接收端过渡说明 | 卡片和确认区分 API 与通知语义；没有改变后端签名行为 |

真实浏览器只验证了表格列明的场景；重复商户号及同名网站、批量忽略离线恢复、404 终止、读取失败、重复版本冲突等完整组合由长期回归覆盖，未将单元测试描述成浏览器实测。预期的 401（登录前）、409（并发编辑）以及主动丢弃请求的网络错误不计为应用脚本错误。
