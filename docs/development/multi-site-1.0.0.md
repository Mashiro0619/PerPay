# PerPay 1.0.0 多网站开发记录

## 基线与当前状态

开发分支为 `feat/1.0.0`，从 `v0.3.2` 创建。

当前只完成配置及加密基础模块，尚未接入数据库和 HTTP 运行路径。
应用版本和数据库仍为 0.3.2 / schema 33；不能把当前分支视为已可用的多网站版本。
新增网站入口在订单、鉴权和通知隔离完成前不开放。

## 已实现的基础约束

- 网站身份与 API 凭据可用性独立；配置不包含或接收客户端自行指定的身份。
- 接单状态与通知开关是两个独立字段，不用一个 enabled 控制整个网站。
- 网站订单、收银台展示、通知投递参数均为完整配置，缺失字段不能回退默认模板。
- 默认模板只用于新建表单的独立副本，不接受密钥、身份或来源地址。
- 通知来源与返回来源分别配置，非空草稿即使通知关闭也必须合法。
- 来源语法复用现有规则，实际通知连接仍必须经过现有 DNS/IP 与传输安全检查。
- 订单时限、尾差、冷却和通知重试复用现有安全范围；待付款上限为正安全整数或 null（不限）。

## 网站密文

保留现有实例 HKDF 和 AES-256-GCM 原语，新密文以网站 ID、用途和版本构造独立 AAD。
网站 ID 不允许分隔符注入；两个业务密钥用途只能是 api_secret 或 webhook_secret。
密文换站、换用途、换版本、换实例或换主密钥必须无法通过认证。

迁移专用转换函数读取旧业务密文，保持明文与版本不变，重新生成网站绑定密文，
并在完成或异常时清理转换过程中的明文缓冲区。运行时解密不回退旧格式，default 无特殊分支。
该转换函数尚未接入 schema 34 事务，不能代替完整的数据库迁移与回滚验证。

## 后续集成顺序

1. 完成 schema 34、主密钥传入、原配置搬迁、归属约束及完整性检查；迁移在隔离测试库验证。
2. 接通鉴权、订单与事件隔离、幂等准入顺序、网站容量和收银台展示。
3. 接通网站通知密钥、策略快照与公平串行投递。
4. 拆分支付宝接入、经营收款码和 PerPay 采集策略的保存接口及表单。
5. 完成网站管理、默认模板、分站统计、向导和示例。
6. 完成 API 契约、全量测试与构建、无损升级和恢复演练、正式 1.0.0 文档。

## 不变量

经营收款码、开放平台应用与 PerPay 采集策略为实例设置。
订单有效期、尾差范围、金额冷却和待付款上限是 PerPay 网站策略，不是支付宝官方配置。

订单保存 api_client_id 归属，金额槽位仍全局共享；不同网站不能同时占用同一完整应付金额。
历史订单冷却和二维码关联不得被后续网站配置覆盖。
providerAccountKey 保持内部采集来源代次用途，不作为网站 ID，也不按网站创建采集任务。

每个可独立验证的基础单元单独提交；只在迁移及其全部读取路径就绪时启用 schema 34。
不修改本地评估记录和安全审计报告，不自动推送、合并、发布或部署。
