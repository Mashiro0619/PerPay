# PerPay 1.0.0 多网站开发记录

## 基线与当前状态

开发分支为 `feat/1.0.0`，从 `v0.3.2` 创建。

已完成配置、加密、网站事务存储和 schema 34 迁移定义，并通过隔离数据库验证。
启动入口已支持传入主密钥，严格完整性检查已支持网站数据；schema 34 尚未登记到自动迁移目录，HTTP 与运行时已支持注入网站存储，但普通启动仍未切换。
应用版本和数据库仍为 0.3.2 / schema 33；不能把当前分支视为已可用的多网站版本。
新增网站入口在订单、鉴权和通知隔离完成前不开放。

## 已实现的基础约束

- 网站身份与 API 凭据可用性独立；配置不包含或接收客户端自行指定的身份。
- 接单状态与通知开关是两个独立字段，不用一个 enabled 控制整个网站。
- 网站订单、收银台展示、通知投递参数均为完整配置，缺失字段不能回退默认模板。
- 默认模板只用于新建表单的独立副本，不接受密钥、身份或来源地址。
- 通知来源与返回来源分别配置，非空草稿即使通知关闭也必须合法。
- 来源语法复用现有规则，实际通知连接仍必须经过现有 DNS/IP 与传输安全检查。
- 订单时限、尾差、冷却和通知重试复用现有安全范围；待付款上限为正安全整数或 null（不限）。

## 网站密文

保留现有实例 HKDF 和 AES-256-GCM 原语，新密文以网站 ID、用途和版本构造独立 AAD。
网站 ID 不允许分隔符注入；两个业务密钥用途只能是 api_secret 或 webhook_secret。
密文换站、换用途、换版本、换实例或换主密钥必须无法通过认证。

迁移专用转换函数读取旧业务密文，保持明文与版本不变，重新生成网站绑定密文，
并在完成或异常时清理转换过程中的明文缓冲区。运行时解密不回退旧格式，default 无特殊分支。
schema 34 数据迁移在同一事务内检查原主密钥保护记录、转换业务密文、校验网站配置和外键；
已覆盖错误主密钥回滚后重试、历史主键不变和多网站独立密钥。自动启动升级及重启验收仍待运行时接线完成。

## 网站事务存储

网站创建使用操作 ID 去重；配置、凭据及审计在一个事务内提交。
模板版本和网站版本独立，修改网站不写入实例运行配置。
API 身份读写按 client_id 定位；网站删除保留墓碑并关闭凭据，不复用客户端 ID。
通知密钥的全局内部主键与网站内版本分离，每站仅一个有效密钥，归属与版本链纳入严格检查。
迁移 SQL 保留旧订单表、流水及历史通知引用，并删除已搬迁的实例设置字段。

## 订单服务

订单服务已增加显式网站作用域，并在事务内校验网站版本、接单状态和待付款容量。
合法幂等重放先于这些准入检查；商户订单号与幂等键按网站隔离，金额分配仍是全局。
收银台通过订单归属读取展示设置，保留历史二维码和财务快照。
该服务已在隔离迁移库运行真实下单测试；HTTP 已按验签网站作用域查询和操作，正式启动切换仍等待迁移前置条件。

## 通知处理器

已实现共享串行调度器使用的站点轮转处理器。物化、领取、有效密钥读取和重试上限按网站隔离，
领取核对配置版本及密钥指纹；在途保留原签名快照，下次重试使用当前密钥。
隔离测试通过真实订单、流水及对账事件验证站间公平、关闭恢复和轮换，不访问外部网络。
运行时在注入网站存储后使用该处理器；未启用迁移的普通启动仍使用旧装配路径。

## 独立实例设置存储

应用配置、经营收款码和采集策略已有独立校验与保存方法。采集策略可在应用尚未配置时保存；
保存任一分组不携带其他分组的密钥或网站策略，沿用设置版本、支付版本与运行时切换保护。
已验证隔离迁移库上的保存不改写网站配置、模板和业务密钥。

网站模式下的默认网站／模板回退与全局业务密钥读取已删除；旧全局快照明确拒绝在 schema 34 上读取。
实例设置 GET 与保存响应均使用纯实例 DTO，不包含网站策略、业务通知或业务密钥元数据。
界面按 site_mode 显示实例名称和图表设置，将旧通知入口及业务密钥引导到网站；向导提供网站创建入口。
OpenAPI 的旧字段仅用于尚未迁移数据库的历史回归响应，标注 deprecated；网站模式的真实响应不包含这些字段。
**仍需完成：** 正式注册 schema 34、旧测试夹具及维护工具迁移、初始化网站的完整端到端验收。不能据此宣布升级已完成。

共享调度器与网站订单服务已改用不包含业务密钥、通知策略或订单参数的纯实例快照。
网站模式下下单只从显式所属网站组装订单策略；删除迁移的 default 网站或修改模板不会影响其他网站下单或共享引擎快照。
旧实例即使从未签发 API／通知密钥，也会保留原网站与策略；全新安装仍不生成隐藏网站。

## 管理查询基础

订单列表、CSV 导出和通知列表的存储查询支持显式网站筛选；金额和历史确认时间的含义不变。
分站统计以订单归属及通知目标归属计算，只统计明确关联订单的资金异常；全局流水冲突在分站视图返回 null，不能解释为零条。
CSV 增加网站 ID 与名称，保留公式转义、单次查询快照、创建日期和最大数量限制。
通知人工重投在事务内读取目标所属网站的当前通知开关和来源，不接受调用方的全局来源代替网站授权；合法历史重放不重新解释策略。

## HTTP 与管理界面集成进度

已接入网站列表、创建、完整配置编辑、密钥动作和默认模板接口及表单；写操作使用管理员会话、同源、CSRF 和只读演示保护。
已接入实例应用、经营码和采集策略的独立 HTTP 保存接口与表单。网站模式下旧全局业务密钥与通知写入口返回 410 / site_settings_moved。
管理员测试收款需要选择网站，未决请求保留原网站、金额和操作 ID；不会因关闭对话框或断网恢复而创建新请求。
订单、通知与首页支持网站筛选，分页与缓存绑定筛选条件；订单列表及详情显示网站名称与客户端 ID。
收银台静默轮询可以更新当前网站展示，不改变订单金额和历史二维码。

首页及待办页已支持网站筛选，只纳入明确关联订单的事项。批量忽略捕获网站范围，并纳入操作幂等指纹；未归属异常和全局流水冲突仍留在全局视图。

本轮全量回归：后端 1014 通过、3 跳过，前端 1068 通过；API 生成类型检查、前后端类型检查及构建通过。

## 不变量

经营收款码、开放平台应用与 PerPay 采集策略为实例设置。
订单有效期、尾差范围、金额冷却和待付款上限是 PerPay 网站策略，不是支付宝官方配置。

订单保存 api_client_id 归属，金额槽位仍全局共享；不同网站不能同时占用同一完整应付金额。
历史订单冷却和二维码关联不得被后续网站配置覆盖。
providerAccountKey 保持内部采集来源代次用途，不作为网站 ID，也不按网站创建采集任务。

每个可独立验证的基础单元单独提交；只在迁移及其全部读取路径就绪时启用 schema 34。
不修改本地评估记录和安全审计报告，不自动推送、合并、发布或部署。
