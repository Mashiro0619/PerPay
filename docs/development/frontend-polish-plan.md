# 前端视觉与动效提升工作计划

日期：2026-10-29（北京时间）

修订：v1.1，补齐指定选型、动效归属、样板评审与原子提交边界。

状态：代码实施与计划内技术验收已完成；用户视觉评审待反馈。各项证据及适用边界见第 7 节和实施记录。

代码基线：`main` / `8dcac3d`；此前趋势统计模型与图表重构已分别提交为 `a1a1fc3`、`8dcac3d`。

## 1. 目标与范围

将 PerPay 后台打磨为 Nova 基础上的精致控制台：视觉层次清楚，同类操作反馈一致，内容切换连贯，长时间使用也保持克制。

用户最后确认的主要问题是缺少视觉质感和动效完成度。此前关于入口多、流程复杂的讨论不作为本轮导航或业务流程改造依据。保持现有页面入口、导航顺序、功能和业务规则，重点改善它们的呈现与反馈。

本轮覆盖：

- 公共外壳：侧栏、顶部栏、页面标题、内容容器及主题下的表面层次。
- 总览样板：指标卡片、趋势卡片、网站概览、待处理摘要和最近订单。
- 公共反馈：选中、悬停、按下、展开、关闭、加载、刷新、成功和错误。
- 样板稳定后推广到订单等列表、业务详情、设置和账号配置。

公开收银台、登录与初始化流程不主动改版；共享组件和样式变化仍需检查这些页面是否受影响。拖拽排序、可调整分栏、新导航体系、服务端接口与数据库改造不在本轮范围内。

## 2. 技术与设计决定

| 领域 | 本轮决定 | 使用边界 |
| --- | --- | --- |
| 组件与主题 | 保留 shadcn/ui `base-nova`、Base UI、neutral 主题 | 优先使用已有组件与变体；公共调整统一落地，避免逐页覆盖基础控件 |
| 图标 | 继续使用 Lucide | 统一同一动作的图标、位置和尺寸；不新增第二套图标库 |
| 组合动效 | 已引入 `motion@14.7.1`，使用 `motion/react` 与图形局部的 `motion/mini` | 负责选中指示、局部内容和必要的布局过渡；实施前核对 React 兼容性、CSP 与包体影响 |
| 基础反馈 | 保留 CSS、Base UI 自带过渡和 `tw-animate-css` | 按钮、焦点、基础弹层不重复叠加 Motion；组件的焦点、关闭和卸载机制继续由 Base UI 管理 |
| 路由过渡 | 先保留现有 View Transition | 不在同一内容区域叠加第二套路由动画；有充分样板证据后才按区域替换 |
| 图表 | 保留 Recharts 与 shadcn Chart | Recharts 负责图形；Motion 可负责外层局部视图，不能同时驱动同一图形 |
| 数据与状态 | 保留 TanStack Query、Table、React Router 和局部 React 状态 | 不为视觉改造迁移缓存、筛选、分页或草稿到新的 store |
| 可调整分栏 | 指定优先使用 react-resizable-panels，本轮不安装 | 仅用于用户可拖动调整比例的面板；普通页面布局继续使用 Grid／Flex |
| 拖放与排序 | 指定优先使用 dnd-kit，本轮不安装 | 明确需要列排序或模块拖放时再引入；文件拖入上传不直接构成引入理由 |
| 共享界面状态 | 指定优先使用 Zustand，本轮不安装 | 仅在复杂跨组件界面状态成立时使用；服务端缓存归 TanStack Query，筛选／分页归 URL，局部状态归 React |

“组件源码可控”用于维护必要的项目适配。新增变体应有明确用途；修改基础组件前列出使用方，避免通过全局选择器给无关页面改变密度或点击区域。

这些库是能力对应的指定选型，不是一次安装的清单。引入时说明首个使用场景、现有能力为何不足、锁定版本及兼容性、替代范围和构建增量。优先使用已有依赖；确需偏离指定选型时，在实现记录中给出原因。不得同时直接引入 Motion 与 framer-motion，也不为同一种组件、图标或状态能力再叠加同类库。对正常的传递依赖按实际重复代码和版本兼容性检查，不以依赖数量本身作为质量指标。

### 2.1 视觉基准

- 统一页面标题、分区标题、主要金额、辅助金额和说明文字的语义，再集中定义字号、字重及行高。
- 继续使用中性色与现有状态色。通过背景、边框、留白和少量阴影区分页面、卡片、浮层，避免每层都加重边框。
- 统一页面间距、卡片内边距、控件组间距及图标对齐。列表、详情、设置保留各自合适的阅读宽度。
- 保留桌面紧凑密度与手机连续分隔行。手机点击区域至少延续现有 40px 规则，不用缩小文字代替布局适配。
- 悬停、选中、键盘焦点和禁用状态应清楚且一致。选择状态与悬停反馈在视觉上可区分。
- 先在样板中确定中文、英文、金额与编号的对齐、行高和字重，再集中推广；字体选型或下载方案若需要变更，另行记录取舍。

### 2.2 动效基准

以下为样板阶段的初始参数，需在实际页面中校准，最终值集中维护。

默认模式保留完整的设计动效。“减少动态效果”仅在用户开启系统对应设置时启用，不是默认削弱动画。

| 场景 | 初始时长 | 表现与限制 |
| --- | --- | --- |
| 悬停、按下、复制反馈 | 120–160ms | 小幅透明度、颜色或图标变化；不改变按钮外部尺寸 |
| Tabs、切换组的选中指示 | 160–200ms | 平滑移动至当前项，业务选择立即生效 |
| 普通局部内容切换 | 180–240ms | 轻微淡入，可使用不超过 4–8px 的位移；不等待旧动画结束才显示结果 |
| 侧栏和展开区域 | 180–240ms | 内容与容器协调变化；连续操作可打断并转向最新状态 |
| 图表切换 | 180–240ms，按图形能力校准 | 避免旧图和新图混淆；金额文本、状态和错误立即显示真实值 |
| 减少动态效果 | 直接切换 | 关闭位移、缩放、布局补间和装饰动画，保留必要的静态反馈 |

不做逐行飞入、持续弹跳、金额滚动计数或定时刷新后重复播放整页入场。不用动画拖延请求、焦点恢复、错误展示或可操作状态。

### 2.3 动效的控制边界

| 场景 | 控制方 | 状态变化要求 |
| --- | --- | --- |
| 按钮悬停、按下、焦点 | CSS／Base UI | 命中、禁用和焦点立即生效，视觉变化不改按钮尺寸 |
| Tabs 与切换组选中指示 | Motion；Base UI 保留交互语义 | 指示器可补间，`aria-selected`／`aria-pressed` 和有效读数立即更新 |
| 普通局部内容与展开区 | Motion 或原有组件过渡，逐项择一 | 连续操作覆盖旧动画，不能出现两个有效表单或两套可操作内容 |
| Dialog、Popover、Sheet | Base UI 与现有 CSS | 不外套延迟卸载的第二套动画，不改变关闭和焦点归还顺序 |
| 路由与工作区切换 | 现有 Router／View Transition 边界 | 保留敏感路由排除规则，不扩大旧页面快照或数据保留时间 |
| 侧栏尺寸与内容区 | 样板中择定一个统一控制方 | 不同时用宽度 CSS 过渡与 Motion 布局补间驱动同一尺寸 |
| 图表图形 | Recharts | 外层容器不同时缩放图形；无合适补间时用短淡入或直接切换 |

每项动效在实现记录中写明触发条件、被改变的属性、时长、打断行为和减少动态效果下的表现。正常完成、取消、失败和重复点击都应落在明确的最终状态。

## 4. 不可被动效破坏的行为

| 边界 | 验收要求 |
| --- | --- |
| 会话与网站范围 | 保留现有导航提交前的等待机制；退出、会话失效或新网站导航提交后，立即执行原有数据清除与卸载，不用 `AnimatePresence` 延长旧业务视图生命周期，不以隐藏代替清除，也不能让晚到响应恢复旧内容 |
| 状态与请求 | 不因动画重新挂载查询、额外发起请求或重复提交；只有最新选择可生效 |
| 草稿与历史 | 未保存草稿保护、筛选、分页、滚动位置与浏览器前进／后退行为保持一致 |
| 财务操作 | 保留操作快照、operation ID、既有确认与失败恢复；“停止等待”的含义不变，不因动画结束触发业务动作 |
| 图表与金额 | 整数分和服务端汇总口径不变；文字不显示插值金额；加载、错误、空值和零值不混淆 |
| 交互与无障碍 | 离场内容不可获得焦点或点击；关闭后焦点正确归还；减少动态效果可实时生效 |
| CSP 与共享产物 | 使用生产 CSP 验证，不为动效放宽策略；后台 Motion 不进入公开收银台或 SSR 引用链；共享样式不破坏收银台 |

侧栏位置或尺寸过渡允许必要的布局计算，但应限于相关容器；其余优先使用 `transform`、`opacity`。不在整个应用根节点启用自动布局动画。

现有图表、列表和详情布局依赖尺寸测量。避免在测量容器上直接施加布局缩放；优先使用独立视觉包装层，检查 `ResizeObserver`、文字尺寸和断点切换是否互相触发。不得用刷新时间或返回数据对象作为动画 key，导致业务组件重新挂载。

## 5. 验收方式

### 5.1 静态与动态体验

使用同数据、同视口的前后对比；动画验收必须有短录屏或可重复交互，截图只证明静态状态。

视觉评审具体看四点：主次文字和数字是否协调；同类间距与对齐是否一致；背景、边框和浮层是否形成清楚层次；同类控件的反馈是否像同一套产品。关闭动画后也应保持这些改善，不用动效掩盖静态布局问题。

| 维度 | 代表场景 | 通过条件 |
| --- | --- | --- |
| 桌面与手机 | 1440px 桌面；390px 手机；320px 窄屏；侧栏展开与收起 | 无横向溢出、文字裁切、触摸目标缩小或焦点遮挡 |
| 主题与字号 | 明暗主题、默认与 200% 字号 | 层次和对比度稳定，金额和长文本可完整获取 |
| 数据状态 | 正常、稀疏、全零、空数据、加载、失败；长商品名和大金额 | 状态含义准确，反馈清楚，不通过缩字隐藏问题 |
| 连续操作 | 快速切三种图、指标和周期；连续开关侧栏或展开区 | 在途动画可打断，不排队，不回弹到旧状态 |
| 任务连续性 | 翻页后开详情再返回；编辑时切分类；后台刷新 | 保留状态和位置，不因装饰动效产生额外请求 |
| 动态偏好 | 减少动态效果初始开启、运行中开启；标签页转后台 | 装饰动画停止，最终状态正确，组件仍可正常操作 |
| 响应速度 | 缓存命中、正常请求、慢请求、失败和离线恢复 | 快请求不闪占位、不人为等待；慢请求及时反馈；失败不被退出动画遮住 |

手机截图和触摸仿真属于浏览器证据；真机或其他浏览器未验证时，明确记录，不写成已通过。

### 5.2 性能与工程检查

- 记录同一环境下改造前后的首次加载资源、后台和收银台 gzip 体积，明确 Motion 实际增加的模块与大小；发现重复引入时先消除再推广。
- 对侧栏、图表切换及普通列表各做连续操作录制，检查布局计算、帧时间和长任务。以 60Hz 下约 16.7ms 的帧预算作为诊断参考；归因于新增动效的超过 50ms 主线程长任务需修复或降级后再验收。
- 金额、状态、错误和业务可操作性立即更新，不等待装饰动画完成；加载占位与正文避免可见的额外跳动。
- 检查控制台、CSP、网络与 hydration 错误，确认公共改动未污染收银台构建。
- 复用现有行为测试，新增测试集中在动画打断、状态保留、减少动态效果、焦点与数据边界，不测试每个 CSS 类名。
- 为每个代表交互记录“操作输入 → 第一处可见反馈 → 业务结果可用”，将网络等待与动画耗时分开比较；不能把更长的装饰过渡表述为性能提升。

阶段内按改动范围执行类型检查、相关 Vitest 和 Playwright；修改公共样式或组件时同时构建后台与收银台。构建完成后再启动浏览器验收，避免运行中的夹具读到半成品。

最终执行现有 `npm run check` 和适用的浏览器矩阵。具体命令、证据摘要及失败处置记入验收记录。通过后的检查不无故重复；只有新改动、失败或未解决疑点才扩大复测。

相关入口：[界面回归](ui-verification.md)、[本地演示场景](preview-scenarios.md)、[全界面验收记录](ui-optimization-acceptance.md)。

## 6. 原子化提交要求

本计划实施时必须进行小步、原子化的本地 SSH 签名提交。每完成一个可独立验证的改动单元，检查通过后立即提交并验签，再继续下一个单元；不得将整个阶段或全部重构堆成一笔大提交。

- 一笔提交只解决一个明确问题，能够单独审查和回退。按完整行为划分，不机械地按文件、前端／测试或代码行数拆分。
- 实现、必要样式、相关测试及直接配套文档一起提交。Motion 依赖、锁文件与首个实际使用方属于同一完整单元；后续场景分别提交。
- 每个提交点必须可构建、相关检查通过，不能依赖尚未提交的文件才能运行或通过测试。验证时同时核对暂存内容与实际受测内容一致。
- 公共接口与受其影响的必要调用方保持兼容；无法独立运行的变更合并为一个完整单元，不制造中间损坏状态。
- 提交前核对 `git status`、暂存差异和 `git diff --cached --check`，按路径或改动块精确暂存，排除无关工作、临时文件、构建产物和本机验收素材。
- 每笔使用 `git commit -S`，随后执行 `git verify-commit HEAD`。提交或验签失败时先处理原因，不以失败记录继续交付，也不自行关闭签名。
- 提交说明写明具体行为；验收记录关联提交哈希、检查结果与视觉／录屏证据。提交后发现的问题使用新的原子修复提交，不擅自改写已有历史。
- 本地提交、推送和部署分别记录；本计划的原子提交要求不包含自动推送或部署。

建议拆分顺序：公共视觉规范 → Motion 基础与首个场景 → 侧栏反馈 → 趋势视图切换 → 列表反馈 → 详情过渡 → 设置反馈 → 最终验收文档。每一项可按实际耦合进一步拆分，相关检查随各笔提交完成，不等到最后统一补测。

例如“侧栏选中指示统一反馈”是一笔完整提交，可包含组件、样式和验证；“给全站加动画”不是合适的原子单元。公共规范可按字阶、表面层次、控件反馈等实际兼容边界拆分。修复公共规则引起的调用方回归应随同一笔交付，不能先留下损坏页面等后续补齐。

| 优先级 | 候选项与当前证据 | 优化价值与边界 |

| 高 | 订单预取与页面参数对齐：[导航预取](../../web/src/lib/workspace-navigation.ts) 调用 `ordersQuery` 未传入收款账号，而[订单页](../../web/src/pages/Orders.tsx)传入 URL 中的 `alipay_account_id`；[查询定义](../../web/src/api/workspace-queries.ts)将账号计入缓存 key | 带账号筛选导航时，预取与页面可能请求不同集合，产生额外等待。共享参数解析，保留网站校验、取消与会话隔离；先用网络记录复现，不先扩大预取范围 |
