# 支付宝多账号验收记录

日期：2026-10-29。范围为当前源码、本地临时数据库和浏览器测试，没有向真实支付宝发起付款或部署生产环境。

## 已实现的行为

- 收款文案统一为“收款码”，经营码为可选形式；文档说明可向订单对应账号转账，金额须一致，流水须能被对应应用查询。
- 每个支付宝账号独立保存收款码、应用身份、公钥和加密私钥。可先保存草稿；保存结果与连接检查结果分别显示，检查失败不会丢失配置。
- 应用密钥生成、导入、公钥复制及待启用换钥在账号详情完成。账号更新只重启受影响的查账任务；并发更新两个账号不会提前恢复另一个账号。
- 网站可以指定一个账号、等概率随机选择或按正整数权重选择账号。停用、未完成配置、查账异常的账号不参与新单；随机与加权在金额位置已满时尝试其余候选，指定模式不会自动换号。
- 已创建订单固定账号、二维码和金额；幂等重试返回原单。金额占用与冷却按稳定账号 ID 隔离，同账号网站共享金额空间。
- 每个账号独立查账、游标、健康状态和手动查账。全部账号暂停后，旧订单仍可打开二维码、核实付款和处理到账。
- 后台订单、支付宝流水、运行状态及试收款显示实际账号。不同账号或环境下相同流水号不会被合并；全局冲突和异常列表、统计包含全部账号。
- 首次设置为“配置支付宝账号 → 配置网站 → 试收款”。旧设置地址跳转到账号管理；旧单账号写接口返回明确的迁移提示。

## 数据升级与恢复

schema 37 将原支付宝配置迁为默认账号，已有网站固定关联该账号。保留原订单、账本身份、二维码、占用金额、业务密钥、通知签名历史与待启用密钥。未完成的旧配置保留为可修正状态。

启动和恢复会验证账号密钥及其归属。备份恢复测试使用真实 SQLite 备份，核对账号配置、当前密钥、待启用密钥、网站关联及旧订单证据。历史迁移测试保留对所有原财务字段、事件和审计记录的完整比较，并单独验证新增账号 ID。

本记录完成时，源码包版本为 `1.0.0-alpha.2`、schema 为 37；该版本原有发布契约的 schema 上限 36 保持不变，当时的源码检查仅对未发布结构设置临时例外。后续已准备 [1.0.0-rc.1](../releases/v1.0.0-rc.1.md)，新增 schema 38 修复账号删除后的历史归属，版本检查不再允许沿用旧版本的结构例外。升级和回退步骤见[维护说明](../maintenance.md#固定版本与回滚)。
