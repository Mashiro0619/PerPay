# 运行状态表

验收日期：2026-10-12（北京时间）。范围：`/admin/system` 的布局、详情入口和官方更新卡片。

## 页面结构

- 页面采用平面状态表，列为服务、状态、最近成功、运行信息及必要操作；没有外层卡片、图标底座、收款汇总卡或重复业务待办。桌面正常服务行高 56px。
- 表格展示账本采集、自动确认、业务通知、数据库和自动备份。状态使用小圆点及文字，最近成功显示北京时间且精确到秒；非零任务数、当前运行任务与数据库类型放在独立信息列。
- 异常诊断在对应服务下一行直接显示；正常服务不提供静态用途说明。备份仅在有策略、启用指引或失败记录时提供「备份详情」。
- 表格上方只放采样时间、刷新和「运行诊断」直接入口。诊断弹窗保留原始数据与复制标识，关闭后恢复按钮焦点。
- 只有收款确实受阻时才显示紧凑的暂停原因及必要配置入口。提醒统计不可用仍明确提示；实际业务待办由侧栏和待办页面承载。
- 官方更新收为页尾信息条，显示已知本地版本及检查状态；失败时不会把旧远端版本当作最新结果。等待时间按完整小时／分钟或精确秒数显示，发布日期按需展开，成功时保留安全发布链接。
- 手机把服务和状态并排，随后显示有值的时间、运行信息及操作，保留表格可访问语义。详情与更新信息自然换行。

## 保留的运行语义

收款判断继续使用服务端的配置、数据库、采集与确认就绪条件。业务待办不会把正常任务显示为故障。状态刷新失败时移除旧的正常快照，显示未知与重试。

采集持久化失败、正常采集与历史补采的区别、真实重试时间及恢复指引继续展示。备份未启用时，恢复要求、配置不一致和时钟回退仍直接显示；备份策略不代表已有可用备份。

## 验证

- 运行状态、页面可用性和采集诊断共 45 项测试通过；更新栏 22 项测试通过，包括本地版本回退、失效数据隐藏及重试时间格式。
- `npm run typecheck:admin`、`npm run build:admin`、`git diff --check` 通过。
- 本地浏览器检查 390／768／1024／1440／1920px 的明暗主题，页面内容无横向溢出；1440px 窗口下正常页面内容总高约 422px。
- 实际点击运行诊断并验证实例编号复制入口、关闭后的焦点恢复，以及备份详情展开。表格语义含五个服务行标题。
- 独立浏览器响应模拟验证了采集失败、关闭备份后的三个危险标志、提醒统计未知和刷新失败；异常无需展开，刷新失败后无旧状态表，没有页面 JavaScript 异常。320／390px 触屏下，异常和展开的版本信息无溢出。
- 重启 6192 只读演示后核对所提供的前端资源与最新构建一致，并在构建版页面重新检查布局和入口。

证据范围为本地只读合成数据及临时浏览器响应。未执行真实收款、通知投递、备份恢复或配置写入。演示中的官方更新请求按设计返回 503，因此截图保留了真实的检查失败提示。
