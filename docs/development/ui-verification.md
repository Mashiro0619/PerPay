# 界面回归

运行 `npm run build` 后，以 `npm run test:ui -- --project core` 验证核心流程，
以 `npm run test:ui:full` 执行完整页面矩阵。首次使用执行 `npx playwright install chromium`。

回归进程只绑定 127.0.0.1 的独立空闲端口，使用独立临时数据库、合成二维码和模拟健康信息，禁止外部请求。
有效订单、投递、五类对账详情及网站 ID 从本轮夹具生成，另测向导各步骤、网站设置分区和网站作用域详情；普通演示仍使用推进时钟。
私有测试时钟由父进程 IPC 控制，不增加生产控制端点。

截图、trace、构建和源码摘要、浏览器及实际视口量测写入 `.ui-audit/runs/`，不进入版本库。
axe 的未确定项需人工复核，不能计入通过；页面仿真不是 iOS Safari 真机证据。

完整审查逐页执行 axe，并把通过、失败、未确定和不适用规则分别写入 JSON。
`npm run typecheck:ui` 检查夹具、浏览器测试和 Playwright 配置；`npm run check` 包含此项。
运行结束后执行 `node scripts/summarize-ui-run.mjs .ui-audit/runs/<时间>`，生成 `EVIDENCE.md` 和 `evidence-index.json`。
每条量测带有源码 HEAD、未提交源码差异摘要、后台及收银台构建摘要和实际浏览器状态。

生产构建、`npm run check` 和浏览器审查依次运行，避免清理构建目录时读取到不完整产物。
错误页使用真实 admission 与 CSP；收银台 429／503 视觉场景通过私有 IPC 在验收进程内合成，保留真实响应 CSP。
测试重置时同时清空合成限流预算。普通演示不使用这些测试控制。
付款码是写有演示说明的合成二维码，浏览器通过仿真接触点验证布局，真实支付与外部投递仍由集成验收负责。

扩展列表矩阵对 11 种视口、两种主题、两种内容宽度和两种密度进行量测；
桌面再分别验证展开侧栏与图标轨道，共 544 组。每组先断言实际偏好及有效记录，再检查溢出和居中误差。
概览另测 68rem、76rem 容器断点前后 1px。收银台核心集包含触摸、减少动画和 200% 文本放大。
截图保存完整页面；首屏查询位置由独立的视口坐标断言验证。
每个工作进程生成新临时数据库，测试间复位时钟、限流预算及合成服务场景；业务夹具保持只读。
最终处置、签名提交和人工复核结果见 [全界面验收记录](ui-optimization-acceptance.md)。

## 详情弹窗连续阅读

分组阅读覆盖订单、通知、审计、账务异常、流水、收款关联、候选、冲突、网站概况与登录会话。通知信息先于关联订单显示，审计操作与结果集中在摘要，技术信息入口位于所属记录正文末尾，点击打开独立只读弹窗；业务核对凭据直接可见。分区间距为 1rem，分组内部间距与字段换行间距为 0.5rem，同行字段间距为 1.5rem；标签与值之间横向间距为 0.5rem，正文使用 0.875rem，标题使用 1.25rem，并随用户文字缩放。

订单的金额拆分并入订单信息，未关联提示与自然宽度的人工关联按钮同排；订单动态的事件、时间与说明优先同排换行。回归需确认长备注、编号复制、历史折叠中的全部事件和原有操作资格仍被保留。

流水的支付宝流水号、订单号、商户单号按内容自然宽度排列，环境标记紧跟交易摘要标题。单份查账记录省去外框与重复可见标题，保留可访问的来源标题、状态、完整内部编号、保存时间和操作入口；多份来源仍有清楚的可见边界。复制、缺失编号占位、当前关联、已撤销历史及 source／match 锚点需按所属记录分别核对。

技术信息回归需在打开、滚动和关闭子弹窗前后，比较父详情的 DOM 实例、宽高、地址与正文滚动位置；至少一个场景从非零滚动位置开始。标题、顶部关闭按钮和底部关闭区固定在子窗口的非滚动区域，正文只有一层纵向滚动，长编号与原始数据换行展示。打开时焦点进入技术信息标题；Escape、顶部关闭与底部关闭只关闭子弹窗，并将焦点恢复到原入口，父详情继续保留。小于 768px 时验证全屏阅读布局，短视口和 200% 字号仍可读取、复制和关闭；这些行为不提交业务写入。

订单、通知、流水详情将原分类的内容连续展示在同一正文中，所有分区同时挂载。回归应确认详情没有 `tablist` 或 `tabpanel`、正文只有一个纵向滚动区，且每份证据仍位于所属记录。设置与列表的横向分类继续保留键盘切换回归。

旧详情地址中的 `section` 参数定位同页分区，hash 锚点优先定位对应记录；这些检查应直接打开旧地址或激活实际关联链接，先验证目标可见和焦点，再进行其他滚动，避免测试主动滚动掩盖定位失败。普通滚动不改写 URL 或历史。复制与金额断言按分区、记录 ID 和字段限定，不能从全页任选一个同值元素。

`detail-record-layout.spec.ts` 补充四类主要详情的共用矩阵，覆盖 320/390/768/1440px、明暗主题、短视口和 200% 字号。共享量测检查字段实际宽度与换行位置、阅读顺序、长值完整性、独立技术弹窗与父详情保持、单滚动区域，原有财务来源、复制、草稿、焦点恢复与操作资格回归继续保留。读取检查验证订单通知随主订单首次加载，通知的投递尝试仅在投递主记录成功后首次加载，滚动和缩放不重复请求；主记录失败时不发起投递尝试查询，错误与重试保持可见。原位折叠方案的历史截图和通过数量不代替当前独立弹窗与流水布局验证。
