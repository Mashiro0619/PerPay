# 界面回归

运行 `npm run build` 后，以 `npm run test:ui -- --project core` 验证核心流程，
以 `npm run test:ui:full` 执行完整页面矩阵。首次使用执行 `npx playwright install chromium`。

回归进程只绑定 127.0.0.1 的独立空闲端口，使用独立临时数据库、合成二维码和模拟健康信息，禁止外部请求。
有效订单、投递、五类对账详情及网站 ID 从本轮夹具生成，另测向导各步骤、网站设置分区和网站作用域详情；普通演示仍使用推进时钟。
私有测试时钟由父进程 IPC 控制，不增加生产控制端点。

截图、trace、构建和源码摘要、浏览器及实际视口量测写入 `.ui-audit/runs/`，不进入版本库。
axe 的未确定项需人工复核，不能计入通过；页面仿真不是 iOS Safari 真机证据。

完整审查逐页执行 axe，并把通过、失败、未确定和不适用规则分别写入 JSON。
`npm run typecheck:ui` 检查夹具、浏览器测试和 Playwright 配置；`npm run check` 包含此项。
运行结束后执行 `node scripts/summarize-ui-run.mjs .ui-audit/runs/<时间>`，生成 `EVIDENCE.md` 和 `evidence-index.json`。
每条量测带有源码 HEAD、未提交源码差异摘要、后台及收银台构建摘要和实际浏览器状态。

生产构建、`npm run check` 和浏览器审查依次运行，避免清理构建目录时读取到不完整产物。
错误页使用真实 admission 与 CSP；收银台 429／503 视觉场景通过私有 IPC 在验收进程内合成，保留真实响应 CSP。
测试重置时同时清空合成限流预算。普通演示不使用这些测试控制。
付款码是写有演示说明的合成二维码，浏览器通过仿真接触点验证布局，真实支付与外部投递仍由集成验收负责。

扩展列表矩阵对 11 种视口、两种主题、两种内容宽度和两种密度进行量测；
桌面再分别验证展开侧栏与图标轨道，共 544 组。每组先断言实际偏好及有效记录，再检查溢出和居中误差。
概览另测 68rem、76rem 容器断点前后 1px。收银台核心集包含触摸、减少动画和 200% 文本放大。
截图保存完整页面；首屏查询位置由独立的视口坐标断言验证。
每个工作进程生成新临时数据库，测试间复位时钟、限流预算及合成服务场景；业务夹具保持只读。
最终处置、签名提交和人工复核结果见 [全界面验收记录](ui-optimization-acceptance.md)。

旧详情页面的回归用例已迁移到统一弹层，覆盖 `detail-reading`、`exception-reading`、`frontend-polish`、`mobile-button-scale`、`polish-content-width`、`source-provenance` 与 `unified-reconciliation` 七份规格，共 45 个用例。它们继续核对来源、财务身份、失败重试、分页、草稿、键盘、触控和完整字段；地址检查同时验证父页与编码后的目标，技术信息在当前弹层内展开。
