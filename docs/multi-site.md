# 多业务网站接入

PerPay 支持多个自有业务网站与多个支付宝收款账号。本文说明当前源码的配置方式；已发布版本的能力及升级边界见对应发布说明。

每个业务网站分别管理 API 密钥、通知密钥、订单权限和业务配置；每笔新订单按该网站的规则选择支付宝账号，收款进入选中的实际账户。

## 配置归属

| 实例共用 | 每站独立 |
| --- | --- |
| 支付宝账号列表；每个账号独立保存 App ID、应用私钥、支付宝公钥和收款码，连接正式网关 | 不可变客户端 ID、API 与通知密钥、收款账号及分配方式 |
| 收款码及其历史版本 | 接单开关、收银台有效期、加价金额、冷却、待付款上限 |
| 常规／活跃／最小查账间隔、查账延迟、超时、有效时限 | 通知开关、通知 origin、返回 origin、超时及重试策略 |
| 管理员安全、备份、后台名称、图表和收银台 token 策略 | 收银台名称、帮助链接、商品名展示 |

查账间隔、查账延迟以及收银台有效期、加价金额、冷却均为 PerPay 自定义策略，不是支付宝官方应用参数。应用和收款码在对应账号内保存；查账策略仍在实例内统一设置。

每个收款账号都须使用支付宝平台状态为“已上线”、具备对应账户账务明细查询权限的应用。“开发中”应用不能查账，PerPay 不提供沙箱接入。

## 创建与接入

1. 管理员从“全局管理 → 业务网站”进入，点击“创建业务网站”并填写名称、选择收款账号，策略沿用“默认模板”；需要调整时先编辑默认模板。可以先不签发任何密钥。
2. 打开该网站，复制客户端 ID，显式生成 API 密钥，配置到对应网站后端。签名协议不变，只把签名材料和 `X-PerPay-Client-Id` 中的网站 ID 改为该站 ID。不要将 ID 写入业务下单 JSON 来选择归属。
3. 如需通知，先生成该站通知密钥，配置一个精确 HTTPS `notification_origin` 并开启通知；下单 `notify_url` 必须属于该来源。需要返回链接则另行配置 `return_origin`；两者可不同，也不能互相替代。
4. 等待实例查账与确认就绪；管理员测试收款必须选择网站，会创建真实订单并遵守其接单、容量及所选账号的金额限制。随后验证本站下单、查询、验签通知和业务履约。

示例客户端必须填写 `PERPAY_CLIENT_ID`。多份网站示例使用不同的密钥、回调地址、端口和本地数据目录，详见[示例说明](../examples/node-client/README.md)。

## 网站收款账号

网站的 `configuration.collection` 包含 `mode` 和 `accounts`：

```json
{"mode":"WEIGHTED","accounts":[{"account_id":"account-a","weight":3},{"account_id":"account-b","weight":1}]}
```

- `FIXED`：只选择一个账号；不可用时明确失败，不自动换号。
- `RANDOM`：在所选且可用的账号中等概率随机选择。
- `WEIGHTED`：按正整数权重随机选择，默认权重为 1；3:1 表示长期期望比例 75%:25%，不是逐笔配额。

账号配置未完成、暂停或查账异常时不参与新单分配；随机和加权遇到金额空间已满会尝试其余候选。订单成功创建后固定账号、二维码与金额，幂等重试返回原订单。修改网站规则、收款码或暂停账号只影响新单，旧单继续查账。只有未被网站、订单和历史流水使用的账号允许删除。删除后清除当前密钥并隐藏该账号，保留删除标记及不可变的历史身份、收款码和审计关联。正式账号不允许重复 App ID，一条配置应对应一个实际支付宝收款账户。

旧库升级将原支付宝配置迁为默认账号，已有网站固定绑定它，保留历史订单、账本身份、二维码、金额占用和待启用密钥。旧单账号写接口返回 `410 / alipay_settings_moved`。升级前请保留备份和主密钥，不能用旧版本直接打开升级后的数据库。

旧沙箱账号及其来源身份保留为只读历史，停止新接入、换钥和查账；不会自动改成正式账号或并入正式流水。需另行添加使用已上线应用的正式账号，再调整网站的新订单分配。

## 订单归属与金额

- `order_id` 是全局唯一 PerPay 订单 ID，`api_client_id` 是所属网站，`merchant_order_no` 是网站自己的订单号。
- 网站 A 无法查询、关闭或读取网站 B 的订单和事件；相同商户订单号、幂等键、nonce 可分别用于两个网站。不存在未知网站回退到 `default` 的行为。
- 金额占用与冷却按**稳定的收款账号 ID**隔离。同账号下的网站共享完整应付金额空间，不同账号可同时使用相同金额；选择最小可用加价金额。前一笔订单记录的冷却期限不会被另一站较短设置覆盖；网站上限不代表预留金额容量。
- 支付宝流水没有 PerPay 网站标识，仍按既有金额、时间和安全规则匹配。不能唯一确认归属时保留异常供核对，不猜站点。
- 新订单记录策略快照及原收款码关联。修改网站展示可影响旧收银台，但不会修改旧订单金额、有效期、冷却或二维码关联。
- 合法幂等重放优先于新单准入。暂停、改来源或额度已满不重新解释已成功创建的历史请求。

## 生命周期与通知

- **暂停接单**：只禁止新订单。旧单查询、关闭、付款、手动核实、对账及通知继续。API 密钥泄露必须轮换，暂停不是吊销密钥。
- **关闭通知**：不再领取该站后续投递；在途请求按已捕获配置完成。保留事件和任务，恢复后继续原状态，不自动复活死信。
- **更改来源**：旧返回链接不变；后续通知尝试和重新发送按当前通知来源校验，不允许的旧目标明确失败，不自动改发。
- **轮换密钥**：API 旧密钥立即失去鉴权资格。通知在途请求保留旧签名快照，下一次投递使用当前密钥；接收端是否短暂兼容旧密钥须结合泄露风险判断。轮换不重启共享查账任务。
- **删除**：仅无历史订单、事件和通知的网站允许删除，保留不可复用身份墓碑（保留已删除的客户端 ID，避免再次分配）及审计。
- **默认模板**：只影响以后创建网站的预填值，不继承、不批量覆盖已有网站，不包含客户端 ID、密钥或来源。

每个支付宝账号独立查账并保存游标和健康状态；同账号的多个收银台核实请求合并，不绕过最小间隔、失败退避、限流或分页续采。通知在可执行站点之间轮转并串行发送，一个站的网络超时仍会影响其他站的等待时间。

## 管理接口与查询

| 接口 | 用途 |
| --- | --- |
| `GET/POST /api/admin/v1/sites` | 列表与创建；创建包含 UUID `operation_id` 和完整 `configuration` |
| `GET/PUT/DELETE /api/admin/v1/sites/:clientId` | 读取、完整更新、删除；写入携带网站 `revision` |
| `POST .../sites/:clientId/secrets/{api_secret,webhook_secret}/actions/rotate` | 生成或轮换；携带网站 `revision` |
| `POST .../sites/:clientId/secrets/{api_secret,webhook_secret}/actions/view` | 显式查看；空 JSON `{}` |
| `GET/PUT /api/admin/v1/settings/site-defaults` | 模板与独立模板 `revision` |
| `GET/POST /api/admin/v1/alipay-accounts`、`GET/PUT/DELETE .../:accountId` | 管理支付宝账号；账号写入携带账号 `revision` |
| `POST .../alipay-accounts/:accountId/check` | 检查账号已保存的连接配置 |
| `PUT /api/admin/v1/settings/collection-policy` | 保存共用查账策略；携带实例 `revision` |

完整请求与响应字段以 [OpenAPI](../openapi.yaml) 为准。管理员写操作沿用会话、同源、CSRF、请求体及只读演示限制。网站与模板表单将服务端字段错误显示在对应输入框旁，保存失败保留草稿。冲突后读取当前配置再确认，不自动排队重放写操作。

管理员页面分为两级：一级 `/admin/` 汇总全部网站，二级 `/admin/sites/:clientId` 绑定一个网站的概览、订单、通知、待处理和设置，不再使用每页网站筛选器。全局管理 API 仍支持 `api_client_id` 筛选；通知列表、独立详情和订单内通知记录均显示所属网站名称及客户端 ID，名称随网站更名更新，不改写投递证据。管理端按商户订单号查询必须指定网站。未匹配流水、全局或无法归属的冲突只留在全局视图。分站确认金额不是独立余额或结算账户。
一级首页的统计始终汇总全部网站；二级“当前待付款”和“待处理”卡片的数量及跳转保持本站范围。`GET /api/admin/v1/work-items/summary` 接受可选 `api_client_id`，返回 `{ data: { total } }`，按待处理列表相同的 ACTIVE 规则统计全部提醒，不受首页四条预览、日期或分页限制；已忽略、已处理及被重新发送替代的旧通知提醒不计入。汇总读取失败显示未知及错误，不使用全局数或零替代；管理员系统状态中的待处理总数仍保持全局口径。

业务 `/api/v1/system/status` 只返回本站 `status`、`code`、`client_id`、`accepting_orders` 和 `notifications_enabled`。`/healthz`、`/readyz` 仍反映实例和收款引擎，单站暂停或达到自身上限不会让整个实例不可用。

## 从 0.3.2 升级

旧网站无损迁移为普通网站 `default`，保留已有密钥、订单、幂等命名空间、nonce 和通知引用；从未签发的密钥不补发。新装不会创建隐藏的 `default`。

必须先用旧构建完成备份并单独保管主密钥，再执行 `docker compose stop app backup`；维护工具与数据库版本匹配。schema 34 事务需要主密钥验证和业务密文重加密；回退必须恢复升级前备份，不可直接用 0.3.2 打开新库。详见 [1.0.0-alpha.1 升级与破坏性变更](releases/v1.0.0-alpha.1.md)。

## 管理接口的网站范围

同一管理员会话可使用全局 `/api/admin/v1/orders`，也可使用网站路径
`/api/admin/v1/sites/{clientId}/orders`；后者的身份只来自路径，正文和查询均不得再传 `api_client_id`。
订单详情、导出、通知及尝试、待处理、测试收款和订单财务操作沿用相同结构，完整路径见 OpenAPI。
本站路径中的其他网站资源返回 404；涉及账本冲突或其他网站收款证据的新财务操作返回
`409 site_scope_conflict`，须在对账（全部网站）处理。合法历史操作的指纹和重试结果保持不变。

`GET /api/admin/v1/sites/overview?range=30&limit=20&q=网站名称` 分页批量返回网站概览：
`confirmed_count` 与 `confirmed_amount_cents` 是选定北京时间区间内的确认订单指标；
`pending_orders` 和 `work_items` 是当前状态指标。网站游标绑定搜索和时间范围，不可跨条件复用。
全局总量取全局概览，不累加当前分页的网站行。

示例（继续使用现有会话和 CSRF 保护，不使用商户 HMAC）：

```http
GET /api/admin/v1/sites/site_xxx/orders?payment_status=UNPAID
GET /api/admin/v1/sites/site_xxx/orders/{orderId}
GET /api/admin/v1/sites/site_xxx/webhooks/deliveries/{deliveryId}/attempts
POST /api/admin/v1/sites/site_xxx/reconciliation/settlements/manual
Content-Type: application/json

{"financial_operation_id":"原操作 UUID","order_id":"本站订单 UUID","ledger_entry_id":"共享流水 UUID","reason":"核实依据"}
```

## 创建网站

管理页面只填写网站名称，其余参数复制当前加载的默认模板；通知关闭、来源留空且不自动生成密钥。模板读取失败不能创建。创建后进入本站概览，按需调整设置；结果未知时重试原请求，不自动创建第二个网站。API 仍接受完整配置，未改变接口契约。

## 两级后台与设置分组

使用同一个管理员登录。网站列表和一级各网站汇总提供“进入后台”；顶部切换器直接选择网站或返回“全部网站”，不提供网站搜索。跨网站切换进入目标网站概览。系统设置、运行状态和对账只在一级展示；二级只呈现已归属本站订单的待处理，不把未归属冲突算成本站零冲突。

二级设置地址为 `/admin/sites/:clientId/settings/{basic,orders,integration,display}`，分别是基本信息、订单设置、接入与通知、收银台展示。各组保留加载时的完整配置快照和网站版本，只修改当前分组；版本冲突保留草稿，不覆盖别组的新配置。默认模板在一级网站管理入口，通过标签页编辑一份草稿，统一保存。普通参数直接保存；暂停、关闭通知、来源变更、轮换和删除仍确认影响。通知重试参数默认收起，有错误时自动展开并定位。

旧全局页面的 `?api_client_id=...` 会转换到二级路径，保留其他筛选并清除分页游标。二级详情、返回列表、导出和财务操作固定本站；共享流水冲突明确引导到一级处理。一级商户订单号查询和测试收款要选择网站，二级固定当前网站。切换不会自动重放写操作；待核实的测试请求仍属于原网站，完成后才可创建目标网站的新请求。
