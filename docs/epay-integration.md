# 易支付 V1 / V2 接入指南

对于已集成易支付（彩虹易支付）协议插件的系统（如商城、论坛、New API 等），可直接在插件中配置 PerPay 提供的网关地址、商户 PID 与密钥完成收款，无需修改业务代码。

> 相关文档：[文档目录](README.md) · [支付宝配置指南](alipay-setup.md) · [原生 API 快速接入](integration-quickstart.md) · [Node.js 示例](../examples/node-client/README.md)

---

## 1. 插件配置步骤

1. **绑定收款账号**：确认目标业务网站已配置可用的支付宝收款账号与收款码。
2. **配置来源与开关**：进入 **业务网站 → 网站设置 → 接入与通知**，填写 **通知来源**（仅填协议与域名，如 `https://shop.example.com`，不含路径）并开启通知；若需支付完成后跳转回商户页，同步填写 **返回来源**。
3. **获取协议凭据**：在同一页面的 **接入助手** 中选择插件对应协议（**V1** 或 **V2**），复制网关地址与商户 PID，并点击凭据旁的 **查看** 获取密钥（明文弹窗最长展示 60 秒）。
4. **填写插件并实付验证**：按下表填入支付插件，发起一笔小额实付订单，验证收银台、异步回调与同步返回。

| 插件常见配置项 | 易支付 V1（MD5） | 易支付 V2（RSA） |
| --- | --- | --- |
| 网关 / 接口地址 | `https://你的PerPay域名/`（末尾带 `/`） | 同左 |
| 商户 ID / PID | 网站固定数字 PID | 同左 |
| 商户密钥 / 商户私钥 | V1 商户密钥（用于签名与验签） | V2 商户私钥（用于签名发往 PerPay 的请求） |
| 平台公钥 | 无需配置 | V2 平台公钥（用于验签 PerPay 响应与回调） |

**配置注意事项**：

- 新建网站默认启用 V1 / V2 并自动生成凭据；更换原生 API 的客户端 ID 不会改变商户 PID。
- 修改协议开关后须先保存配置，再管理或轮换密钥。
- 关闭某一协议的接单开关仅拦截新下单，历史订单的查单、通知与同步返回不受影响。

## 2. 接口路径与参数参考

POST 请求均使用 UTF-8 编码的 `application/x-www-form-urlencoded` 表单。页面下单成功返回 `302` 跳转至 PerPay 收银台；API 接口返回 HTTP `200` 与 JSON（V1 成功 `code=1`，V2 成功 `code=0`，失败均为 `code=-1` 并附 `msg`）。

### 接口列表

| 功能 | V1 | V2 |
| --- | --- | --- |
| 页面下单（跳转收银台） | `GET/POST /submit.php` | `GET/POST /api/pay/submit` |
| API 下单（返回收银台链接） | `POST /mapi.php`（字段 `payurl`） | `POST /api/pay/create`（字段 `pay_info`，`pay_type=jump`） |
| 单笔查询 | `GET/POST /api.php?act=order` | `POST /api/pay/query` |
| 商户信息 | `GET/POST /api.php?act=query` | `POST /api/merchant/info` |
| 订单列表 | `GET/POST /api.php?act=orders` | `POST /api/merchant/orders` |

直收模式下商户余额固定返回 `0.00`；退款、关闭、代付、结算等接口返回不支持。

### 下单参数

| 参数 | 说明 |
| --- | --- |
| `pid` | 固定商户 PID（字符串） |
| `out_trade_no` | 商户订单号（1–64 位字母或数字开头，可含 `._-`） |
| `name` | 商品名称（最长保留 127 个 UTF-8 字节，按完整字符截断） |
| `money` | 商品原价（单位元，最多两位小数，如 `10.00`） |
| `notify_url` | 必填，完整 HTTPS 异步通知地址（域名须匹配「通知来源」） |
| `return_url` | V1 页面下单必填，其余方式可选（域名须匹配「返回来源」） |
| `type` | API 下单必填 `alipay`；页面下单可省略 |
| `method` | V2 API 下单必填 `web` 或 `jump` |
| `param` | 可选透传参数（最长 4096 UTF-8 字节，不含控制字符），随通知原样返回 |
| `timestamp` | V2 必填，当前 Unix 秒时间戳（允许 ±300 秒偏差） |
| `sign` / `sign_type` | V1 为 `MD5`，V2 为 `RSA` |

> **幂等规则**：同一网站重复提交相同的 `out_trade_no` 及完全一致的订单载荷时，返回原订单（V2 重试须更新 `timestamp` 并重新签名）。同单号但金额或业务参数变更将返回冲突错误；请求超时时应先查单再决定是否重试。

### 查询参数与签名规则

- **V1 查询**：公共参数为 `pid`、`key`、`act`；单笔查单传 `trade_no` 或 `out_trade_no`；订单列表传 `page`（从 `1` 开始）、`limit`（默认 `20`，最大 `50`）及可选 `status=0|1`。
- **V2 查询**：公共参数为 `pid`、`timestamp`、`sign`、`sign_type`（须用商户私钥单独签名，不得复用下单签名）；单笔查单传 `trade_no` 或 `out_trade_no`；订单列表传 `offset`（从 `0` 开始）、`limit`（默认 `20`，最大 `50`）及可选 `status=0|1`。
- **支付状态**：`status=1` 表示收款已确认，`status=0` 表示未确认。
- **签名计算**：
  1. 对表单执行一次 URL 解码，按参数名 UTF-8 字节序升序排列，拼接为 `key=value&...`（签名原文的值不做二次 URL 编码）。
  2. **V1（MD5）**：排除 `sign`、`sign_type` 与空字符串 `""`（保留 `"0"` 与纯空格），末尾直接拼接商户密钥后计算小写 MD5。
  3. **V2（RSA）**：排除 `sign`、`sign_type`、空值与纯空白值（保留 `"0"`），使用 RSA-SHA256（PKCS#1 v1.5，≥2048 位）签名并 Base64 编码；验签响应时跳过数组和对象字段（如列表响应的 `data`）。
  4. 发送 HTTP 表单时再进行 URL 编码（字面量 `+` 编码为 `%2B`）；下单仅接受易支付 V1/V2 标准字段，禁止同名重复字段和数组参数。除 `notify_url` 与 `return_url` 的查询串（`?a=1&b=2`）外，参数值不得包含字面量 `&`（子查询参数值中同样不得含解码后的 `&`，且不得使用易支付保留字段名）。

## 3. 付款通知与同步返回

1. **异步通知（`notify_url`）**：收款确认后，PerPay 向 `notify_url` 发起 `GET` 请求，携带 `pid`、`trade_no`、`out_trade_no`、`type=alipay`、`trade_status=TRADE_SUCCESS`、`name`、`money`、可选 `param` 与签名（V2 由平台私钥签名并附带 `timestamp`）。
2. **`money` 口径**：对外返回与回调中的 `money` 始终为商品原价，不含 PerPay 为区分订单增加的小额加价（例如商品原价 `10.00` 元、应付 `10.03` 元，回调中 `money` 仍为 `10.00`）。
3. **成功回执**：接收端须按「验签 → 核对 PID、单号与金额 → 数据库幂等履约」顺序处理，持久化成功后返回 **HTTP `2xx` 且正文为纯文本 `success`**。其他响应将触发按站点策略的自动退避重试（详见 [回调通知重试规则](../USAGE.md#5-回调通知)）。
4. **同步返回（`return_url`）**：收款已确认时，付款人点击「返回商家」将附加已签名的成功参数跳转；未确认、关闭或过期则跳转原地址。同步返回与异步通知应共用同一订单履约锁，防止重复发货。
5. **收款撤销处理**：若后台撤销了原收款确认，该笔易支付旧成功通知立即终止且禁止重发；后续重新确认收款时会生成新通知。

> **说明**：`notify_url` 与 `return_url` 允许携带一个或多个固定查询参数（如 `?instance_id=1&source=epay`），查询参数名不能含点号 `.`、不能重复且不能与易支付保留字段重名（`return_url` 允许携带与当前订单一致的 `out_trade_no`，回跳时自动复用不重复拼接），所有参数一并参与回调签名。
