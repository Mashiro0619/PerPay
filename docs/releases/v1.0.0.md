# PerPay 1.0.0

PerPay 1.0 提供完整的自托管支付宝收款流程：业务网站创建订单，顾客按收银台金额付款，PerPay 自动查账确认并发送通知。一个后台可管理多个业务网站和支付宝账号，支持原生 API 与易支付 V1/V2。以下汇总 RC4 以来的功能、修复和升级步骤。

## 1.0 的主要能力

| 能力 | 使用方式 |
| --- | --- |
| 多网站、多账号 | 网站独立管理密钥、订单与通知，按指定、随机或权重分配收款账号。 |
| 查账与人工复核 | 通过支付宝官方 SDK 查询账务明细；按账号、金额和时间确认订单，异常付款保留流水和处理记录。 |
| 三种接入协议 | 接入助手给出原生 API、易支付 V1/V2 的服务地址、客户端 ID／PID 和密钥；可用 Node Demo 完成下单、付款和通知检查。 |
| 日常管理 | 查看趋势、筛选订单、导出 CSV、重发通知、追溯审计记录。 |
| 自托管维护 | 自动备份、异地保存与恢复工具，支持固定版本升级和回滚。 |

## RC4 以来的改进

### 配置与业务接入

- 首次创建管理员默认要求初始化令牌，从最新启动日志读取后填写。已创建管理员的实例照常登录；显式配置 `PERPAY_SETUP_TOKEN_ENABLED=false` 仍然有效。
- 后台统一按“支付宝账号 → 业务网站 → 试收款”完成配置，逐项列出还没填的应用信息、密钥和收款码。连接检查后，可继续接入所选业务网站，完成付款和通知检查。旧单账号向导和全局密钥设置入口跳转到对应的账号或网站；创建账号后没收到响应时，用原请求重试会找到同一账号。
- 支付宝账号禁止重复配置同一收款码，修改协议、域名大小写或附带参数也会识别为同一码。更换应用请编辑原账号；已有重复配置按[网站收款账号说明](https://github.com/Mashiro0619/PerPay/blob/v1.0.0/docs/multi-site.md#网站收款账号)清理。
- 新网站创建后进入接入配置；没有可用收款账号时，可直接前往配置账号。密钥在独立弹窗中查看和复制，页面按现有密钥的状态提供生成或更换操作。
- 切换网站接入设置的分组时，保留尚未保存的内容。删除没有业务记录的网站后，清除其草稿和侧栏选择并返回列表；取消删除或删除失败时保留草稿。正在保存易支付配置时，不能同时删除该网站。
- 账号、网站、默认模板、管理员白名单及易支付设置等待超过 20 秒后可以关闭窗口。写入超时、响应丢失或遇到版本冲突时，保留输入和原版本，可重新读取配置、核对结果后继续。
- 密钥操作超时后可以关闭窗口并核对当前密钥；轮换不会自动重试，迟到响应不会覆盖后来打开的界面。修复未完成账号配置时连续更换密钥失败；密码修改结果不明确时提供重新登录入口。
- 服务器明确拒绝创建测试订单时，可修改网站和金额；没有拿到明确结果时，保留原请求供核查和重试。

### 收款与订单处理

- 正常查账已覆盖需要核对的时间段，而且结果仍在有效期内时，即使正在分段补查历史记录，也继续接受新订单。历史补查不会延长正常查账结果的有效期。
- 同一账号、同一环境更换 App ID 后，可核对新应用查到的迟付款，并人工关联到旧订单；仍会阻止同一笔付款被同时确认给多笔订单。
- 争议订单可在核对可用收入流水、填写理由后重新确认，保留原关联、撤销和通知历史。每次确认时保存当时的金额，历史统计读取这份金额，后来重新确认不会改写过去日期的数据。
- 撤销收款确认后，不再重发原来的易支付成功通知。手动重发通知会打开这次发送的记录，可在原记录和最新结果间跳转，投递历史说明当次失败类型；登记外部退款后，可逐条忽略已核对的争议提醒。
- 订单区分待付款、过期未付款和关闭未付款，保留商户订单号及独立退款标记；同名收款账号也能区分。CSV 可按创建日期范围导出，并标明收款账号和金额单位。

### 后台与收银台

- 后台用“查看范围”切换网站，用“网站管理”维护网站；单站设置标明当前网站归属。页名统一显示一次，桌面页面操作放到标题旁，未知地址的正文和标签页标题一致。
- 手机总览先显示待处理和最近订单，网站概览默认显示四项，可展开查看全部；每日趋势完整展示所选日期范围，每日数据可独立滚动。小额网站的金额横条保持可见，暂停接单网站的首笔收款引导给出相应操作。
- 趋势汇总金额随宽度调整字号并完整保留小数位，今日指标的统计口径可点击查看。可跳转的指标卡片支持整卡点击并显示跳转图标；桌面短数值减少额外的键盘停靠点，窄屏和长数值保留滚动焦点。
- 首次打开总览时，收款趋势的标题、筛选、统计和下方内容保持原位，仅绘图区按需加载。测试收款界面在打开时加载，加载期间可以取消并再次打开，减少后台初次进入需要下载的代码。
- 列表日期筛选集中显示范围和北京时间，显示列名称按单列排列，导出和显示操作归到筛选条件之后。搜索提示缩短为“输入关键词，回车搜索”，窄屏使用“关键词”；清空搜索后不再残留旧关键词，复制提示对应实际复制的内容。
- 桌面表格让主信息列利用剩余宽度，金额、状态等列保持紧凑，并为较多列保留横向滚动。手机订单摘要去掉重复的商户订单号标签；筛选和列表显示抽屉固定底部操作区，统一底栏背景，并为顶部控件的键盘焦点留足空间。
- 支付宝账号配置完成后，收款状态和最近连接检查集中到“使用情况”；缺少配置或启用后无法收款时仍显示处理提示。已配置收款码显示摘要和更换入口，旧版测试账号可直接查看已保存的收款码，手机上的长链接自动换行。
- 网站配置分类在窄屏使用选择器，冲突核对操作纵向排列，单行密钥使用紧凑查看窗口。窄屏配置向导显示当前步骤，设置卡片的标题与操作分行，并收紧设置摘要和手机登录页的留白。
- 撤销登录会话成功后立即关闭确认窗口并显示结果，会话列表在后台刷新。
- 收银台将查询付款状态与扫码操作放在同一栏，桌面状态放进订单资料标题区；放大二维码在大字号和短横屏下为码图留足空间。手机补齐从相册扫码的步骤，本机通过 HTTP 试用易支付收银台时可返回商家页面。
- 收银台单独打包所需样式，付款页面下载的 CSS 从约 237 kB 减少到 59 kB，继续与后台共用主题和基础控件。
- 重整 README、部署、接入、维护和开发文档，补齐配置步骤与错误处理，更新界面截图。

### 长期运行与备份

- 升级服务端 HTTP 框架 Hono 至 4.13.18、Node.js 适配器 `@hono/node-server` 至 2.1.8，修复上游路由匹配和请求路径处理相关安全问题。
- 一次查账成功结束、且结果只有一页时，其中的空结果和重复流水副本保留 7 天，后台每小时分批清理；首次入账的来源记录、异常与各账号最近的查账记录继续保留。
- 查账和对账正常且结果没有变化，或这一轮没有待发送通知时，将记录按小时汇总，减少日志增长。
- 普通查询和匿名错误请求按分钟汇总。未关联核心审计的查询和匿名请求每分钟最多接收 600 条待写入记录、最多保留 20,000 条；审计采集状态显示超出预算的数量、最近时间和原因，付款与配置等核心审计继续逐条保留。
- 临时空间足够时，备份会去掉副本中已经空出来的数据库页，缩小文件（SQLite 压实）；空间不足以压实时，仍保留完整快照。只有通过最终校验的文件才会成为可用备份。
- 新增查看数据库空间占用和停服压实的工具。程序运行时要求的最低可用磁盘空间设为 64 MiB，备份另外检查目标目录的空间，避免仅因数据库较大就提前停止收款。
- 等待下一次备份时，进程最多间隔 30 秒重新读取策略，并调整执行计划。备份或校验失败时，后续清理出错不会把原定重试时间向后推；如果只有清理出错，备份仍按正常周期运行。
- 运行状态复用未改变备份的校验结果，应用启动及每小时在后台执行完整校验。概览显示最近内容校验时间，新副本或文件变化会立即重新校验。成功的备份健康检查只返回状态，减少长期保留的审计记录；检查失败仍记录原因和结果。
- 备份页面集中显示当前任务、最近一份备份和下次执行时间；未启用且没有历史文件时，摘要集中显示任务和策略。查账诊断和审计详情先说明实际结果及失败原因。
- Compose 三个服务共用 `x-perpay-image`，发布附件固定对应镜像；恢复指南覆盖新服务器导入备份与原主密钥。

## 升级与恢复

本版的数据库结构版本（schema）为 **44**，兼容范围为 **24—44**。从 RC4 的结构版本 42 升级会依次执行迁移 43、44，增加查账历史清理所需的状态和索引，并允许争议订单重新确认收款；已经使用结构版本 44 的开发版本无需再次迁移数据库。

1. 使用原版本完成备份，单独保存原主密钥（`PERPAY_MASTER_KEY` 或 secrets 卷中的 `master-key`）。
2. 若存在同一付款跨应用重复确认，先按[历史重复收款关联检查](https://github.com/Mashiro0619/PerPay/blob/v1.0.0/docs/maintenance.md#历史重复收款关联的升级检查)处理并重新备份。
3. 停止应用和自动备份：`docker compose stop app backup`。
4. 将 `x-perpay-image` 改为 `ghcr.io/mashiro0619/perpay:1.0.0`。旧 Compose 配置需统一修改 `app`、`backup`、`maintenance` 三处镜像。
5. 执行 `docker compose pull`、`docker compose up -d`，检查迁移、查账、通知与备份状态。

回退到 rc.4 或更早版本，须恢复目标版本兼容的升级前备份和原主密钥。升级后已有新交易时，先保留当前完整数据。

清理查账历史后，空出来的数据库页会留给后续数据复用。需要真正减小主库文件时，先停服，再按[数据库空间与压实](https://github.com/Mashiro0619/PerPay/blob/v1.0.0/docs/maintenance.md#数据库空间与压实)操作。

新部署下载本版 `docker-compose.yml`，按[部署说明](https://github.com/Mashiro0619/PerPay/blob/v1.0.0/README.md)启动。支付宝应用须已上线，并具备对应收款账户的账务明细查询权限。
