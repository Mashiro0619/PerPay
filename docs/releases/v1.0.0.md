# PerPay 1.0.0

PerPay 1.0.0 是首个正式稳定版本，提供完整的自托管支付宝个人收款码自动核账方案：业务网站创建订单，顾客按收银台金额付款，PerPay 自动查账确认并发送通知。一个后台可管理多个业务网站和支付宝账号，支持原生 API 与易支付 V1/V2，并提供内置在线备份、恢复、历史归档与双轨在线自更新。

## 1.0.0-rc.5 以来的改进

- **可选在线一键更新与升级助手**：新增独立可选伴生更新器配置 `docker-compose.updater.yml`（主 `app` 容器维持只读、非 root 且零 `docker.sock`），支持升级前自动在线备份、重启断连自动重连与健康检查失败自动回滚；默认安全部署下提供内置升级助手，可一键在线备份并复制目标版本单行升级命令。手动检查更新解除失败退避锁死，可随时重试。
- **管理员手动查账立即恢复**：修复长期网络/IP 异常触发长时间退避后，更换 IP 点击“手动查账”仍被排队至数小时后导致无法恢复收款的问题；管理员手动查账改为仅在查账进行中防连击，可立即探测并在成功后清零历史退避，后台自动查账与收银台公开核实继续保留完整退避与最小间隔。
- **允许加价从 ¥0.00 开始的可选项**：在“业务网站 → 订单设置”与“新网站默认设置”新增“允许原价起（从 ¥0.00 开始加价）”开关（默认关闭以保持原 +¥0.01 起避开个人日常整数收款的策略）；开启后首笔订单按原价收款，并发撞额时依次递增至最大加价金额，并支持将最大加价金额设为 0（仅原价单槽位）。
- **收银台移动端一键跳转支付宝**：手机端收银台新增“打开支付宝”按钮，免扫码直接拉起支付宝进入付款金额输入页并自动复制精确应付金额，对微信/QQ 内置浏览器提供明确降级引导。
- **通知手动重试全入口闭环**：在通知列表、待处理列表与订单详情顶部/底栏补齐一键“立即重试”与“重新发送”快捷入口，并透传具体失败原因。
- **总览与运行状态界面重构**：重构总览趋势图表（支持平滑面积、柱状与累计视图）、每日数据账单日历、网站概览与运行状态页布局，支持在“系统设置 → 界面显示”自定义总览显示模块，并新增修改管理员密码前的当前密码校验与右侧整高详情面板。

## 升级与恢复

本版的数据库结构版本（schema）为 **49**，兼容范围为 **24—49**。从 RC5（结构版本 47）升级会执行迁移 48—49（放宽 `payment_orders` 与 `amount_slots` 的 0 分加价约束，并新增 `runtime_configuration.dashboard_sections` 总览模块显示设置）；从更早版本（24—46）升级会依次执行所需迁移。

1. 使用原版本完成备份，单独保存原主密钥（`PERPAY_MASTER_KEY` 或 secrets 卷中的 `master-key`）。
2. 停止应用和自动备份：`docker compose stop app backup`。
3. 如固定了镜像标签，将 `x-perpay-image` 改为 `ghcr.io/mashiro0619/perpay:1.0.0`（默认 `latest` 会自动指向 `1.0.0`）。
4. 执行 `docker compose pull`、`docker compose up -d`，检查迁移、查账、通知与备份状态。

回退到 `1.0.0-rc.5` 或更早版本，须恢复目标版本兼容的升级前备份和原主密钥。升级后已有新交易时，先保留当前完整数据。

新部署下载本版 `docker-compose.yml`，按[部署说明](https://github.com/Mashiro0619/PerPay/blob/v1.0.0/README.md)启动。
