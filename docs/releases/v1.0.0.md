# PerPay 1.0.0

PerPay 1.0 正式版提供面向个人开发者的自托管支付宝收款流程：创建订单、展示收款码、自动查账确认，再将结果通知业务网站。一个后台可管理多个业务网站和支付宝账号，支持原生 API 与易支付 V1/V2。

## 1.0 的主要能力

- **多网站与多账号收款**：各网站独立管理接入密钥、通知和订单，按指定、随机或权重选择收款账号。同账号下的网站共享应付金额空间及冷却规则。
- **自动查账与人工复核**：使用支付宝官方 SDK 查询账务明细，按应付金额与付款时间确认订单；错付、迟付、重复付款及争议保留流水和处理证据，便于人工核对。
- **三种接入方式**：网站接入助手提供原生 API、易支付 V1/V2 的配置与 Demo。通知包含签名，支持失败重试和人工重发，可查看每次投递结果。
- **日常管理与维护**：查看订单和收款趋势、导出 CSV、追溯审计记录，通过自动备份、主密钥保存和恢复工具维护实例。

## RC4 以来的改进

- 首次配置按步骤展示缺少的应用、密钥与收款码，新网站创建后直接进入接入配置。创建支付宝账号时即使响应丢失，重试也会恢复同一账号。向导弃改刷新会重新读取账号和网站、复位表单；试收款之后可继续配置所选网站的业务接入，并核对订单和通知结果。
- 网站接入设置切换分组时保留易支付开关草稿及在途操作。测试收款遇到明确拒单时可以更换网站和金额；原请求结果未知时继续保留原操作供重试。
- 支付宝配置指南补齐经营码申请、保存与上传步骤，收款码和开放平台应用按同一收款账号配置。
- 争议订单在核对可用收入流水并填写理由后可以重新确认，原关联、撤销和通知记录持续保留。每日与网站确认金额按每次确认的历史快照汇总，后续重新确认不再改写过去日期的金额。
- 正常查账结果新鲜时，历史补扫可以继续进行并接收新订单。更换 App ID 后，同账号、同环境的新来源迟付款可以由管理员核对后关联旧订单，继续校验同付款去重。
- 通知重发后直接打开新投递，原记录与最新结果相互关联；已撤销确认的易支付成功通知终止重发，并引导核对订单当前状态。待处理优先展示需要人工处理的事项。外部退款登记后，可逐条忽略已核对的争议提醒。
- 订单列表区分待付款、已过期未付款和已关闭未付款，并保留商户订单号。订单和流水的同名账号筛选使用 App ID 或短账号编号区分；CSV 可选择创建日期范围，包含收款账号和金额单位。
- 收款趋势的每日数据一次展示所选范围内全部日期；空总览提供首次收款入口。手机收银台说明将二维码保存到相册或截图后扫码付款，本地 HTTP 易支付收银台保留返回商家入口；列表、弹窗和错误提示适配窄屏与放大文字。
- 成功单页查账中的空结果和重复流水副本保留 7 天，后台分批回收；首次入账证据、异常及各账号最近的查账记录持续保留。无变化的健康查账、对账和空通知轮次按小时汇总，减少长期运行的数据增长。
- 备份在空间允许时压实 SQLite 空闲页。备份进程在等待下一轮任务期间，以不超过 30 秒的间隔重读备份频率和保留数量，持锁对账并确认新策略，按新策略安排下一轮及判断副本时效，避免将正常等待报为配置故障。新增数据库空间诊断与停服压实命令，运行空间检查采用固定 64 MiB 门槛。
- Compose 的应用、备份和维护工具共用 `x-perpay-image`。发布附件固定对应镜像版本，维护说明补齐全新服务器导入备份与原主密钥的恢复步骤。
- 源码启动默认监听本机回环地址。初始化 API 默认提交管理员密码；开启初始化令牌时再提交最近启动日志中的令牌。

## 升级与恢复

本版使用 **schema 44，运行兼容范围为 24—44**。使用 schema 44 的 RC5 构建升级无需新增迁移；从 rc.4 升级会应用采集历史回收与争议重新确认相关迁移。发生数据库迁移时，应用会先创建并校验迁移前备份。

1. 使用原版本完成数据库备份，并单独保存原主密钥（`PERPAY_MASTER_KEY` 或 secrets 卷中的 `master-key`）。
2. 停止应用和自动备份：`docker compose stop app backup`。
3. 将 Compose 顶部 `x-perpay-image` 改为 `ghcr.io/mashiro0619/perpay:1.0.0`。旧配置没有此项时，将 `app`、`backup`、`maintenance` 三处镜像统一修改。
4. 执行 `docker compose pull`、`docker compose up -d`，核对服务健康状态、查账和通知结果。

此前若有同一付款被跨应用来源重复确认的历史数据，升级前按[重复收款关联检查](https://github.com/Mashiro0619/PerPay/blob/v1.0.0/docs/maintenance.md#历史重复收款关联的升级检查)完成核对。回退到 rc.4 或更早、只支持较低 schema 的构建时，须恢复匹配的升级前备份及原主密钥；已有新增账务时先保留当前完整数据。

新部署可直接下载本 Release 的 `docker-compose.yml`。接入所需支付宝应用应已上线，并具备对应收款账户的账务明细查询权限；配置步骤见[支付宝接入](https://github.com/Mashiro0619/PerPay/blob/v1.0.0/docs/alipay-setup.md)。
