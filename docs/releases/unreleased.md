# PerPay 未发布改动

当前源码已准备 [1.0.0-rc.2](v1.0.0-rc.2.md)，新增可筛选、查看详情及导出 CSV 的全局审计日志，汇总管理、业务接口、后台任务与备份维护活动。此前的支付宝多账号、网站收款分配和正式应用接入要求继续适用，见 [1.0.0-rc.1 说明](v1.0.0-rc.1.md)。

数据库升级至 schema 39，增加审计上下文与活动记录，保留旧审计哈希和业务事实。核心审计及其来源、字段变化持续保留，接口与任务活动保留 30 天；旧记录未采集的 IP、设备及字段变化不回填。1.0.0-rc.1 的结构上限仍为 38，1.0.0-alpha.2 仍为 36。

版本号和说明文件不代表已经公开发布。部署前请确认目标版本的 GitHub Release 和镜像已经可用；升级与回退要求见[维护说明](../maintenance.md#固定版本与回滚)。

新增发布说明按[发布模板](TEMPLATE.md)编写。

## 审计日志

- 全局入口 `/admin/audit` 支持来源、类别、动作、结果、操作者、网站、IP、日期和关键词筛选；网站选项保留历史网站，“未关联网站”表示当时没有记录网站归属。
- 核心记录与本次请求／任务的执行结果分别展示，通过内部活动编号关联。同一请求可能产生多条核心事实，记录条数不能当作业务操作次数。
- 普通成功查询按分钟汇总，显示首次／最后时间、次数及累计耗时；失败、关键变化和任务结果保留单条。新来源信息按可信代理配置解析；旧来源哈希不显示成真实 IP。
- CSV 使用固定读取快照，保留中文编码、单元格引用及公式转义。日期跨度超过 366 天或结果超过 10,000 条时返回错误，不自动截断。导出记录表示文件已生成，不表示用户已完成下载。
- 备份与维护事件通过 `PERPAY_BACKUP_DIR/perpay-activity/v1` 交接，由主进程只读采集；采集异常与已检测到的缺口在页面显示，保留规则见[隐私说明](../privacy.md)。

## 官方更新检查

- 发现新版本时显示更新弹窗，同一浏览器对同一版本仅自动提示一次；正在编辑表单或操作其他弹窗时延后提示。侧边栏“运行状态”以图标提示新版本，可在运行状态页忽略当前通道的版本提醒、恢复提醒或重新查看更新。
- 手动检查刷新官方结果，并遵守每通道 60 秒间隔及 GitHub 限流等待时间；自动检查继续使用缓存。检查结果、失败原因和等待状态提供明确反馈。

## 紧凑提示与列表操作

- 后台服务读取失败和断网提示统一在页面顶部显示一次，共用重试入口；保留原分页重试、已读取的数据和操作失败反馈。
- 侧栏以图标提示暂停接单、运行告警、待处理提醒、状态未知和检查中，悬浮或键盘聚焦时显示完整说明；折叠侧栏同时保留运行状态与更新标记。
- 列表的展开／收起、清除搜索、密度和显示列入口改用图标，保留操作说明与菜单文字，减少窄屏和放大字号时的挤压。
- 收款趋势将标题、日期和时间／视图选择集中在上行，指标与图形选择另成一行；周期统一使用下拉框，图形类型使用带说明的图标，窄屏下按空间换行。
- 收款趋势新增“金额与订单”组合视图，以柱形和折线同时展示每日确认金额、新建订单，金额与笔数使用独立刻度；同日提示同时列出两项值，汇总仍分别使用各自的区间总数。
