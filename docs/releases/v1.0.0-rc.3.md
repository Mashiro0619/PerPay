# PerPay 1.0.0-rc.3

本版修复历史数据较多时，迁移前备份校验耗尽容器临时空间、导致升级启动失败的问题。此前从 RC1 升级并遇到该错误的实例可换用本版重试。

## 主要更新

- 备份、恢复和管理员救援检查数据库时，将查询产生的临时数据存入内存，避免占满官方 Compose 中 32 MiB 的应用临时目录。
- 数据库完整性检查出错时，记录发生在哪一步及 SQLite 错误码，便于区分空间不足、数据库损坏，以及字段或记录关系不符合规则的问题。

## 升级与恢复

本版的数据库结构版本（schema）为 **40**，兼容范围为 **24—40**，与 rc.2 相同。

1. 完成数据库备份，单独保存原主密钥 `PERPAY_MASTER_KEY`。
2. 停止应用与自动备份，将三个服务统一设为 `ghcr.io/mashiro0619/perpay:1.0.0-rc.3`，拉取镜像并启动。
3. 检查迁移结果、运行状态和自动备份。

若 RC2 日志同时包含 `backup verification failed`、`database or disk is full`，且调用栈经过 `createPreMigrationBackup`，失败发生在迁移前；停止全部写入进程后，可保留现有数据库换用本版重试。

已迁移到结构版本 40 的实例回退到 RC1，须恢复符合其结构版本上限 38 的备份和原主密钥。后续 RC 升级需主动调整固定镜像标签。
