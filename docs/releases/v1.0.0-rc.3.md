# PerPay 1.0.0-rc.3

相较于 1.0.0-rc.2，本版修复较多历史记录的实例在升级时，迁移前备份校验耗尽容器临时空间、导致应用启动失败的问题。从 RC1 升级时遇到该错误的实例可使用本版重试。

## 主要更新

- 备份、恢复及管理员救援的独立完整性校验连接统一使用内存保存查询临时数据，修复官方 Compose 的 app 容器在 32 MiB 临时目录限制下的校验失败。
- 完整性检查执行失败时，日志保留具体阶段与 SQLite 错误码，便于区分临时存储不足、数据库损坏和实际数据约束违规。

## 升级与恢复

本版使用 schema 40，运行兼容范围为 24—40。

升级前完成备份，单独保管原主密钥 `PERPAY_MASTER_KEY`，然后停止应用与自动备份，将 Compose 中 `app`、`backup`、`maintenance` 的镜像统一切换为 `ghcr.io/mashiro0619/perpay:1.0.0-rc.3`，拉取镜像并启动。启动后检查后台运行状态和自动备份。

如果 RC2 的错误明确为 `backup verification failed`、包含 `database or disk is full`，且调用栈经过 `createPreMigrationBackup`，失败发生在 schema 迁移之前。停止全部写入进程后，可保留现有数据库并换用本版重试。

已经迁移到 schema 40 的实例回退到 RC1 时，须恢复迁移前、符合 RC1 结构上限 38 的备份及原主密钥。

本版为预发布版本，附件采用固定 RC 镜像通道，后续升级需显式修改三个服务的镜像版本。

完整升级步骤、数据库兼容范围及恢复方法见[维护说明](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.3/docs/maintenance.md#固定版本与回滚)。
