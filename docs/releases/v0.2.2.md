# PerPay 0.2.2

本版允许管理员记录已在支付宝完成的退款，按当前筛选一次忽略多页提醒，并设置金额再次用于新订单前的等待时间。登录状态可保留 30 天。

## 更新内容

- 管理员可标记或撤销外部退款，填写备注并查看历史。实际退款在支付宝完成；标记不转账、不验证退款，也不通知业务网站。
- 待处理页面的四类提醒支持按当前筛选一次忽略多页记录，也可查看已忽略记录并逐条恢复。隐藏提醒后，原冲突仍需处理，系统仍按原策略重试通知。
- 普通支出仍保存为流水并接受校验，但不再参与自动收款匹配，也不再产生待处理提醒；收入匹配和流水冲突检查继续进行。
- 改善密钥弹窗与窄屏布局。页面显示的密钥仍会在限定时间后清除，保存配置前仍会检查它是否在编辑期间发生过变化。
- 支持 30 天保持登录，浏览器不保存管理员密码。
- 查账增加常规与活跃两档间隔。金额再次用于新订单前需要等待冷却时间，登录接口增加请求频率限制。

## 兼容性说明

| 事项 | 本版行为 |
| --- | --- |
| 旧退款登记 API | `POST /api/admin/v1/reconciliation/refunds` 完成鉴权和格式校验后返回 `410 / refund_recording_retired`。 |
| 历史退款 | 保留既有退款记录、部分/全额退款状态及 `REFUND_UPDATED` 事件；已排队通知继续投递。 |
| 新管理员标记 | 只在后台记录管理员的处理结果，不改变付款状态、实收金额、业务接口中的订单版本或记账分录，也不出现在业务 API 和收银台中。 |
| 已结束提醒 | 保留查阅，不能恢复成待处理事项。 |
| 历史支出提示 | 保留原记录与处理状态。 |

## 升级

本版的数据库结构版本（schema）升级至 **23**。迁移会增加提醒状态及管理员标记，保留原有金额、收款凭据、账务状态和审计记录。

1. 备份数据库，另存 `perpay-secrets` 主密钥卷。
2. 将三个服务统一设为 `ghcr.io/mashiro0619/perpay:0.2.2`，在原部署目录执行：

   ```sh
   docker compose pull
   docker compose up -d
   ```

3. 核对迁移与原配置。旧查账间隔同时保留为常规和活跃间隔；金额复用冷却默认 600 秒，付款截止时间按原订单保留。

回退需要目标版本兼容的备份和原主密钥。升级后已有新交易时，先保留当前完整数据，避免用旧备份覆盖新增记录。
