# PerPay 1.0.0-rc.4

本版新增易支付 V1/V2 和网站接入助手，支付宝查账统一使用官方 Node.js SDK。已有易支付插件的网站可直接使用 PerPay 收银台完成支付宝收款。

## 主要更新

- 网站接入助手支持原生、易支付 V1/V2，提供可直接运行 Demo 的完整配置下载。
- 易支付支持页面及 API 下单、单笔查单、订单列表、商户统计、付款通知和同步返回。订单号、金额、通知与重试沿用现有收款流程。
- 每站分配固定数字 PID，新网站默认开启 V1/V2 并自动生成密钥。V1 密钥及 V2 商户和平台密钥分别加密保存、查看与轮换。关闭协议接单后，历史查询与通知继续可用。
- Node Demo 支持三种协议和独立数据目录，可重复接收通知并核对同步返回。
- 支付宝请求签名与响应验签使用官方 SDK，原始账单证据、超时、取消和错误分类保留在 PerPay 适配层。
- 电脑端点击顶部网站名称即可展开切换菜单，保留当前栏目与适用筛选，并沿用未保存修改和在途操作保护。

## 修复与体验调整

- V2 查询接口严格区分各自接受的参数，阻止将顾客可见的下单签名重放到商户查询接口。
- 同一收款账号的同一支付宝付款，跨应用来源最多保留一个生效关联；候选查询、确认写入和数据库完整性检查使用同一约束。
- 到期订单、付款统计与应用切换使用一致的截止时间。更换应用前，实际查账覆盖必须达到最后订单截止或主动关闭时刻，并完成对应对账。
- 易支付配置冲突后重新读取可合并协议开关草稿；明文密钥在隐藏页面、离开或展示满 60 秒后清除。
- 离线退出登录及撤销会话立即提示未提交，避免联网后自动执行旧操作。
- 手机订单、通知和待处理列表保留订单辨识信息，整理金额与状态层级；登录字段间距收紧，图表触屏点击不再出现粗焦点框。
- 极窄屏放大文字时，记录操作按钮按卡片宽度换行，保留完整点击区域和焦点边界。
- 接入助手的临时回调地址在下载配置时校验；历史订单的商家返回地址保留原查询编码，通知参数与签名按协议核对。
- 发布流程在同一待发布提交的三个浏览器回归分片全部通过后，才开始镜像发布。

## 接入调整

尚未初始化易支付的现有网站会在启动时生成密钥并开启 V1/V2，管理员已保存的开关和密钥继续使用原值。网站可在接入设置中直接下载配置。V2 商户私钥用于签请求，平台公钥用于验证响应、通知和同步返回。完整配置包含密钥，应保存在业务后端。

通知与查单金额使用商品原价，收银台与对账使用实际应付金额。商家仍需按订单号幂等履约，并同时验证签名和金额。[易支付接入说明](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.4/docs/epay-integration.md)

## 升级与恢复

本版使用 schema 42，运行兼容范围为 24—42。迁移新增易支付商户、凭据历史、兼容订单及通知证据，历史原生订单继续按原协议处理。

升级前在原版本的 **对账 → 支付宝流水 → 多笔关联** 检查重复确认。同一付款若被错误关联给多个订单，先按实际收款与履约情况撤销错误关联并重新备份；新版完整性检查会拒绝含这类重复关联的数据库和备份。具体步骤见[历史重复收款关联的升级检查](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.4/docs/maintenance.md#历史重复收款关联的升级检查)。

发布后，固定版本镜像为 `ghcr.io/mashiro0619/perpay:1.0.0-rc.4`。升级前完成备份并单独保管原主密钥 `PERPAY_MASTER_KEY`，停止应用和自动备份，将 app、backup、maintenance 统一切换到同一版本后启动。服务启动时会创建并校验迁移前备份。

结构 42 的数据库回退至 RC3 及更早构建时，须恢复对应的迁移前备份和原主密钥，并核对备份之后新增的交易记录。

完整升级步骤、数据库兼容范围及恢复方法见[维护说明](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.4/docs/maintenance.md#固定版本与回滚)。
