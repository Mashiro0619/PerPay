# PerPay 1.0.0-rc.4

本版新增易支付 V1/V2 与网站接入助手，支付宝查账统一使用官方 Node.js SDK，已有易支付插件可接入 PerPay 收银台。

## 主要更新

- **三种协议接入**：接入助手提供原生 API、易支付 V1/V2 说明及 Demo 配置下载。
- **易支付接口**：支持从页面或 API 下单、查询单笔订单和订单列表、查看商户统计、接收签名通知，以及付款后返回商家页面；订单和收款沿用现有处理流程。
- **独立凭据**：每个网站有固定的数字商户号 PID，默认开启 V1/V2 并生成密钥；各协议的商户和平台凭据分别加密保存，可查看或更换。
- **Node Demo**：支持三种协议和各自的数据目录。重复收到同一通知时不会重复处理，浏览器返回后还会核对付款状态。
- **官方 SDK**：由官方 SDK 生成请求签名并验证响应签名。PerPay 继续保存查账的原始响应，负责超时、取消及错误分类。
- **网站切换**：桌面顶部名称可展开网站菜单，保留当前栏目和适用筛选。

## 修复与体验调整

- V2 的各个查询接口只接受对应参数，防止用顾客能看到的下单签名读取商户订单和统计。
- 即使在不同应用来源下查到同一付款，也只能保留一条有效的收款关联。推荐可关联的记录、确认收款和检查数据库时，都执行这条规则。
- 订单到期统计、需要查账的时段和应用切换检查使用同一截止时间；更换应用前，先完成最后一笔订单对应时段的查账和对账。
- 发现配置已被其他操作修改时，可重新读取最新配置，并保留、合并尚未保存的开关选择。页面上显示的密钥在隐藏、离开页面或显示 60 秒后清除。
- 网络断开时，退出登录或让其他设备下线会立即提示操作尚未提交；恢复联网后不会补做这次旧操作。
- 手机列表保留网站名称、订单号等识别信息，改善窄屏、大字号、触屏输入和登录页布局。
- 下载配置前检查输入的临时回调地址；旧订单的返回地址保留原查询参数编码，通知按所用协议验证参数与签名。

## 接入调整

未初始化易支付的旧网站会在启动时生成密钥并开启 V1/V2，已有开关和凭据保持原值。关闭协议接单后，历史查询与通知继续处理。

V2 商户私钥用于签请求，平台公钥用于验证响应、通知和同步返回。含私钥的完整配置保存在业务后端。

易支付通知和查单金额使用商品原价，收银台与对账使用实际应付金额。业务端同时验证签名和金额，并保证同一订单即使收到多次通知，也只充值或发货一次。[易支付接入](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.4/docs/epay-integration.md)

## 升级与恢复

本版的数据库结构版本（schema）为 **42**，兼容范围为 **24—42**。迁移增加易支付商户信息、密钥历史、订单协议字段和通知原始记录；原有的原生订单继续使用原协议。

1. 在原版本的“对账 → 支付宝流水 → 多笔关联”核对重复确认，按实际收款撤销错误关联并重新备份。[检查步骤](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.4/docs/maintenance.md#历史重复收款关联的升级检查)
2. 保存数据库备份和原主密钥 `PERPAY_MASTER_KEY`，停止应用及自动备份。
3. 将三个服务统一设为 `ghcr.io/mashiro0619/perpay:1.0.0-rc.4`，启动时创建并校验迁移前备份，随后核对查账与通知。

同一付款同时被确认给多笔订单时，数据库完整性检查会拒绝该数据库。回退到 rc.3 或更早版本，须恢复对应迁移前备份和原主密钥，并保管升级后新增的交易记录。
