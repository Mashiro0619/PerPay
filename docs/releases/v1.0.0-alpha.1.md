# PerPay 1.0.0-alpha.1

这是 1.0 系列的首个预发布版本。相较于 0.3.2，本版新增多业务网站支持，并重新整理管理后台、数据概览和对账流程。

Alpha 版本用于新功能试用和升级验证，已有生产收款建议继续使用稳定版。

## 主要更新

- **多网站管理**：一次部署可接入多个自有网站，共用支付宝账户与经营收款码。每个网站独立管理 API 密钥、通知密钥、订单策略和收银台展示。
- **新版管理后台**：全局概览汇总各网站的收款情况；进入网站后，订单、通知、待处理事项和设置都围绕当前网站展开。网站切换、创建和配置流程同步简化。
- **统一对账中心**：集中查看支付宝流水、账务异常和账本冲突，支持筛选交易、查看来源记录及跳转关联订单。同一订单的多笔付款分别保留金额、时间和流水号，方便逐笔核对。
- **数据概览**：增加每日收款明细、日均与单日最高金额，支持比较各网站收款情况；最近订单直接展示收款和通知进展，待处理事项按优先级排列。
- **界面与操作**：重新整理列表、详情和设置页面，增加紧凑／舒适密度及侧栏收起选项，改善手机布局、长文本显示和键盘操作。
- **失败恢复**：完善设置保存冲突、网络中断和付款核实后的恢复。保存失败时保留草稿，结果未知时保留原操作供继续核查；已结束的收银台继续更新后续确认结果。

## 接入调整

旧实例升级后，原业务网站迁移为 `default`，保留已有密钥、订单和通知记录。业务请求与通知的 HMAC 签名协议保持不变；新增网站使用各自的客户端 ID 和密钥。

管理接口有破坏性调整：网站配置与实例设置分开保存，旧单站配置入口停用；全局测试收款和按商户订单号查询需要明确网站，业务状态接口改为只返回本站状态。自行维护管理脚本或客户端的用户，请按[多网站接入说明](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-alpha.1/docs/multi-site.md)调整。

## 升级与恢复

本版将数据库升级至 schema 35。**升级前先备份数据库，并单独保存原 `PERPAY_MASTER_KEY`。升级后的数据库不能直接交给 0.3.2 打开；回退必须恢复升级前备份及原主密钥。**

预发布镜像固定为 `ghcr.io/mashiro0619/perpay:1.0.0-alpha.1`。`app`、`backup`、`maintenance` 三个服务须使用同一版本；本版不会更新稳定版 `latest`。

完整升级步骤、数据库兼容范围及恢复方法见[维护说明](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-alpha.1/docs/maintenance.md#固定版本与回滚)。
