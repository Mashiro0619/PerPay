# PerPay 1.0.0-alpha.1

1.0 系列首个预发布版本，在 0.3.2 基础上新增多业务网站，并重新整理后台、数据概览和对账流程，可用于试用新功能和检查旧实例能否顺利升级。

## 主要更新

- **多网站管理**：一次部署接入多个自有网站，共用支付宝账号和收款码，各网站独立管理 API 与通知密钥、订单策略及收银台展示。
- **网站工作台**：全局汇总各网站收款，进入网站后查看本站订单、通知、待处理与设置。
- **对账中心**：集中查询支付宝流水、账务异常和冲突，查看来源并跳转关联订单；同一订单的多笔付款分别保留金额、时间和流水号。
- **经营概览**：增加每日收款、日均和单日最高金额、网站对比；最近订单显示收款与通知进度。
- **日常操作**：列表支持紧凑/舒适密度和侧栏收起，改善手机、长文本与键盘操作。
- **失败恢复**：配置保存失败时保留已填写内容；无法确定是否成功时，保留原操作供核查或重试。收银台结束后仍会更新后来确认的付款结果。

## 接入调整

旧实例的业务数据迁移到 `default` 网站，保留已有密钥、订单和通知。业务请求与通知的 HMAC 协议保持不变，新增网站使用自己的客户端 ID 和密钥。

网站配置与整个实例的设置分别保存，原来只支持一个网站的管理接口停止使用。从全局页面测试收款、或按商户订单号查询时，需要指定网站；业务状态接口只返回当前网站的状态。管理脚本按[多网站接入](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-alpha.1/docs/multi-site.md)调整。

## 升级与恢复

本版的数据库结构版本（schema）升级至 **35**。

1. 备份数据库，单独保存原主密钥 `PERPAY_MASTER_KEY` 或 secrets 卷中的密钥文件。
2. 将 `app`、`backup`、`maintenance` 统一设为 `ghcr.io/mashiro0619/perpay:1.0.0-alpha.1`。
3. 按[固定版本升级步骤](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-alpha.1/docs/maintenance.md#固定版本与回滚)启动并核对默认网站、历史订单和通知配置。

预发布使用固定标签，不更新稳定版 `latest`。回退到 0.3.2 时须恢复升级前备份和原主密钥。
