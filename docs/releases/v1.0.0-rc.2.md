# PerPay 1.0.0-rc.2

相较于 rc.1，本版新增全局审计日志与客户端 ID 管理，并统一订单详情、配置编辑和手机列表的操作方式。

## 主要更新

### 审计与数据管理

- 全局审计可按来源、类别、动作、结果、操作者、历史网站、IP、日期和关键词查询；打开详情可查看同一次请求或任务产生的关键业务记录。
- 订单的关键状态变化、收款确认、撤销与管理操作持续保留审计记录。新记录显示来源 IP、设备和普通字段修改前后的值；密钥等秘密只记录发生了变更。
- 关键行为和失败逐条记录，普通成功查询按分钟汇总。备份和维护进程先把事件写到备份目录，再由主进程读取；发现未能完整收集的记录时，页面保留提示。
- 核心审计持续保留，接口与任务活动保留 30 天。CSV 按当前筛选导出，最多 366 天、10,000 条；导出成功也会留下审计记录。

### 网站与后台操作

- 创建网站时可自定义客户端 ID，之后也可更换；历史订单等数据始终关联到同一个固定网站编号。
- 订单、通知、流水、对账、审计和网站概况使用一致的详情弹窗，桌面居中、手机全屏。切换编辑分组时保留未保存内容，关闭弹窗后回到之前的页面。
- 新账号可先创建再继续配置，同名账号和网站显示 App ID 或编号，人工关联同时展示双方账号。
- 图表增加金额与订单组合视图；更新弹窗在编辑时延后显示，可按通道忽略或恢复提醒。
- 手机列表保留网站名称、订单号等识别信息，较长的商品名、通知内容、金额和操作按钮按可用宽度排列。

### 修复

- 修复批量忽略后的合法记录被完整性检查拒绝，导致备份或重启失败的问题。
- 修复输入框选中边框被裁切、菜单抢走错误输入项的键盘焦点、手机分类无法点击，以及放大文字后开关滑块超出边框的问题。
- 窗口较矮时，可滚动查看完整的确认说明和操作按钮；成功提示避开密钥正文。
- 二维码加载失败可重试，手机横屏且高度不足时仍能关闭弹窗；旧对账地址失效时可返回列表。
- 使用中文输入法时，等选词完成再搜索。准备再次测试收款时，光标回到金额输入框；刷新详情时，一并更新关联的收款记录。

## 接入调整

### 客户端 ID 与网站编号

创建网站的可选 `client_id` 为 3—64 位字母、数字、点、下划线或连字符，首位为字母或数字，区分大小写；留空自动生成。

更换接口为 `POST /api/admin/v1/sites/{clientId}/actions/change-client-id`，提交 `operation_id`、`revision` 和新的 `client_id`。成功后，业务端立即更新 `X-PerPay-Client-Id` 及签名中的 ID。旧 ID 失效，系统保留它的使用记录，防止再次分配。

| 字段 | 含义 |
| --- | --- |
| 管理员响应 `client_id` | 固定网站编号，用于管理路径，以及关联历史订单等记录 |
| 管理员响应 `api_client_id` | 当前业务接入的客户端 ID |
| 业务状态 `client_id` | 当前接入 ID |
| 业务状态 `site_id` | 稳定网站编号 |

Node Demo 启动时读取 `/api/v1/system/status`，将本地订单绑定到 `site_id`。字段与接口见 [OpenAPI](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.2/openapi.yaml) 和[接入参考](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.2/USAGE.md)。

### 审计与流水

管理员登录后才能查询审计；导出还会检查请求来源并进行 CSRF 校验。管理员流水详情可返回收款账号 ID 和名称，旧记录中找不到对应账号时，这些字段为空。[审计维护说明](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.2/docs/maintenance.md#审计日志与采集状态)

## 升级与恢复

本版的数据库结构版本（schema）为 **40**，兼容范围为 **24—40**。迁移增加审计中的请求与操作者信息、接口和任务活动记录，以及网站与公开客户端 ID 的对应关系；原有审计哈希、网站编号等业务标识保持不变。

1. 用原版本完成备份，单独保存原主密钥 `PERPAY_MASTER_KEY`，保管 `PERPAY_BACKUP_DIR/perpay-activity/v1` 中的维护事件。
2. 停止应用与自动备份，将三个服务统一设为 `ghcr.io/mashiro0619/perpay:1.0.0-rc.2` 后启动。
3. 检查迁移、审计采集、后台任务及备份。

回退到 rc.1（结构版本上限 38）或更早版本需恢复对应升级前备份和原主密钥。固定 RC 标签不更新稳定版 `latest`。
