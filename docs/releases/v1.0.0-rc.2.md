# PerPay 1.0.0-rc.2

相较于 1.0.0-rc.1，本版增加全局审计日志、自定义与更换客户端 ID，并调整后台详情、设置和手机列表的操作方式。管理员可以在详情弹层中核对订单、收款账号、流水和通知，追溯操作来源及字段变化。部署者需要按新的保留规则管理数据库、备份与导出文件。

RC 版本面向受控试用与升级验证。部署前请确认对应 GitHub Release 和固定版本镜像已经可用。

## 主要更新

- 创建网站时可自定义客户端 ID，留空自动生成，之后可在接入设置中单独更换。更换立即生效，业务端须同步配置，历史数据通过稳定网站身份关联。
- 订单、通知、流水、对账、审计和网站概况使用统一详情弹层，桌面居中、手机全屏，关闭后回到父页原位置。桌面详情高度限制在视口的 85% 以内，最高 900px，长内容在正文区域滚动。网站与账号编辑的分组共享草稿，修复手机轻触部分可见分类标签时无法切换的问题。设置摘要直接显示收款分配和白名单规则，对账详情刷新同步更新关联证据。
- 修复输入框、文本域和开关焦点光圈被表单滚动区域裁切的问题。输入控件使用独立的焦点颜色，输入组合内的操作按钮提供清晰的键盘焦点提示，兼顾系统滚动条与页面缩放。账号保存草稿时，菜单关闭会尊重已移入错误字段的焦点。
- 确认步骤在极短可见视口下共用一个滚动区域，说明和操作按钮可依次滚动查看，关闭按钮有独立空间。提示支持键盘查看，关闭提示后可继续当前步骤。
- 开关滑块按轨道尺寸适配文字缩放。成功提示优先利用弹窗操作栏下方的可用空间，避免遮挡密钥正文。
- 新账号先创建再继续配置，未完成时可保存草稿。同名收款账号用 App ID 或编号区分，同名网站也会显示可区分的编号。人工关联最终确认分别显示订单和流水所属账号，金额不同会提示核对。中文搜索在输入法组词完成后执行，再次创建测试订单后焦点返回金额。
- 修复按关键词或网站筛选批量忽略待处理提醒后，合法记录被完整性校验误判、导致备份或重启失败的问题。校验兼容已有操作记录。
- 收银台二维码加载失败后可重复重试。长金额和短横屏下调整金额与放大二维码的布局，保留关闭操作空间。
- 手机网站列表提供进入后台及设置入口，通知明确区分业务事件和投递结果，流水显示关联订单及账号身份，最近订单的商品名与状态分行显示。收款趋势增加“金额与订单”组合视图，金额和笔数使用各自刻度，窄屏和放大文字下的操作可换行。
- 修复超长商品名撑宽流水表格和通知列表列宽溢出的问题，窄容器按可用空间安排身份和日期列。截断显示的商品仍可打开订单详情核对完整名称。
- 无效的旧对账详情地址提供返回列表入口，保留网站范围及已有返回上下文。
- 服务读取失败和断网提示集中呈现。侧栏显示暂停接单、运行告警与更新状态，支持键盘查看说明。更新弹窗在编辑时延后显示，可在运行状态页忽略当前通道的版本提醒、恢复提醒或重新查看更新。
- 全局“审计日志”支持按来源、类别、动作、结果、操作者、历史网站、IP、日期和关键词查询。桌面表格和手机摘要列表使用同一筛选与分页，详情可查看本次请求或任务关联的核心记录。
- 关键订单状态、自动／人工收款确认、撤销关联及管理操作保留核心审计，支持幂等重试。新记录显示当时的来源 IP、设备及普通字段变更前后值，秘密只显示已变更。
- 关键行为、失败和任务结果逐条记录。普通成功查询按分钟汇总次数、首次／最后时间和耗时，查询按来源限制读取量后合并，筛选目录增量更新。备份与维护进程通过备份目录交接事件，恢复、删除和清理记录保留经过验证的操作目标。
- 核心审计及上下文持续保留，接口与任务活动保留 30 天。已检测来源缺口持久保存，重启后继续提示。交接文件按批次清理，异常退出遗留来源也执行保留策略。
- 按当前筛选导出最多 366 天内的 10,000 条 CSV 记录，超限须缩小范围。导出使用固定读取快照及公式转义，生成成功会留下审计，下载后的文件由下载者保管。

## 接入调整

### 客户端 ID 与网站编号

创建网站可传入可选的 `client_id`，格式为 3—64 位英文字母、数字、点、下划线或连字符，首位须为字母或数字，区分大小写。后台输入留空时自动生成。已有网站可在接入设置中更换客户端 ID，也可调用 `POST /api/admin/v1/sites/{clientId}/actions/change-client-id`，提交 `operation_id`、`revision` 和新的 `client_id`。

更换完成后，业务端须立即更新签名请求中的 `X-PerPay-Client-Id` 及参与签名的客户端 ID。旧值随即失效，且持续保留占用记录。更换前应安排接入配置的同步更新。

管理员网站响应中的 `client_id` 表示稳定网站编号，`api_client_id` 表示当前接入用客户端 ID。管理员网站路径、历史记录和本地业务数据关联使用稳定编号。业务状态接口 `/api/v1/system/status` 返回当前 `client_id` 和稳定 `site_id`。Node.js 接入示例在启动时查询此接口，将本地订单存储绑定到 `site_id`，启动前需确保 PerPay 可访问。具体字段和请求格式见 [OpenAPI](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.2/openapi.yaml) 与[接入文档](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.2/USAGE.md)。

### 审计与流水

新增管理员审计列表、详情、筛选元数据和导出接口，均要求管理员会话，导出另需同源与 CSRF 校验。接口面向全局记录，支持网站筛选。权限与使用方法见[审计维护说明](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.2/docs/maintenance.md#审计日志与采集状态)。

管理员原始流水详情新增可选的收款账号 ID 和名称，历史归属不可用时返回空值。

## 升级与恢复

本版使用 schema 40，运行兼容范围为 24—40。迁移增加审计上下文、活动与采集凭据，以及网站公开接入 ID 映射。原有审计事件、哈希和业务身份继续保留。

升级前使用旧版本完成备份，单独保存原主密钥 `PERPAY_MASTER_KEY`，然后停止应用与自动备份，将 `app`、`backup`、`maintenance` 同时切换到本版。完成迁移后检查审计采集状态、后台任务及备份恢复。已有的 `PERPAY_BACKUP_DIR/perpay-activity/v1` 事件文件也应保管，其中可能包含尚未采集的维护记录。

1.0.0-rc.1 的结构上限仍为 38。回退到 rc.1 或更早版本必须使用对应升级前备份和原主密钥；升级后产生的新记录不能通过直接换旧镜像保留。

预发布镜像固定为 `ghcr.io/mashiro0619/perpay:1.0.0-rc.2`，不覆盖稳定版 `latest`，也不会自动跟随后续 RC。原多账号与正式支付宝应用接入要求继续适用。

完整升级步骤、数据库兼容范围及恢复方法见[维护说明](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.2/docs/maintenance.md#固定版本与回滚)。
