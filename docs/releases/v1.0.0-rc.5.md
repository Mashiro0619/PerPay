# PerPay 1.0.0-rc.5

本版改善长期运行的数据库与备份，并完善首次接入、争议收款复核和通知恢复流程。

## 主要更新

- 成功单页查账中的空结果和重复流水副本保留 7 天，后台每小时分批回收。每笔流水的原始入账证据、异常证据及各账号最近的查账记录继续保留。
- 备份在空间允许时自动压实 SQLite 空闲页，空间不足时保留完整快照；最终文件完成完整性校验后发布。
- 运行空间门槛改为固定 64 MiB，备份单独检查目标目录容量，修复大库仍有可用空间却提前停止收款的问题。
- 新增数据库空间查看与停服压实命令，可定位采集表和索引占用，并将已释放空间归还给文件系统。
- 无变化的健康查账和对账按小时汇总活动，减少逐轮日志；新流水、失败、恢复及人工操作仍独立记录。
- Compose 三个服务共用一个镜像配置，固定版本只需修改 `x-perpay-image`；首次反代部署补齐创建网络和配置可信代理的顺序。
- 修复列表“清除搜索和筛选”残留未提交关键词的问题；手机可直接清除关键词，窄屏大字号下搜索工具栏自动换行。
- 修复切换内容后残留的复制成功提示，较早的复制请求不再覆盖当前操作结果。
- 备份设置优先显示正在执行的任务，并明确提示中断恢复、时钟回退和需要重新备份等状态。
- 网站接入统一凭据名称，密钥在独立弹窗中查看和复制，轮换前显示警告及具体影响；短密钥使用单行输入，窄屏大字协议选项可完整排列。
- 管理员 IP 白名单保存冲突后可重读并保留草稿；双方修改 IP 列表时明确选择所需规则后再保存。
- 支付宝账号配置、换钥和删除遇到版本冲突后可重读并核对草稿；修复尚未完成配置的账号连续换钥失败。
- 窄屏和放大文字时，操作提示保留正文行宽，避免文字竖排或截断，并保持关闭和后续操作可用。
- 精简列表、查账诊断及通知记录中的重复说明，修正前端开发启动步骤，增加源码与验证入口导航。

- 新网站根据密钥是否存在显示生成或轮换，创建后直接进入协议接入配置；无可用收款账号时提供配置入口。
- 支付宝向导按分组填写，显示具体缺项、连接检查结果和收款就绪状态；已拒绝的保存不会再提示可能仍在提交。
- 订单列表、总览和详情区分过期／关闭未付款，保留独立的退款标记；列表默认显示商户订单号。
- 争议订单可在填写核对理由后重新关联可用收入流水。原关联、撤销及通知历史保留，仍未归属的原流水继续提醒；登记外部退款后可逐条忽略争议提醒。
- 通知重发后直接查看新投递并更新发送结果，原投递和最新结果可相互跳转；待处理默认优先展示需要人工操作的事项。
- CSV 导出窗口可选择创建日期范围、核对当前筛选，增加收款账号及金额单位。
- 空总览提供首次收款入口，手机收银台补齐保存二维码后在支付宝相册扫码付款的步骤。
- 备份摘要显示真实任务状态、最近副本与下一计划；查账诊断先展示账号与任务结果，审计详情直接显示失败原因，无业务通知轮次按小时汇总。
- 发布附件与镜像固定同一版本，部署区分稳定版和预发布版，新增全新服务器导入备份与主密钥的恢复步骤。

## 升级与恢复

本版使用 schema 44，运行兼容范围为 24—44。启动时新增采集历史回收状态、索引和有完整人工复核证据支持的争议重新确认规则；升级前自动保留迁移备份。回退到 rc.4 须恢复对应的升级前备份。

将 Compose 顶部的 `x-perpay-image` 改为 `ghcr.io/mashiro0619/perpay:1.0.0-rc.5`，三个服务会使用同一版本。旧配置没有此项时，将 `app`、`backup`、`maintenance` 三处 `image` 统一修改。数据库与原主密钥（`PERPAY_MASTER_KEY` 或 secrets 卷中的 `master-key`）需分别保存。

历史清理释放的空闲页由在线数据库继续复用，新备份在完成压实后缩小。需要立即收回主库磁盘空间时，按[数据库空间与压实](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.5/docs/maintenance.md#数据库空间与压实)停服执行维护命令。

完整升级与恢复步骤见[维护说明](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.5/docs/maintenance.md#固定版本与回滚)。
