# PerPay 1.0.0-rc.1

1.0 的首个发布候选版增加支付宝多账号、网站收款分配和正式应用接入，让待处理列表显示更多处理线索，并改进概览图表的操作。

## 主要更新

- **多账号收款**：账号独立管理应用、密钥、收款码、查账和运行状态；网站可指定账号、等概率随机或按权重分配，旧订单保留原账号与收款码。
- **首次设置**：按账号、网站、试收款三个步骤完成。初始化令牌默认关闭，可用 `PERPAY_SETUP_TOKEN_ENABLED=true` 开启。
- **待处理列表**：展示商品、商户订单号、网站、金额、异常原因与通知进度；未关联记录保留流水或提醒编号。
- **概览与辅助阅读**：面积、柱状和折线图提供日均与峰值统计，每日数据分页；图表选择保存在当前浏览器，日期包含完整星期信息。
- **交互反馈**：侧栏和分类切换支持减少动态效果，刷新保留历史趋势和展开记录，复制失败清除旧成功提示。
- **账号删除**：删除未使用账号时清除当前密钥，保留历史订单、流水与原账号的关系及审计记录，修复数据库完整性检查与重启失败。仍被网站、订单等记录使用的账号不能删除。
- **历史流水**：更换应用后，历史流水仍按原来的主要来源分组，翻页顺序不会因为切换应用而改变。

## 接入调整

原单账号配置入口迁至账号管理，旧写接口返回 `410 / alipay_settings_moved`。管理脚本改用账号接口，并在网站中选择收款账号；业务网站下单、签名和通知协议保持不变。[多网站接入](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.1/docs/multi-site.md)

支付宝应用须**已上线**并具备对应收款账户的账务明细查询权限。“开发中”应用不能查账；新账号配置只接受正式网关。

旧沙箱账号、流水、订单和通知保留查阅，但停止新收款、查账、自动对账及通知投递。原使用沙箱的实例需新增正式账号，并重新选择网站的收款分配。

付款仍按账号、完整应付金额和付款时间匹配。接入后按[支付宝配置指南](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.1/docs/alipay-setup.md)完成小额付款与通知联调。

## 升级与恢复

本版的数据库结构版本（schema）为 **38**，兼容范围为 **24—38**。迁移 37 将原配置移到默认账号；迁移 38 增加账号删除状态，保留历史记录与账号的关系。

1. 使用原版本备份数据库，另存原主密钥 `PERPAY_MASTER_KEY`。
2. 停止应用和自动备份，将三个服务统一设为 `ghcr.io/mashiro0619/perpay:1.0.0-rc.1`。
3. 启动后核对原账号、网站分配、订单、查账与通知。固定 RC 标签不会自动跟随后续 RC，也不更新稳定版 `latest`。

回退到 alpha.2 或其他结构版本上限低于 38 的构建，须恢复对应升级前备份和原主密钥。若曾使用未发布的结构版本 37 构建，且删除账号已破坏历史记录与账号的关系，先保存当前数据，再从删除前的有效备份恢复。
