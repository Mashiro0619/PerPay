# PerPay 1.0.0-rc.1

这是 1.0 系列的首个候选版本。相较于 1.0.0-alpha.2，本版增加支付宝多账号与网站收款分配规则，简化首次设置，并完善后台趋势、导航和读取反馈。

RC 版本面向受控试用与升级验证。源码版本号和说明文件不代表镜像已经发布，部署前请确认对应的 GitHub Release 和固定版本镜像已经可用。

## 主要更新

- **支付宝多账号**：每个账号分别管理应用、密钥、收款码、查账游标和运行状态。网站可以指定账号、等概率随机选择或按权重分配新订单；旧订单始终使用创建时的账号和收款码。
- **首次设置**：按“配置支付宝账号 → 配置网站 → 试收款”完成接入。一次性初始化令牌默认关闭，可通过 `PERPAY_SETUP_TOKEN_ENABLED=true` 开启；首次初始化前应限制后台访问来源。
- **总览与后台交互**：趋势支持面积图、柱状图和折线图，保留精确金额及每日数据分页。侧栏、列表展开和设置分类采用可打断的选中反馈，并遵守系统减少动态效果设置。
- **读取与复制反馈**：统计刷新失败时保留带日期的历史趋势，当前指标保持未知直到成功读取；离线恢复等待期间不重用过期读数，正常后台刷新保留已有读数。复制失败会清除上次成功状态，列表刷新保持展开记录。
- **账号删除**：删除未使用账号后保留不可变的历史归属关系，修复删除后数据库完整性检查及重启失败。当前密钥和可用配置会清除，账号名称、标识、历史收款码、应用身份及审计仍保留；已有网站、订单或流水引用的账号不能删除。
- **历史流水**：更换支付宝应用后，新增来源不再抢占已有流水分组的主来源；旧来源顺序和分页位置保持稳定，人工关联仍严格按来源账号筛选候选订单。

## 接入调整

原支付宝单账号设置入口转到账号管理，旧单账号写接口返回 `410 / alipay_settings_moved`。管理员接入工具需要使用支付宝账号接口，并在网站配置中选择收款账号。业务网站下单、签名及通知协议保持不变；分配规则和接口说明见[多业务网站接入](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.1/docs/multi-site.md)。

收款仍按实际账号、金额和时间匹配。付款人需支付完整应付金额；遗漏识别尾数或冷却结束后迟付仍有误归属风险。正式承接收款前，应使用实际支付宝账号完成小额下单、付款、查账确认和通知回执验证，详见[支付宝配置](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.1/docs/alipay-setup.md)。

## 升级与恢复

本版将数据库升级至 schema 38，运行兼容范围为 24—38。schema 37 将原支付宝配置迁为默认账号，保留旧订单、二维码、网站关联和待启用密钥；schema 38 增加账号删除状态，保留不可变的历史归属关系。

**升级前先备份数据库，并单独保存原 `PERPAY_MASTER_KEY`。回退到 1.0.0-alpha.2 或其他仅支持 schema 37 及以下的构建，必须恢复对应升级前备份及原主密钥，不能直接用旧程序打开升级后的数据库。** `app`、`backup`、`maintenance` 三个服务须使用同一版本。

如果未发布的 schema 37 构建已经因删除账号而破坏归属关联，升级前的完整性检查仍会拒绝该数据库。应先保留现状，从删除前通过验证的备份及原主密钥恢复，再升级；本版不会绕过检查或重建缺失的账号证据。

预发布镜像固定为 `ghcr.io/mashiro0619/perpay:1.0.0-rc.1`，不会覆盖稳定版 `latest`，也不会自动跟随下一版 RC。

完整升级步骤、数据库兼容范围及恢复方法见[维护说明](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.1/docs/maintenance.md#固定版本与回滚)。
