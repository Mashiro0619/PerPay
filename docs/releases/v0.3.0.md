# PerPay 0.3.0

相较于 0.2.2，本版重新整理管理后台、收银台、首次配置和密钥维护流程，改进记录查询、人工核账，以及操作失败后的继续处理方式。0.3.0-alpha.1 用户升级时也会执行数据库迁移。

## 更新内容

### 管理后台与公开收银台

- 后台统一使用 shadcn/ui，整理侧栏、设置、列表和弹窗，改善手机、主题切换和键盘操作。
- 收款概览支持面积、柱状和折线图，完整显示金额，每日数据可分页查看。
- 订单详情集中展示确认收款所用的记录、关联流水、异常与通知，并可打开订单原收银台。
- 收银台采用桌面双栏和手机单栏，支持二维码放大、保存及状态查询；可关闭商品名显示。
- 付款区域尚未加载、脚本执行失败或订单已过期时，不显示付款入口。页面保留不依赖脚本的刷新链接，恢复后重新检查付款期限。

### 五步配置与密钥维护

- 向导分为应用公钥、支付宝接入、经营码、通知与备份、收款检查。切换步骤时保留尚未保存的填写内容。
- API 凭证位于当时的“实例设置 → 密钥与安全”。业务端单独配置客户端 ID 和签名密钥。
- 账号已准备好收款时，管理员即使还没有配置 API 密钥，也可创建测试订单；该订单接收真实付款。
- 应用换钥先生成待启用密钥，上传应用公钥并重新填写支付宝公钥，查账验签成功后再切换。
- 通知签名密钥支持轮换，业务端同步更新验签配置；请求结果未知时先核查原操作。
- “收银台结束后查询期”控制公开链接结束后继续读取状态的时长，付款截止时间及后台查账独立处理，修改仅影响新订单。

### 查询、人工核账与安全检查

- 订单、通知、关联、冲突、异常和待处理列表支持搜索、排序、分页和选择显示哪些列；从详情返回时保留原来的列表位置。
- 人工关联可查看推荐的匹配记录或自行搜索，确认前重新读取选中的订单和流水；本版允许不填写人工关联理由。
- 提醒可按筛选跨页忽略和单条恢复，原冲突及通知重试继续处理。
- 完善停服重设管理员密码、请求响应迟到，以及密钥轮换超时后继续操作的流程。创建测试订单时，读取请求体后会再次检查管理员登录状态。
- 已有结束订单时，先完成原账号对应时段的查账和对账，再更换支付宝账号；即使暂时还没查到该账号的流水，也要完成这些检查。

### 更新通道与默认配置

- 正式版只提醒正式版更新，预发布版同时提醒正式版和预发布版更新；版本比较遵循 SemVer。
- 新实例默认每 60 秒进行常规查账，每 8 秒进行活跃查账，查账结果有效时限为 120 秒；已有配置保留。

## 兼容性与数据库迁移

本版的数据库结构版本（schema）为 **29**，兼容范围为 **24—29**。应用启动时迁移旧数据库；备份、恢复等维护工具只处理自己支持的结构版本。

| 起点 | 应用的迁移 |
| --- | --- |
| 0.2.2 / 结构版本 23 | 24—29 |
| 0.3.0-alpha.1 / 结构版本 26 | 27—29 |

迁移增加显示设置、查询索引、可选人工关联理由、应用密钥变更历史，并分离 API 客户端身份与凭证。已有订单、流水、密钥、管理员和配置保留。

业务订单与通知协议保持不变，公开查询期仍使用 `checkout_terminal_observation_seconds`。历史 `REFUND_UPDATED` 通知继续按原有规则处理；新退款标记记录管理员在支付宝完成的退款。

## 升级与回滚

1. 使用原版本备份数据库，另存原主密钥和部署配置。
2. 将三个服务统一设为 `ghcr.io/mashiro0619/perpay:0.3.0`，在原部署目录执行：

   ```sh
   docker compose pull
   docker compose stop app backup
   docker compose up -d
   ```

3. 检查迁移、查账、自动确认及备份。完成一笔小额付款，确认业务网站已收到并处理通知，再恢复正式收款。

回退到只支持结构版本 26 的 Alpha 或更旧版本，需恢复对应升级前备份和原主密钥。已有新增交易时，先保存当前完整数据；不能通过修改结构版本号降级。
