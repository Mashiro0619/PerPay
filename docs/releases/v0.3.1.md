# PerPay 0.3.1

本版在 0.3.0 基础上增加日期筛选、CSV 导出、系统名称和商家帮助链接，并统一后台布局与操作反馈。

## 主要变化

- 可自定义系统名称，为收银台配置商家帮助链接；未配置时不显示入口。
- 收银台按当前付款状态提供返回商家入口，由顾客点击后返回。业务网站需要查单或验证付款通知的签名，不能仅凭顾客跳回商家页面就认定付款完成。
- 订单和通知按北京时间的创建日期筛选，订单列表显示 PerPay 的付款确认时间。
- CSV 按当前筛选和排序导出订单，最多 10,000 条、跨度 366 天。导出期间固定所读取的数据，文件带 UTF-8 BOM，并防止单元格内容被表格软件当作公式执行；文件不包含密钥或可直接打开收银台的访问链接。
- 首页集中今日指标、待处理与最近订单，图表和每日数据同区切换。
- 后台支持收缩/全屏布局，默认内容最大宽度 1280px，偏好保存在当前浏览器。
- 表单、确认和技术详情使用一致的弹窗；刷新中、没有数据、危险操作和操作成功都有对应提示。
- 配置表单用时间单位显示参数，原有数值不会因换算丢失精度；同时改进配置向导、备份状态说明和通知失败后的处理。

## 数据库与兼容性

本版的数据库结构版本（schema）为 **31**，兼容范围为 **24—31**。

- 从 0.3.0 升级执行迁移 30—31，增加系统名称（默认 PerPay）和帮助链接（默认空）。从 0.2.2 或 Alpha 升级会先应用所缺迁移。
- 旧请求省略帮助链接时保留原配置，传 `null` 清除；无日期参数的列表调用继续可用。
- 原订单、流水、管理员、密钥和查账配置保留，付款确认及通知签名协议保持不变。
- `notify_url` 为服务端通知地址，`return_url` 为浏览器返回地址，各自独立保存和使用。

## 升级与回滚

1. 使用原版本备份数据库，另存原主密钥和部署配置。
2. 将三个服务统一设为 `ghcr.io/mashiro0619/perpay:0.3.1`，在原部署目录执行：

   ```sh
   docker compose pull
   docker compose stop app backup
   docker compose up -d
   docker compose logs --tail=100 app backup
   ```

3. 核对迁移、后台配置、收银台和备份。恢复正式收款前，完成一笔实际付款，并确认业务网站已收到和处理通知。

回退到 0.3.0（结构版本上限 29）或 Alpha（上限 26），需恢复兼容的升级前备份和原主密钥。升级后已有新交易时，先保留当前完整数据。
