## 预发布提示

**这是 0.3.0 的首个 Alpha 预发布版本，建议先在测试实例验证，不建议直接用于生产收款。**

本版相对 **0.2.2**，主要更新管理后台、公开收银台、查询与人工核账体验，并加入预发布版本更新支持。此次发布不会覆盖稳定版 `latest`，运行正式版的实例也不会收到 Alpha 更新提示。

## 更新内容

### 管理后台与收银台

- 管理后台统一采用 shadcn/ui 组件，重新整理侧栏、设置分类、表格和弹窗；支持浅色、深色及跟随系统，改善手机布局、键盘操作与焦点回归。
- 收款概览支持面积图、柱状图和折线图，汇总指标可直接切换；每日数据直接展示并分页。修复金额数字内部滚动及窄屏溢出，完整数值不缩写。
- 订单详情集中展示付款依据、关联流水、异常及通知结果；通知投递尝试直接展示并分页，原始报文和内部字段仍按需查看。
- 重整公开收银台，改善桌面信息布局、扫码金额展示、二维码放大与保存体验，并保留付款状态、暂停收款和订单失效时的提示。
- 新增实例级显示设置：可关闭收银台商品名称展示，并保存首页图表样式。商品名称默认显示，图表默认采用面积图；显示设置不改变订单或通知内容。

### 查询与人工核账

- 订单、业务通知、支付关联、账本冲突、账务异常和待处理事项支持服务端搜索与排序，不再局限于当前页；列表统一筛选、游标分页和列显示操作，并保留查询条件与返回位置。
- 人工关联改为“推荐候选＋搜索选择”，不再要求手动寻找内部编号。支持从订单选流水、从流水选订单，以及从对账页逐步选择双方记录。
- 推荐候选优先展示同金额、匹配时间窗口重叠的记录；选择后重新读取双方证据，仍需管理员核对、填写理由并确认，不自动关联。
- 冲突详情将字段、传入记录、已有流水和差异独立展示；手机逐字段上下对照。异常金额原值、毫秒精度、长编号和多行备注均保留。
- 待处理事项可按当前筛选范围跨页忽略提醒；改善已忽略状态同步、逐条恢复和处理中断后的继续操作。

### 运行提示与操作恢复

- 非阻断提醒移至侧栏轻提示，首页不再堆叠整块运行告警；暂停收款、数据库异常和状态无法确认等情况仍明确展示。
- 区分运行故障与业务待处理，冲突和失败事项继续显示计数与处理入口，但不再仅因积压就将正常运行的采集标成故障。
- 完善首次初始化、未保存表单、测试收款、退款标记及人工关联的恢复流程。提交结果未知时保留原对象和操作编号，避免换记录后重复执行。
- 新部署的数据库初始值与后台表单统一为：**常规采集 60 秒、活跃采集 8 秒、采集有效时限 120 秒**。已有实例保存的配置不被覆盖。

### 预发布版本与更新

- 支持 `-alpha.1`、`-beta.1`、`-rc.1` 等版本，按 SemVer 优先级比较，例如 `rc.2 < rc.10 < 同版本正式版`。
- 正式版只检查正式版；预发布版同时检查正式版和预发布版。仅提示可用更新，不自动安装；检查失败不会显示成“已是最新”。
- 预发布镜像使用固定版本标签，GitHub Release 标记为预发布，不修改镜像或 GitHub 的 `latest`。
- 预发布 Release 的 Compose 附件固定到对应版本，后续 Alpha／Beta／RC 升级需主动修改三个服务的镜像版本。

## 兼容性与数据安全

- 数据库最新结构为 **schema 26**，本版应用及维护工具的兼容范围为 **24—26**。从 0.2.2 的 schema 23 升级时，应用启动会自动执行迁移 24—26。
- 迁移 24 增加显示设置，迁移 25—26 增加后台查询索引；不重写历史订单金额、流水证据或既有财务记录，也不重置管理员与已保存的收款配置。
- 新增管理员只读候选查询接口，并扩展后台列表查询参数；业务网站的订单与通知接入流程保持原有方式。现有鉴权、CSRF、事务校验和幂等保护继续生效。
- 推荐候选不等于付款确认，金额推断不等于支付宝按商户订单号确认。忽略提醒不解决原问题，管理员退款标记也不会执行转账或通知业务网站。
- 预发布仍需真实部署环境验证；本版不支持以 `+build` 元数据作为发布版本标签。

## 试用与升级

**本版为预发布版本，请先备份并在测试实例验证，再决定是否升级。**

1. 先备份数据库及 `perpay-secrets` 主密钥卷，保留原数据卷。建议先在隔离测试实例验证；不要让测试实例使用真实支付宝采集和通知发送配置。
2. 已有部署在原 Compose 文件中，将 `app`、`backup`、`maintenance` 的镜像统一改为：

   `ghcr.io/mashiro0619/perpay:0.3.0-alpha.1`

   不要直接用下载的模板覆盖现有域名、代理或数据卷配置。
3. 在原部署目录执行：

   ```sh
   docker compose pull
   docker compose up -d
   ```

4. 登录后台，确认版本、原账号与配置、历史订单以及运行状态；开始收款前再次核对采集和自动确认是否就绪。

**不能把已经升级至 schema 26 的数据库直接交给 0.2.2 使用。** 如需回退，必须核对目标版本兼容性及对应备份；若升级后已经产生新交易，不能直接覆盖为旧备份，否则会丢失之后的记录。请先保留当前完整数据库和主密钥，再按维护流程处理。
