# PerPay 文案术语表（v1.0）

> 状态：v1.0（2026-10-18 定稿）。术语已确认；执行中遇到表外新词先问，不要自创。
> 用途：界面、文档、API 描述、错误信息共用一套词；一个概念只用一个词。
> 配套：[接入说明](../USAGE.md) · [支付宝配置](alipay-setup.md)。

## 使用规则

1. 一个概念一个词，不写同义词。
2. 界面用白话；文档首次出现给一句定义，之后直接用。
3. 数字与单位之间加空格：5 秒、10 MB、100 条。
4. 中文与行内代码之间加空格：`client_id` 字段。
5. 按钮用动词，标题用名词；状态标签不超过 6 个字。
6. 不在界面暴露内部 ID、错误码、表名、字段名；统一放「技术详情」。
7. 危险操作才用警告；普通说明不用「禁止 / 不得 / 不要」。

## 数据来源

界面和文档里同时出现三类数据，**必须标来源**：

| 来源 | 典型字段 | 标注方式 |
| --- | --- | --- |
| 支付宝 | 支付宝订单号、支付宝交易时间、支付宝交易金额、支付宝交易对方、支付宝交易备注、支付宝商户单号、收支方向、经营码、App ID、支付宝公钥 | 字段名带「支付宝」，或放在「支付宝流水」分组下 |
| PerPay | 内部订单编号、应付金额、加价金额、收款关联、确认状态、PerPay 确认时间、收银台状态、通知投递、异常与冲突 | 不借用支付宝的词；判断类文案写清依据 |
| 业务网站 | 商户订单号、商品名称、订单备注、通知地址、返回地址 | 字段名带「商户」或「商品」，不叫「订单号」 |

三条硬规则：

1. 同一屏出现两个来源，必须有分组标题或字段前缀。
2. 支付宝原始字段一律带「支付宝」前缀；不要用「流水商户单号」这种半前缀。
3. PerPay 的判断要带依据：自动关联写「PerPay 按金额和付款时间推断」，人工关联写「管理员人工关联」。

### 字段来源速查

**金额**

| 界面叫法 | 字段 | 来源 | 说明 |
| --- | --- | --- | --- |
| 下单金额 | `requested_amount_cents` | 业务网站 | 商户下单时提交 |
| 加价金额 | `payable - requested` | PerPay | 为区分订单加的小额 |
| 应付金额 | `payable_amount_cents` | PerPay | 下单金额 + 加价金额 |
| 支付宝交易金额 | `ledger.amount_cents` | 支付宝 | 账单原始金额 |
| 实收金额 | `received_amount_cents` | 支付宝 → PerPay | 关联成功时从流水记到订单 |
| 确认金额（统计） | `SUM(received)` | PerPay | 按确认时间汇总，不是支付宝账单合计 |

**时间**

| 界面叫法 | 字段 | 来源 |
| --- | --- | --- |
| 创建时间 | `created_at` | PerPay |
| 收银台有效期至 | `expires_at` | PerPay |
| 支付宝交易时间 | `occurred_at` | 支付宝 |
| PerPay 确认时间 | `PAYMENT_CONFIRMED.occurred_at` | PerPay |
| 撤销时间 | `payment_match.resolved_at` | PerPay |
| 发现时间 | `exception/conflict.created_at` | PerPay |
| 下次重试 | `next_attempt_at` | PerPay |

**编号**

| 界面叫法 | 字段 | 来源 |
| --- | --- | --- |
| 内部订单编号 | `order_id` | PerPay |
| 商户订单号 | `merchant_order_no` | 业务网站 |
| 支付宝订单号 | `alipay_order_no` / `provider_order_no` | 支付宝 |
| 支付宝流水号 | `external_event_id` | 支付宝 |
| 支付宝商户单号 | `ledger.merchant_order_no` | 支付宝 |
| 客户端 ID | `api_client_id` | PerPay |
| 操作编号 | `operation_id` | PerPay |

**状态**

| 界面叫法 | 字段 | 来源 |
| --- | --- | --- |
| 待付款 / 收款已确认 / 收款有争议 | `payment_status` | PerPay 判断 |
| 开放中 / 已关闭 / 已过期 | `checkout_status` | PerPay |
| 未分配 / 有候选 / 已分配 / 冲突 / 隔离 / 忽略 | `ledger.state` | PerPay 对流水的处理状态 |
| 待处理 / 已处理 / 已忽略 | 异常、冲突、提醒状态 | PerPay |
| 等待投递 / 已停止重试 | 通知投递状态 | PerPay |

> 注意：`ledger.state` 不是支付宝的状态，而是 PerPay 拿到流水后的处理状态。

### 状态由谁改变

| 状态 | 谁改 | 依据 |
| --- | --- | --- |
| 待付款 → 收款已确认 | PerPay 自动 / 管理员 | 金额 + 时间推断 / 人工关联 |
| 收款已确认 → 收款有争议 | 管理员 | 撤销收款关联 |
| 开放中 → 已关闭 | 管理员 / PerPay | 手动关闭 / 订单取消 |
| 开放中 → 已过期 | PerPay | 收银台到期 |
| 流水：未分配 / 有候选 / 已分配 / 冲突 / 隔离 / 忽略 | PerPay | 匹配与异常处理 |
| 通知：等待投递 / 等待重试 / 已停止重试 | PerPay | 投递结果 |
| 退款标记 | 管理员 | 外部退款声明，PerPay 不验证 |

> 支付宝提供账单流水和响应签名，PerPay 在本地验证签名。

### 数据新鲜度

同一屏里的数据，时间口径可能不同：

| 数据 | 新鲜度 | 展示要求 |
| --- | --- | --- |
| PerPay 订单状态、收银台状态 | 即时（本地写入） | 可直接显示 |
| 支付宝流水、实收金额、确认金额 | 有延迟：查账间隔 + 查账延迟 | 只能写「最近查账成功：HH:mm」 |
| 通知投递状态 | 即时 | 可直接显示 |
| 备份、运行状态 | 即时 | 显示「更新于」 |

规则：**凡是来自支付宝的数字，不能让人以为是实时余额。**

两个时间不要混：

- **最近查账成功**：`SystemStatus.ledger.last_success_at`，只说明任务成功过。
- **数据截至**：账单实际覆盖到的时刻。查账窗口终点是「当前时间 − 查账延迟」，所以成功时间 ≠ 数据截至。没有覆盖窗口终点时，不要写「数据截至」。

## 收款与订单

| 术语 | 定义 | 不要这样说 |
| --- | --- | --- |
| 下单金额 | 商户创建订单时提交的金额 | 原始金额、订单金额、`requested_amount` |
| 加价金额 | 为了让每笔订单的应付金额不同，在下单金额上增加的小额（0.01–0.99 元） | 尾差、金额尾差、金额尾数 |
| 应付金额 | 下单金额 + 加价金额，付款人实际要付的金额 | 实付金额、应收金额 |
| 实收金额 | 支付宝流水实际到账的金额 | 到账金额、收款金额 |
| 收款确认笔数 | 统计区间内确认收款的次数，含自动和人工；不等于当前已确认订单数 | 确认笔数（图例可用「确认次数」）、成交笔数 |
| 收款关联 | 把一笔支付宝流水与一个订单建立的关系 | 支付关联、收款依据、匹配 |
| 自动确认收款 | 系统按金额和付款时间自动找到唯一订单并确认收款 | 自动对账、自动匹配 |
| 自动推断 | PerPay 按金额和付款时间匹配到唯一订单 | 推断、猜测、系统确认 |
| 人工关联 | 管理员手动把流水与订单关联 | 手动确认、人工确认（易与通知 ACK 混） |
| 收银台 | 付款人扫码付款的页面 | 支付页、付款页 |
| 经营码 | 支付宝的商家收款码（首次写「支付宝经营码」） | 收款码、经营收款码 |
| 支付宝订单号 | 支付宝账单里的交易号 | 订单号、交易号 |
| 支付宝交易时间 | 支付宝账单里的交易发生时间 | 交易时间、付款时间 |
| 支付宝商户单号 | 支付宝账单里可能带的商户单号字段，**不等于**业务网站的商户订单号 | 流水商户单号、商户订单号 |
| 商户订单号 | 业务网站自己的订单号 | 订单号、商户单号 |
| 内部订单编号 | PerPay 生成的订单 ID | 订单号、内部单号 |
| PerPay 确认时间 | PerPay 记录付款确认事件的时间 | 交易时间、到账时间 |

## 待处理

| 术语 | 定义 | 不要这样说 |
| --- | --- | --- |
| 待处理 | 需要管理员处理的提醒集合 | 待办、全局待办、事项、工作项 |
| 提醒 | 待处理列表里的一条 | 事项、工作项 |
| 忽略提醒 | 只关闭提醒，不改变数据状态 | 忽略事项 |
| 已忽略 | 提醒被关闭 | 已隔离 |
| 恢复提醒 | 重新打开已关闭的提醒 | 恢复事项 |

## 对账与异常

| 术语 | 定义 | 不要这样说 |
| --- | --- | --- |
| 对账 | 核对支付宝流水与订单的页面和动作 | 共享账本、对账证据、账本与对账 |
| 查账 | 定时调用支付宝账单接口拉取流水 | 采集、补采（文档可写「采集（查账）」） |
| 流水 | 一条支付宝交易记录 | 账本、账务流水、记账分录 |
| 可能匹配的记录 | 系统按金额和时间推测、还没确认的配对记录；界面按方向分别叫「可能匹配的流水」或「可能匹配的订单」 | 候选、匹配候选、金额推断候选 |
| 账务异常 | 需要人工处理的收款问题（金额不符、多候选、收银台结束后付款等） | 资金异常、财务异常 |
| 账本冲突 | 同一笔流水出现两份不一致记录 | 共享冲突 |
| 已隔离 | 数据不可信、不能参与收款匹配 | 已忽略 |
| 金额占用时间 | 订单占用某个应付金额的起止时间 | 金额占用窗口 |

> **为什么不是「可能匹配的流水」：** 候选可能是流水（给订单找流水），也可能是订单（给流水找订单）。总称用「可能匹配的记录」，界面按方向分别写成「可能匹配的流水」或「可能匹配的订单」。

## 通知

| 术语 | 定义 | 不要这样说 |
| --- | --- | --- |
| 通知 | PerPay 向业务网站发送付款事件的回调 | 业务通知（页面标题除外）、消息 |

## 时间与金额

| 术语 | 定义 | 不要这样说 |
| --- | --- | --- |
| 收银台有效期 | 订单可付款的时间段 | 付款截止、订单有效期 |

## 状态词

> 以下状态都是 **PerPay 的判断**，不是支付宝返回的状态；推断得出的要写明「按金额和付款时间推断」。

| 场景 | 用 | 不用 |
| --- | --- | --- |
| 订单未付款 | 待付款 | 未付款、UNPAID |
| 订单已收款 | 收款已确认 | 已确认、CONFIRMED |
| 订单有争议 | 后台：收款有争议；收银台：付款待核实 | 需核对、DISPUTED |
| 待办事项 | 待处理 | 未忽略、OPEN |
| 已处理 | 已处理 | RESOLVED |
| 提醒已关闭 | 已忽略 | IGNORED、已隔离 |
| 数据不可信 | 已隔离 | ISOLATED、已忽略 |
| 关联已撤销 | 已撤销 | REVERSED |

## 写文案时的三个检查

1. **这句话里的名词，术语表里有吗？** 没有就补定义，不要造新词。
2. **这句能不能拆成两句？** 一句话里超过两个条件，就拆。
3. **否定词能不能换成正面说法？** 「不是…也不是…」改成「它是什么」。
