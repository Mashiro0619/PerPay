# PerPay 文案与字段术语表

后台 UI、公开收银台、文档、OpenAPI 描述与错误消息统一遵循本词典，确保每个名称能清晰表达**数据来源**、**当前状态**与**可执行动作**。

配套文档：[接口与运维参考](../USAGE.md) · [支付宝配置](alipay-setup.md) · [前端开发](../web/README.md)

## 写作与命名规范

1. **一词一义**：同一概念全站使用同一术语；文档首次出现附简短定义，后文直接复用。
2. **词性分离**：操作按钮用动词，标题与字段用名词；状态标签保持简短，解释性原因放在紧邻副文案。
3. **排版格式**：数字与单位间留空格（`5 秒`、`10 MB`、`100 条`）；中文与行内代码间留空格。
4. **来源与技术信息分层**：同屏混排多方数据时通过分组标题或字段前缀显式标明来源；完整业务单号必带复制按钮；错误码、表名、校验指纹归入技术细节折叠区。
5. **后果与依据透明**：会修改数据、密钥或账务结果的操作须明确写出影响；呈现状态判断时须写明判定依据。

## 数据来源标注

| 来源 | 典型字段 | UI / 文档标注约束 |
| --- | --- | --- |
| 支付宝 | 订单号、流水号、交易时间、交易金额、交易对方、交易备注、商户单号、App ID、公钥 | 字段加“支付宝”前缀，或置于明确标示“支付宝流水”的区块 |
| PerPay | 内部编号、应付金额、加价金额、收款关联、确认时间、收银台状态、通知与异常 | 标明由 PerPay 生成或判定；自动关联统一标注 `PerPay 按金额和付款时间推断`，人工关联标注 `管理员人工关联` |
| 业务网站 | 商户订单号、商品名称、订单备注、通知地址、返回地址 | 使用“商户”“商品”等前缀，避免与支付宝账单同名字段混淆 |

## 字段映射速查

### 金额字段

| 规范名称 | 对应字段 / 计算公式 | 语义边界 |
| --- | --- | --- |
| 下单金额 | `requested_amount_cents` | 业务网站下单提交的商品原价 |
| 加价金额 | `payable - requested` | PerPay 为区分唯一应付金额叠加的小额增量（0.01–0.99 元） |
| 应付金额 | `payable_amount_cents` | `下单金额 + 加价金额`，付款人实际需扫码支付的金额 |
| 支付宝交易金额 | `ledger.amount_cents` | 支付宝账单返回的原始入账金额 |
| 实收金额 | `received_amount_cents` | 从收款关联记入订单的实际收款金额 |
| 确认金额（统计） | 按确认时间汇总 `received_amount_cents` | 所选时段内每次收款确认事件金额之和；撤销后重新确认会再次计入 |
| 易支付金额 | `money` | 以元为单位的两位小数字符串，表示**下单金额**（不含加价） |

### 时间字段

| 规范名称 | 对应字段 | 来源 |
| --- | --- | --- |
| 创建时间 | `created_at` | PerPay |
| 收银台有效期至 | `expires_at` | PerPay |
| 支付宝交易时间 | `occurred_at` | 支付宝 |
| PerPay 确认时间 | `PAYMENT_CONFIRMED.occurred_at` | PerPay 记录确认事件的时间 |
| 通知确认时间 | `acknowledged_at` | PerPay 收到有效协议回执的时间（UI 须在下方注明不代表下游已发货） |
| 撤销时间 | `payment_match.resolved_at` | PerPay |
| 发现时间 | `exception/conflict.created_at` | PerPay |
| 下次重试 | `next_attempt_at` | PerPay 调度下次通知投递的时间 |

> **说明**：`acknowledged_at`（通知确认时间）仅证明 PerPay 收到符合协议要求的 HTTP 回执；发货、充值或服务开通是否完成由业务网站独立记录。

### 标识符字段

| 规范名称 | 对应字段 | 来源与用途 |
| --- | --- | --- |
| 内部订单编号 | `order_id` | PerPay 生成 |
| 内部流水编号（PerPay） | `ledger_entry_id` | PerPay 为本地采集账本记录生成 |
| 商户订单号 | `merchant_order_no` | 业务网站生成（关联视图中标作“关联商户订单号（业务网站）”） |
| 支付宝订单号 | `alipay_order_no` / `provider_order_no` | 支付宝交易号 |
| 支付宝流水号 | `external_event_id` | 支付宝账单唯一记录编号 |
| 支付宝商户单号 | `ledger.merchant_order_no` | 支付宝账单附带的商户单号 |
| 网站编号 | 网站 `client_id`、订单/通知 `api_client_id`、业务状态 `site_id` | PerPay 不可变内部站点标识，用于管理路由及归属过滤 |
| 客户端 ID | 网站 `api_client_id`、业务状态 `client_id` | 业务 API 对外接入标识，支持轮换 |
| 收款账号编号 | `alipay_account_id` | PerPay 为收款账号分配的不可变内部 ID |
| 查账来源 | `provider_account_key` | 区分不同支付宝应用配置及其采集的流水 |
| 操作编号 | `operation_id` | 写操作幂等键，重试沿用原值防重复执行（管理端通常自动生成） |

> **注意**：“商户订单号”“支付宝订单号”“内部订单编号”三者严禁统一简称为“订单号”。无值时留空；多编号并列时逐一标出全称。

### 状态机与状态变迁

| 状态对象 | 合法状态集 | 说明 |
| --- | --- | --- |
| 订单收款状态 | `待付款` / `收款已确认` / `收款有争议`（收银台称 `付款待核实`） | PerPay 基于收款关联维护的账务状态 |
| 收银台状态 | `开放中` / `已关闭` / `已过期` | 收银台当前是否仍接受付款 |
| 流水处理状态 | `可匹配` / `已关联` / `已隔离` 等 | PerPay 对采集流水的处理态（不改变原始支付宝交易字段来源） |
| 待处理提醒 | `待处理` / `已处理` / `已忽略` | 异常、冲突、通知失败等提醒的处理进度 |
| 通知投递任务 | `等待投递` / `等待重试` / `通知已确认` / `已停止重试` / `已终止` | 发送队列与回执状态 |

| 状态变迁 | 触发方 | 判定依据 |
| --- | --- | --- |
| `待付款` → `收款已确认` | 自动对账 / 管理员人工关联 | 金额、付款时间、来源账号及关联记录 |
| `收款已确认` → `收款有争议` | 收款关联撤销流程 | 撤销记录与原因 |
| `开放中` → `已关闭` | 管理员 / 业务取消接口 | 关闭操作 |
| `开放中` → `已过期` | PerPay | `expires_at` 收银台有效期 |
| 流水处理状态变化 | 对账与异常处理 | 候选、关联、隔离等记录 |
| 通知任务状态变化 | 通知 Worker / 管理员重发 | 投递响应、有效回执、人工重发记录 |
| 退款标记变化 | 管理员 | 在 PerPay 之外完成退款的声明（不涉及外部验证） |

### 数据新鲜度与查账口径

UI 呈现的是最近一次接口读取到的快照；标注时间时必须区分 **PerPay 落库时间**、**支付宝交易时间**与**任务计划时间**。

| 数据类别 | 更新机制 |
| --- | --- |
| 订单与收银台状态 | PerPay 本地持久化，展示最近一次接口返回态 |
| 支付宝流水与实收金额 | 经定时查账与对账产生，存在查账间隔与查账延迟（**严禁标作实时余额**） |
| 通知发送状态 | 最近记录的投递或回执快照 |
| 备份与运行状态 | 最近读取的任务状态及对应更新时间 |

- **最近查账成功**（`SystemStatus.ledger.last_success_at`）：最近一轮覆盖完目标时间窗口的**正常查账开始时间**；判断时效时计入查询自身耗时。**历史补扫成功不更新此字段**。
- **数据截至**：已完成正常查账的最晚时间边界；因查账延迟通常早于当前墙上时间。
- **历史补扫中**：后台正在补采更早区间的流水。若近期正常窗口已查完且结果仍在有效期内，账号继续接单；若首次正常查账未完成、近期窗口落后、查账报错或结果过期，则自动暂停该账号接单。

## 分域术语表

### 收款与订单

| 术语 | 定义 |
| --- | --- |
| 收款确认笔数 | 时段内的收款确认事件总数（含自动与人工确认，按确认事件统计） |
| 收款关联 | 一条支付宝流水与一笔 PerPay 订单的绑定关系 |
| 自动确认收款 | 按金额、付款时间与来源账号锁定唯一可确认订单并自动建立关联 |
| 自动推断 / 人工关联 | 关联来源标注：系统推断 vs 管理员核对后手动绑定 |
| 收银台 | 供付款人扫码付款与查询状态的公开页面 |
| 收款码 | 支付宝收款二维码（经营码为其中一种形式） |
| 历史退款记录 | 旧版本保留的退款记录，与管理员外部退款标记分栏展示 |

### 待处理与对账异常

| 术语 | 定义 |
| --- | --- |
| 待处理 / 提醒 | 需管理员处置的账务异常、账本冲突与通知失败入口 |
| 忽略提醒 / 已忽略 / 恢复提醒 | 关闭或重新打开提醒本身，保留原业务记录；**不替代**关联、退款或重发通知 |
| 对账 / 查账 / 流水 | 核对流程 / 调用支付宝账单接口拉取 / 单条支付宝交易记录 |
| 可能匹配的记录 | 待人工核对的候选对（按视角标作“可能匹配的流水”或“可能匹配的订单”） |
| 账务异常 | 金额不符、多订单歧义、超时后付款等无法自动确认的账务问题 |
| 账本冲突 | 同一笔流水出现互相矛盾的来源记录 |
| 已隔离 | 数据被移出正常自动对账候选集 |
| 金额占用时间 | 订单锁定完整应付金额的起止区间 |
| 应付金额复用等待 | 收银台关闭或过期后，该完整应付金额重新进入分配池前的冷却时间（自实际关闭或原到期时间起算） |

### 通知

| 术语 | 定义 |
| --- | --- |
| 通知 / 回调通知 | PerPay 向业务网站推送付款事件的 HTTP 请求（首次说明可括注 webhook） |
| 通知签名密钥 | 原生协议下 PerPay 与业务端共享的验签密钥（易支付改用各自商户/平台密钥） |
| 投递 | 单个事件的一次通知任务，失败时可在同一任务内退避重试 |
| 通知已确认 | PerPay 收到符合协议规范的成功回执 |
| 重新发送 | 管理员为同一事件新建独立投递任务（保留原记录与重发原因） |
| 已停止重试 | 当前投递任务耗尽重试或触发停止条件，需人工介入核查 |
| 已终止 | 原收款确认已撤销，对应旧成功通知停止投递且禁止重发 |

> **说明**：通知类型与商品名称须分开展示，金额保留“应付 / 实收”标签。收到回执后永久保留该记录；若后续撤销收款确认，须在同屏说明最新收款状态，避免误读旧回执。

### 网站、系统与时间/金额单位

| 术语 | 定义 |
| --- | --- |
| 系统 / 本系统 | UI 中指当前这套 PerPay 服务 |
| 实例 | 部署/运维文档中指一套独立运行的 PerPay 部署 |
| 业务网站 / 全局 / 本站 | 接入的一个自有站点 / 跨全部站点视图 / 当前所选站点视图 |
| PID | 易支付协议下的不可变数字商户号 |
| 系统设置 / 网站设置 | 全局级配置 / 单站点级配置 |
| 已暂停接收新订单 | 当前站点拒绝新建订单，已有订单与查账任务不受影响 |
| 任务最近成功 | 正常查账显示该轮**开始**查询时间；其余任务显示**完成**时间 |
| 收银台有效期 / 结束后可查询时长 | 允许付款的窗口 / 关闭或过期后公开收银台仍可查询的宽限期 |
| 查账延迟 / 查账有效时限 | 暂缓采集最近几秒以等账单稳定 / 正常查账结果的最长有效时长（自该轮开始计时，超时暂停该账号接单与未付收银台，站点按路由规则改派其他健康账号） |
| 金额单位 | UI 展示用**元**；原生 API 用整数**分**（`_cents`）；易支付 `money` 用两位小数**元**字符串 |

### 密钥与外部退款标记

| 术语 | 用途 |
| --- | --- |
| 支付宝应用密钥对（应用公钥 / 应用私钥） | 应用公钥上传支付宝开放平台；应用私钥由 PerPay 加密保存用于请求签名 |
| 支付宝公钥 | 从支付宝平台获取，用于验证支付宝响应（与易支付平台公钥分属不同协议） |
| V1 商户密钥 | 易支付 V1 请求与回调共享密钥 |
| V2 商户私钥 / 公钥 | 商户用私钥签名请求，PerPay 用公钥验签 |
| V2 平台私钥 / 公钥 | PerPay 用私钥签名响应与回调，商户用公钥验签 |
| 退款标记（标记已退款 / 撤销标记） | 管理员声明已在 PerPay 之外完成退款；PerPay **不执行也不验证**外部退款 |

## 文案提交前自检

1. **映射一致**：术语与对应字段、来源和状态是否完全匹配本表。
2. **口径诚实**：结论对应的证据记录与时间区间是否清楚，断言强度是否未超出实际状态。
3. **指引可执行**：若需要用户干预，是否直接给出了下一步明确操作。
