# PerPay 文案术语表

界面、文档、OpenAPI 描述和错误信息使用下表中的名称。每个名称都应让读者看懂数据来自哪里、现在是什么状态、接下来能做什么。配套：[接入说明](../USAGE.md) · [支付宝配置](alipay-setup.md) · [前端开发](../web/README.md)。

## 使用规则

1. 同一概念使用同一名称。文档首次出现时给出简短定义，后文直接使用。
2. 按钮使用动词，标题和字段使用名词；状态标签简短，原因放在相邻说明中。
3. 数字与单位之间留空格，如 5 秒、10 MB、100 条；中文与行内代码之间留空格。
4. 同一屏出现多个来源时，用分组标题或字段前缀区分。完整业务编号保留复制入口；错误码、表名和校验指纹放在技术信息中。
5. 普通说明直接解释作用。操作会改变数据、密钥或付款结果时，说明具体后果；判断状态时，写清依据。

## 数据来源

| 来源 | 典型内容 | 推荐标注 |
| --- | --- | --- |
| 支付宝 | 订单号、流水号、交易时间、交易金额、交易对方、交易备注、商户单号、App ID、公钥 | 字段前加“支付宝”，或置于来源明确的支付宝流水分组 |
| PerPay | 内部编号、应付金额、加价金额、收款关联、确认时间、收银台状态、通知与异常 | 标明 PerPay 的记录或判断；自动关联注明金额和付款时间依据 |
| 业务网站 | 商户订单号、商品名称、订单备注、通知地址、返回地址 | 使用“商户”“商品”等名称，区分支付宝账单中的同名字段 |

自动关联的说明统一为“PerPay 按金额和付款时间推断”，人工关联使用“管理员人工关联”。

### 字段来源速查

**金额**

| 界面名称 | 字段或计算方式 | 含义 |
| --- | --- | --- |
| 下单金额 | `requested_amount_cents` | 业务网站提交的商品金额 |
| 加价金额 | `payable - requested` | PerPay 为区分应付金额分配的小额增量 |
| 应付金额 | `payable_amount_cents` | 下单金额加上加价金额，付款人应支付的金额 |
| 支付宝交易金额 | `ledger.amount_cents` | 支付宝账单中的金额 |
| 实收金额 | `received_amount_cents` | 从收款关联记入订单的实际金额 |
| 确认金额（统计） | 按确认时间汇总实收金额 | 选定时段内，每次收款确认记录的金额之和；撤销后重新确认会再次记入 |
| 易支付金额 | `money` | 以元表示的下单金额，不含 PerPay 加价 |

**时间**

| 界面名称 | 字段 | 来源 |
| --- | --- | --- |
| 创建时间 | `created_at` | PerPay |
| 收银台有效期至 | `expires_at` | PerPay |
| 支付宝交易时间 | `occurred_at` | 支付宝 |
| PerPay 确认时间 | `PAYMENT_CONFIRMED.occurred_at` | PerPay 记录确认事件的时间 |
| 通知确认时间（PerPay 记录） | `acknowledged_at` | PerPay 收到有效协议回执的时间 |
| 撤销时间 | `payment_match.resolved_at` | PerPay |
| 发现时间 | `exception/conflict.created_at` | PerPay |
| 下次重试 | `next_attempt_at` | PerPay 计划再次发送通知的时间 |

通知确认时间表示 PerPay 收到成功回执的时间。发货、充值或服务开通是否完成，以及完成时间，由业务网站记录。

**编号**

| 界面名称 | 字段 | 来源与用途 |
| --- | --- | --- |
| 内部订单编号 | `order_id` | PerPay 生成 |
| 内部流水编号（PerPay） | `ledger_entry_id` | PerPay 为本地采集记录生成 |
| 商户订单号 | `merchant_order_no` | 业务网站生成 |
| 支付宝订单号 | `alipay_order_no` / `provider_order_no` | 支付宝交易号 |
| 支付宝流水号 | `external_event_id` | 支付宝账单记录编号 |
| 支付宝商户单号 | `ledger.merchant_order_no` | 支付宝账单中的字段 |
| 网站编号 | 网站的 `client_id`、订单和通知归属的 `api_client_id`、业务状态的 `site_id` | PerPay 为网站保留的固定编号，用于管理路径，以及查找所属订单和通知 |
| 客户端 ID | 网站的 `api_client_id`、业务状态的 `client_id` | 业务接入标识，可在接入设置中更换 |
| 收款账号编号 | `alipay_account_id` | PerPay 为支付宝收款账号生成的固定编号 |
| 查账来源 | `provider_account_key` | 区分不同支付宝应用配置及其查到的流水 |
| 操作编号 | `operation_id` | 标记同一次操作，重试时沿用原编号以防重复执行；管理界面通常自动生成 |

关联记录中的业务单号标为“关联商户订单号（业务网站）”。支付宝账单中的同名字段使用“支付宝商户单号”。没有编号时显示为空，多个编号并列时分别标注名称。

**状态**

| 名称 | 状态对象 | 含义 |
| --- | --- | --- |
| 待付款 / 收款已确认 / 收款有争议 | 订单收款状态 | PerPay 根据收款关联记录的状态 |
| 开放中 / 已关闭 / 已过期 | 收银台状态 | 收银台是否已关闭或过期 |
| 可匹配 / 已关联 / 已隔离等 | 流水处理状态 | PerPay 对采集记录的处理 |
| 待处理 / 已处理 / 已忽略 | 异常、冲突和提醒 | 问题或提醒处理到了哪一步 |
| 等待投递 / 等待重试 / 通知已确认 / 已停止重试 | 通知发送任务 | 发送和回执结果 |

流水处理状态描述 PerPay 的处理，支付宝交易字段仍按原来源展示。

### 状态由谁改变

| 变化 | 触发方或流程 | 依据 |
| --- | --- | --- |
| 待付款 → 收款已确认 | 自动对账 / 管理员人工关联 | 金额、付款时间、来源及关联记录 |
| 收款已确认 → 收款有争议 | 收款关联撤销流程 | 撤销记录与原因 |
| 开放中 → 已关闭 | 管理员 / 业务取消流程 | 关闭操作 |
| 开放中 → 已过期 | PerPay | 收银台有效期 |
| 流水处理状态变化 | 对账与异常处理 | 候选、关联、隔离等记录 |
| 通知状态变化 | 通知发送任务 / 管理员重新发送 | 每次发送的结果、成功回执和后续重发记录 |
| 退款标记变化 | 管理员 | 在 PerPay 之外完成退款的声明 |

### 数据更新到什么时候

界面展示最近一次读取到的数据。说明更新时间时，要写清它是 PerPay 保存状态的时间、支付宝交易时间，还是任务计划执行的时间。

| 数据 | 何时更新 |
| --- | --- |
| 订单、收银台状态 | 由 PerPay 保存，界面显示最近一次接口返回的状态 |
| 支付宝流水、实收金额 | 查账取得的账单与收款关联，有查账间隔和查账延迟 |
| 通知发送状态 | 最近记录的发送或回执结果 |
| 备份和运行状态 | 最近读取的任务状态及对应更新时间 |

- **最近查账成功**：`SystemStatus.ledger.last_success_at` 记录最近一次查完目标时间段的正常查账开始时间。判断这次结果是否还有效时，也计算查询本身花费的时间。补查旧流水成功不会更新此值。
- **数据截至**：正常查账已经查完的最晚时刻，以已完成的查询记录为准。受查账延迟影响，它通常早于当前时间。
- **历史补扫中**：正在补查过去时间段的流水。最近应查的时间段已查完，且结果仍在有效期内时，该账号可以继续接单；首次正常查账尚未完成、近期流水没查完、查账出错或成功记录过期时，该账号仍会暂停接单。

支付宝流水及相关汇总按其账单和确认时间展示，不标作实时余额。

## 收款与订单

| 术语 | 定义 |
| --- | --- |
| 下单金额 | 商户创建订单时提交的金额 |
| 加价金额 | PerPay 为区分应付金额增加的小额，按网站上限在 0.01–0.99 元内分配 |
| 应付金额 | 下单金额 + 加价金额 |
| 实收金额 | 收款关联记录的实际金额 |
| 收款确认笔数 | 区间内的确认次数，包含自动和人工确认；按确认事件统计 |
| 收款关联 | 一笔支付宝流水与一个订单之间的关系 |
| 自动确认收款 | 按金额、付款时间和来源找到唯一可确认订单并建立关联 |
| 自动推断 | PerPay 按金额和付款时间推断的关联依据 |
| 人工关联 | 管理员核对后手动关联流水与订单 |
| 收银台 | 付款人扫码付款的页面 |
| 收款码 | 支付宝收款二维码，经营码是其中一种形式 |
| 历史退款记录 | 旧版本保存的退款记录，与管理员退款标记分别展示 |

“商户订单号”属于业务网站，“支付宝订单号”属于支付宝，“内部订单编号”由 PerPay 生成。三者使用完整名称，避免统一简称“订单号”。

## 待处理

| 术语 | 定义 |
| --- | --- |
| 待处理 | 需要管理员处理的账务异常、账本冲突和通知失败提醒 |
| 提醒 | 列表中的一条处理入口 |
| 忽略提醒 | 关闭该提醒，保留相关业务记录 |
| 已忽略 | 提醒已关闭 |
| 恢复提醒 | 重新打开已关闭的提醒 |

忽略提醒不会替代关联、退款或通知重发等业务操作。

## 对账与异常

| 术语 | 定义 |
| --- | --- |
| 对账 | 核对支付宝流水和订单的页面与处理流程 |
| 查账 | 调用支付宝账单接口取得流水 |
| 流水 | 一条支付宝交易记录 |
| 可能匹配的记录 | 尚待核对的配对记录；按方向显示“可能匹配的流水”或“可能匹配的订单” |
| 账务异常 | 金额不符、同时可能对应多个订单、收银台结束后付款等需要处理的收款问题 |
| 账本冲突 | 同一笔流水出现不一致的来源记录 |
| 已隔离 | 数据被排除在正常收款匹配之外 |
| 金额占用时间 | 订单占用完整应付金额的起止时间 |
| 应付金额复用等待 | 收银台关闭或过期后，该完整应付金额再次用于新订单前的等待时间 |

复用等待按实际关闭时间或原到期时间起算，作用于完整应付金额。

## 通知

| 术语 | 定义 |
| --- | --- |
| 通知 / 回调通知 | PerPay 向业务网站发送付款事件的请求；首次说明可括注 webhook |
| 通知签名密钥 | PerPay 和业务后端共同保存，业务后端用它验证原生通知的签名；易支付使用自己的商户或平台密钥 |
| 投递 | 某个事件的一次通知发送任务，失败后可以在同一任务内自动重试 |
| 通知已确认 | PerPay 收到符合协议要求的回执 |
| 重新发送 | 管理员为同一事件创建新的通知发送任务，原发送记录和重发理由都会保存 |
| 已停止重试 | 当前通知发送任务停止自动重试，需要核对原因 |
| 已终止 | 原付款确认已撤销，旧成功通知不再发送或重发 |

通知类型与商品名称分别展示，通知列表的金额保留“应付 / 实收”标签。通知地址是该订单保存的接收地址。收到成功回执后保留记录；以后撤销付款确认时，再说明当前收款状态，避免把旧通知结果当成最新付款结果。

## 网站与系统

| 术语 | 定义 |
| --- | --- |
| 系统 / 本系统 | 界面中指这一套 PerPay |
| 实例 | 运维和部署文档中指一套独立部署 |
| 业务网站 | 接入 PerPay 的一个自有网站 |
| 网站编号 | 固定不变，用于管理路径，以及查找所属订单和通知 |
| 客户端 ID | 业务 API 使用的可更换接入标识 |
| PID | 易支付协议中的固定数字商户编号 |
| 全局 / 本站 | 全部网站的内容 / 当前业务网站的内容 |
| 系统设置 | 整套 PerPay 的设置 |
| 网站设置 | 单个业务网站的设置 |

“已暂停接收新订单”表示当前网站停止创建新订单，已有订单和查账任务继续处理。“任务最近成功”根据该任务的记录显示：正常查账成功时，显示这一轮开始查询的时间；其他任务显示完成时间。

## 密钥与安全

| 术语 | 用途 |
| --- | --- |
| 支付宝应用密钥对 | 应用公钥和应用私钥 |
| 应用公钥 | 上传到支付宝应用 |
| 应用私钥 | PerPay 保存，用于签名支付宝请求 |
| 支付宝公钥 | 从支付宝取得，用于验证支付宝响应 |
| V1 商户密钥 | 易支付 V1 请求和回调的共享密钥 |
| V2 商户私钥 / 公钥 | 商户私钥签名请求，PerPay 使用公钥验证 |
| V2 平台私钥 / 公钥 | PerPay 使用私钥签名响应和回调，商户使用公钥验证 |
| 退款标记 | 管理员声明已在 PerPay 之外完成退款 |
| 标记已退款 / 撤销标记 | 管理员退款声明的操作名称 |

支付宝公钥与易支付平台公钥属于不同协议。退款标记记录管理员声明，PerPay 不执行或验证外部退款。

## 时间与金额

| 术语 | 定义 |
| --- | --- |
| 收银台有效期 | 订单允许付款的时间段 |
| 结束后可查询时长 | 收银台关闭或过期后，公开链接继续查询的时间 |
| 查账延迟 | 查账时暂缓读取最近几秒的流水，等待支付宝记录稳定 |
| 查账有效时限 | 一次正常查账的结果最多可以使用多久，从该轮开始查询时计时；超过后暂停该账号接单和未付款收银台 |
| 界面金额单位 | 元 |
| 原生 API 金额单位 | 整数分，字段以 `_cents` 表示 |
| 易支付金额单位 | `money` 使用元的两位小数字符串 |

网站可以继续使用其他配置完整、查账正常的账号，按该网站的账号分配规则选择。

## 状态词

| 场景 | 推荐名称 |
| --- | --- |
| 订单未付款 | 待付款 |
| 订单已收款 | 收款已确认 |
| 订单有争议 | 后台“收款有争议”，收银台“付款待核实” |
| 需要处理的提醒 | 待处理 |
| 处理完成 | 已处理 |
| 提醒关闭 | 已忽略 |
| 数据隔离 | 已隔离 |
| 关联撤销 | 已撤销 |
| 收到通知回执 | 通知已确认 |
| 停止自动发送通知 | 已停止重试 |
| 撤销确认后的旧成功通知 | 已终止 |

状态名称要说明正在处理什么，例如提醒可以“已忽略”，流水可以“已隔离”。展示时根据对应对象和字段选择名称。

## 写文案时的三个检查

1. 名称对应哪个字段、来源和概念，是否与本表一致。
2. 结论依据的是哪条记录、哪个时间范围，强度是否与实际状态一致。
3. 用户接下来能执行什么操作，是否直接说明必要步骤。
