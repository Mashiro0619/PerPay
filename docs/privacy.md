# 数据收集与保留说明

你部署的 PerPay 由你保存和管理数据。下面列出程序会记录什么、保存多久，以及谁可以读取。付款人想了解某个收款网站如何使用数据，应联系该收款方；部署者还需要分别检查反向代理、监控、备份和业务网站保存的内容。

[文档导航](README.md) · [维护与恢复](maintenance.md)

## 收集哪些数据

| 来源 | 保存内容与用途 |
| --- | --- |
| 业务网站下单 | 网站编号、商户订单号、金额、商品名称、备注、通知和返回地址、状态及时间，用于展示订单、查询付款和通知业务网站。 |
| 支付宝账务明细 | 流水号、交易时间、金额、收入或支出、支付宝及商户订单号、备注、交易对方的账户信息，用于核对付款和处理异常。 |
| 查账原始记录 | 查询的时间范围、分页信息、支付宝返回的状态、响应头、完整正文、签名检查结果和接收时间，用于重新核对账单来源及内容。 |
| 管理操作和登录 | 登录 IP、浏览器或客户端标识（User-Agent）、登录与使用时间、会话撤销时间，以及谁在何时改了哪些配置。旧记录可能只保存 IP 的哈希值，即经过单向计算的摘要。 |
| 接口和后台任务 | 执行时间、操作、结果、管理员或业务网站、来源 IP、User-Agent、请求方法、接口路径模板、状态码、耗时和错误码，用于排查失败原因。 |
| 备份与维护 | 备份结果，以及恢复、删除和清理锁的操作、时间、执行阶段和结果。备份或维护进程先写到记录文件，再由主程序读入。 |
| 通知发送 | 通知中的订单事件、每次发送尝试、接收方回复和错误，用于重试及排查。 |

**查账会取得这个收款账号在所查时间段内的其他收支，不只包含 PerPay 订单的付款。** 交易对方账户 `other_account`、备注 `trans_memo` 等字段按支付宝返回的内容保存，可能已被遮盖，也可能含有能识别个人的信息。完整响应中还可能有页面上没有单独展示的字段。

页面隐藏或缩短字段，不会删除数据库中的原文。填写商品名、备注或网址参数时，避免加入与收款无关的个人信息。

## 保存多久

| 数据 | 保留与清理规则 |
| --- | --- |
| 订单、账务流水、首次入账和异常核对证据、重要操作记录（核心审计） | 长期保存。关闭订单、忽略提醒或标记处理完成，不会删除这些记录。 |
| 重复或为空的查账记录 | 成功单页查询中的空结果、重复流水副本保留 7 天，每小时分批清理。首次入账证据、其他记录仍在使用的内容，以及各账号最近的正常查账和历史补扫记录继续保留。 |
| 清理后的历史查询摘要 | 长期保存请求摘要、最后一次响应摘要和记录时间，用于发现再次查询同一时间段时支付宝返回的内容是否变化。 |
| 接口和任务活动记录 | 保留 30 天，分批清理。相关订单、账单和重要操作记录仍按各自规则保存。 |
| 备份与维护进程写出的记录文件 | 保留 30 天。恢复、删除等重要操作读入后形成的核心审计，以及已读入的确认记录长期保存。 |
| 管理员会话 | 会话到期或被撤销后再保留 30 天；两种时间都有时，以较晚者为准。成功登录、记录登录失败等操作会触发清理，IP 和 User-Agent 随会话记录一起删除。 |
| 自动备份 | 默认每 24 小时一份、保留 7 份，可在后台调整。恢复所需或暂时无法校验的文件可能被保留，使实际份数超过设置值。 |

查账清理会删除符合条件的批次、分页和重复响应记录，每笔已经入账的流水仍保留来源证据。普通成功查询按分钟汇总，没有变化的正常查账、对账和空通知轮次按小时汇总；重要操作、失败和状态变化逐条保存。汇总中记录开始与结束时间、次数和总耗时。

核心审计会一起保存操作当时的 IP、User-Agent 和字段变化。密钥等机密字段只记录“发生了变化”，不记录原值；过长的普通字段会明确标为预览，并附上原始大小和摘要。旧记录缺少的信息保持为空。

更换客户端 ID 或删除网站后，旧 ID 仍被保留，不能再分给其他网站；更换记录和审计也会保留。删除未使用的支付宝账号会清除当前密钥和配置，但保留账号名称、编号、删除状态、以前使用的应用、收款码版本和操作记录。

备份与维护记录文件位于 `PERPAY_BACKUP_DIR/perpay-activity/v1`。程序还会保留少量序号和清理进度，用来发现有没有记录在读入之前就超过了 30 天。出现这种情况时会显示 `source_retention_gap`，表示这段记录已经缺失，不能自动补回。

备份保存的是制作当时的数据。程序清理在线数据库时，不会同步删除旧备份、恢复时保留的原文件、手动导出文件和异地副本。这些副本需要另外安排保留时间和删除方式。

## 谁可以接触这些数据

| 接收方或访问者 | 可接触的数据 |
| --- | --- |
| 实例管理员，以及有服务器、数据卷或备份权限的人员 | 对应实例保存的记录和文件。 |
| 业务网站 | 通过本站 API 和通知接收订单及付款状态；网站收到后如何保存和使用，由该网站管理。 |
| 支付宝 | 查账请求，以及请求所需的应用信息。 |
| 配置的通知接收地址 | 对应订单事件和通知参数。 |
| GitHub 官方发布服务 | 检查更新的网络请求和连接 IP 等信息，不包含订单内容或支付密钥。 |

管理员可以查询这套 PerPay 的全部审计记录，访问时会检查登录状态和管理员 IP 白名单。选择一个网站只是缩小查询范围，不会把管理员权限限制在这个网站。

自动检查更新的开关、是否查看预发布版、已忽略的提醒，都保存在当前浏览器。同一地址的多个标签页会同步这些设置，换浏览器后需要重新设置。它们不包含密钥或业务数据；关闭自动检查后仍可手动检查。

## 存储和导出

**PerPay 主密钥用于加密配置里的密钥和凭据，不会加密整个 SQLite 数据库。** 订单、账单原文、会话记录和数据库备份，需要靠服务器的文件及数据卷权限保护。保存到其他机器时，分别加密数据库备份和原主密钥，步骤见[主密钥与备份的异地保存](maintenance.md#主密钥与备份的异地保存)。

接口活动记录保存路径模板，例如 `/api/v1/orders/:orderId`，不保存完整请求和响应，也不记录 Cookie、Authorization 或收银台令牌。IP 是否准确取决于反向代理配置；User-Agent 是客户端自行提供的名称，不能单凭它判断是谁在使用。账单原始响应仍按前面的规则保存。

审计 CSV 一次最多导出 366 天内的 10,000 条记录，包含所选记录中可见的 IP、客户端信息和字段变化。导出操作也会留下记录。下载或分享后的文件由持有人保管，不会随服务器上的 30 天清理一起删除。

活动记录会分批写入，因此页面可能稍晚才显示。写入失败或缺少记录时，采集状态会提示原因；进程突然退出，也可能丢失尚未写入的活动。订单等关键变更与对应的核心审计会一起保存，排查时可以结合这两类记录和运行日志。

公开提交问题、截图或样本前，先遮盖账单原文中的个人信息、交易对方账户、备注、网址参数、登录来源和密钥。排查签名问题确实需要保留原文时，放在只有相关人员能访问的位置。安全问题通过[私密漏洞报告](../SECURITY.md)提交。
