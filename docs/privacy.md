# 数据与隐私说明

PerPay 为完全自部署服务，所有业务与账务数据均存储于使用者自有服务器，不向项目作者上报任何数据。本文说明存储范围、留存周期、访问边界及加密导出规则。

> 相关文档：[文档目录](README.md) · [维护与恢复](maintenance.md) · [安全报告](../SECURITY.md)

---

## 1. 数据存储范围

| 数据类别 | 存储内容 | 用途 |
| --- | --- | --- |
| 业务订单 | 商户订单号、商品名称、备注、金额、通知/返回地址、状态与时间 | 收银台展示、对账确认与回调通知 |
| 支付宝账务流水 | 流水号、交易时间、金额、收支方向、交易对方信息与交易备注 | 自动匹配收款与人工异常核对 |
| 查账原始响应 | 查询时间区间、分页参数、支付宝返回原文与验签状态 | 账单来源审计与完整性核验 |
| 通知投递记录 | 推送的事件载荷、历次尝试的 HTTP 状态、回执内容与报错 | 自动退避重试与对接排障 |
| 管理登录与审计 | 登录 IP、浏览器 User-Agent、配置修改记录与后台任务执行结果 | 操作追溯与运行状态排查 |

> **注意**：
> 1. 支付宝账务明细查询接口会拉取该账号对应时段内的**全部收支流水**（包含非 PerPay 产生的常规收支），交易对方及备注按接口返回值原样落库。建议使用专用收款账号。
> 2. 请勿在商品名称、备注或 URL 参数中填入非必要的个人敏感信息；界面上的折叠或缩略展示不会删除数据库中的原始文本。

## 2. 留存与清理策略

| 数据类别 | 留存与清理规则 |
| --- | --- |
| 订单、流水、首次入账证据、核心审计 | 长期保留。已完结的历史记录可通过 [历史归档](maintenance.md#历史归档) 移出在线库；归档文件永久保留，需管理员手动删除。 |
| 空查账页与重复账单副本 | 保留 7 天，每小时自动清理（每笔流水的首次入账证据与摘要永久保留）。 |
| 普通接口与任务活动记录 | 保留 30 天；未关联核心审计的查询与匿名请求最多保留最近 20,000 条，高频重复记录按分钟/小时合并，超限时丢弃并记录提示。 |
| 管理员登录会话 | 过期或撤销后再保留 30 天，到期清理时同步删除对应 IP 与 User-Agent。 |
| 备份与维护日志 | 维护进程日志保留 30 天；自动数据库备份默认保留最近 7 份（可在后台调整），「恢复前备份」长期保留需手动删除。 |

> **说明**：在线数据库的自动清理或归档不会同步修改已生成的历史备份、异地副本或已导出的 CSV 文件，外部副本的留存周期须由运维者自行管理。

---

## 3. 访问边界与外部通信

- **管理员与服务器运维人员**：拥有实例全部数据的访问权限（后台各网站由同一管理员会话访问，切换网站仅作数据筛选，不构成多管理员权限隔离）。
- **业务网站**：仅可访问并接收属于本站点的订单与通知数据。
- **支付宝开放平台**：接收查账接口请求与对应应用标识。
- **GitHub Releases API**（仅执行官方更新检查时）：仅产生公开版本的 HTTP 查询请求与来源 IP，不发送任何订单、流水、配置或密钥；更新通道、开关与已忽略版本偏好仅保存在管理员浏览器本地。

---

## 4. 加密范围与导出注意事项

- **主密钥加密范围**：PerPay 主密钥用于加密存储于数据库中的各类密钥与凭据，**不会加密整个 SQLite 文件**。数据库文件、原始账单文本与本地备份依赖宿主机文件系统权限保护；异地保存请按 [主密钥与备份的异地保存](maintenance.md#主密钥与备份的异地保存) 进行离线加密。
- **CSV 导出**：订单 CSV 不包含密钥、订单备注和收银台令牌；审计 CSV 包含页面可见的 IP、User-Agent 与字段变更（单次导出上限 366 天 / 10,000 条）。
- **外部反馈与漏洞上报**：提交 Issue 或日志前须先对订单/账单中的个人账号、交易备注、公网 IP 及密钥脱敏；安全漏洞请按 [SECURITY.md](../SECURITY.md) 私密上报。
