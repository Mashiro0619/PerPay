# 数据收集与保留说明

本文说明当前 PerPay 源码的数据处理行为。每个自托管实例由部署者管理；实际访问人员、代理日志、外部备份和业务网站的数据使用方式取决于部署配置。付款人如需了解某一实例的数据处理，应联系该收款方。

## 收集哪些数据

| 来源 | 保存内容与用途 |
| --- | --- |
| 业务网站下单 | 网站标识、业务单号、金额、商品或订单描述、备注、通知及返回地址、状态和时间，用于下单、查单、收银台及履约通知 |
| 支付宝账务明细 | 支付宝流水号、交易时间、金额、收支方向、支付宝及商户订单号、交易备注、对手账户字段，用于对账、异常核实和追溯 |
| 查账原始证据 | 查询窗口、页与分段信息、响应状态、响应头、完整响应正文、验签结果、接收时间及相关观测记录，用于复核来源和完整性 |
| 管理操作和登录 | 管理员会话来源 IP、User-Agent、创建/使用/撤销等时间，以及操作审计、来源哈希和登录失败限制记录，用于会话管理与操作追溯 |
| 通知投递 | 订单事件载荷、投递尝试、响应及错误记录，用于签名通知、失败重试与人工排查 |

**账务查询按收款账户及时间窗口进行，不只获取已匹配 PerPay 订单的流水。** 同一账户在窗口内的其他收支也可能被采集并保存。业务备注、URL 参数和上游正文中可能包含额外个人信息，应避免主动在这些字段填入无关信息。

支付宝返回的 `other_account`、`trans_memo` 等字段按返回值保存；字段规整和长度限制不等于匿名化。上游可能返回掩码，也可能返回可识别的内容，PerPay 不保证统一二次脱敏。原始响应还可能包含解析后未单独列出的字段，不能把后台某一处的隐藏显示视为底层数据已删除或脱敏。

## 保存多久

当前版本**没有对在线订单、账务流水、查账原始证据和核心审计记录按天自动清除的机制**，这些记录持续保存在数据库中。订单过期、关闭、忽略提醒或标记处理完成不会删除相应原始记录；部分表通过禁止删除的约束维护追溯关系。不要直接删表或修改底层记录来模拟保留策略。

管理员会话记录有单独清理规则：绝对过期时间与撤销时间中的较晚者已过去 30 天后，记录才符合清理条件。清理由成功登录或记录登录失败等操作触发，不保证到期时立即执行；会话中保存的 IP 和 User-Agent 随该会话记录一同清理，其他审计或外部日志有各自的存储范围。

自动备份默认每 24 小时运行一次、保留 7 **份**，可在后台调整。保留份数不等于固定保留 7 天；执行中断、恢复点保护和无法安全校验的文件也可能影响清理。备份包含数据库当时的记录，删除或清理在线数据不代表旧备份同步清除。恢复隔离目录、手动导出和异地副本应由部署者另行管理保留时间。

## 谁可以接触这些数据

实例管理员及拥有服务器、数据库卷或备份访问权的人员可以接触对应记录。业务网站通过本站 API 和通知接收订单及支付状态等数据；网站收到通知后的保存和使用由该网站管理。查账请求会发送给配置的支付宝服务，通知会发送给配置的接收地址。

官方更新检查请求 GitHub 的公开发布信息，不附带业务订单正文或支付凭据；请求仍会向服务提供方暴露通常的网络来源信息。服务器反向代理、容器日志、监控、导出工具及业务网站可能另外记录数据，本文不代替对这些组件的核查。

## 存储和导出

PerPay 主密钥用于加密配置中的秘密，**不是整个 SQLite 数据库的加密密钥**。订单、账务证据、会话元数据和数据库备份不能因此视为已整库加密。应限制数据库卷和备份的访问权限，异地保存前对备份及原主密钥分别加密；步骤见[主密钥与备份的异地保存](maintenance.md#主密钥与备份的异地保存)。

公开提交问题、截图或样本前应另行脱敏，尤其检查原始响应、对手账户、备注、URL 参数、会话来源和凭据。原始验签证据需要保持原文时，应在受控位置保存，避免放入公开仓库。
